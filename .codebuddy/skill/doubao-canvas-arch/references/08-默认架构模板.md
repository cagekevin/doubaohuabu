# 08 · 默认架构模板（可直接采用 · 把细节定死）

> **为什么要这份文件**：原则（"分层""SSOT""错误透传"）如果只停留在抽象表述，AI 写代码时仍会**自由发挥**。所以这里把每条原则落成**可直接照建的目录、可直接用的接口代码、可直接配的规则、可直接抄的骨架**。
> **使用方式**：新项目**默认照此建**；只有约束明显不同时才偏离，**并在文档里写明为什么**。目标是**不给 AI 留"随便写"的空间**。
> 占位符：`<站点>` = 具体外部站点名。
>
> ⚠️ **本文件是"通用默认"，不是"豆包画布的实际落地"** —— 该项目的实际目录 / 规则 / 端口 / 命名以 **`docs/11-架构与契约定稿.md`** 为准。本文件示例里的默认名（如 `constants/styles.ts`、数据形状放 `core/model/`）在该项目已分别落地为 `constants/stylePresets.ts`、`stable/model/`；dependency-cruiser 实际规则条数也多于下文示例（含 `core-no-react`）。**照建到豆包画布前先对齐 `docs/11`。**

## 二、层级定义与依赖白名单（手工列，工具不自动推导）

| 层 | 允许依赖 |
|---|---|
| `lib` / `constants` | 无（谁都能用，它不依赖谁） |
| `stable` | `lib` / `constants` |
| `core` | `stable` / `lib` / `constants`（**不依赖** adapters / state / ui） |
| `adapters` | `core/ports`（实现它）/ `stable` / `lib` / `constants` |
| `state` | `core/usecases` / `core/ports` / `stable` / `lib` / `constants` |
| `ui` | `state` / `core/model`（只读类型）/ `lib` / `constants` / `styles` |
| `bootstrap` | 全部（唯一允许） |

**三条铁律**：① 内核不得 import 适配器/状态/视图；② 视图不得直接调宿主 API；③ 冻结层不得 import 上层。

## 三、dependency-cruiser 规则（完整可用）

```js
// .dependency-cruiser.cjs
module.exports = {
  forbidden: [
    // 1. 层级方向：内核 / 冻结层不得依赖上层
    {
      name: 'no-upward-dependency',
      severity: 'error',
      comment: '依赖只能自下而上；内核与冻结层不得依赖上层',
      from: { path: '^src/(core|stable)/' },
      to: { path: '^src/(adapters|state|ui|bootstrap)/' },
    },
    // 2. 视图禁 import 适配器（必须经 state → usecases → ports）
    {
      name: 'ui-no-adapters',
      severity: 'error',
      comment: 'ui 不得直接 import adapters/**',
      from: { path: '^src/ui/' },
      to: { path: '^src/adapters/' },
    },
    // 3. 冻结层禁 import 上层
    {
      name: 'stable-no-upper',
      severity: 'error',
      comment: 'stable/** 不得 import 上层',
      from: { path: '^src/stable/' },
      to: { path: '^src/(core|adapters|state|ui|bootstrap)/' },
    },
    // 4. volatile 隔离：站点适配器只允许 adapters 内部 import（入口点边界）
    {
      name: 'site-adapters-private',
      severity: 'error',
      comment: 'adapters/site/* 只允许 adapters 内部 import，外部拿不到站点选择器',
      from: { pathNot: '^src/adapters/' },
      to: { path: '^src/adapters/site/' },
    },
    // 5. 无环
    {
      name: 'no-circular',
      severity: 'error',
      comment: '禁止依赖环',
      from: {},
      to: { circular: true },
    },
  ],
  options: {
    doNotFollow: { path: 'node_modules' },
    tsConfig: { fileName: 'tsconfig.json' },
  },
};
```

**落地步骤**：① 装 `dependency-cruiser`（devDependency）→ ② 写上面 5 条 + 手工列分层白名单 → ③ 加脚本 `lint:boundaries` 并**折进已有 typecheck 命令** → ④ **禁 barrel**（每层暴露若干小入口点，不要巨型 `index.ts`）→ ⑤ **证明规则会咬**：故意从 `ui/` 深导入 `adapters/site/<站点>/selectors.ts` → `lint:boundaries` **必须失败** → 再还原。

## 四、端口接口（完整可用）

```ts
// core/ports/host.port.ts —— 按用途切分，不是照抄全部宿主方法
export interface HostPort {
  readonly os: 'windows' | 'macos' | 'linux';   // 用宿主 platform，不读 navigator
  file: FilePort;
  clipboard: ClipboardPort;
  project: ProjectPort;
  media: MediaPort;
  account: AccountPort;
  license: LicensePort;
  api: ApiPort;
}

// core/ports/site.port.ts —— 最易变
export interface SitePort {
  readonly kind: string;
  scan(account: Account, opts: ScanOptions): Promise<ScanResult>;    // 抓取（降级链内部实现）
  send(account: Account, payload: SendPayload): Promise<SendResult>; // 发送
  probe(account: Account): Promise<SiteProbe>;                        // 登录态/可用性探测
}

// core/ports/storage.port.ts
export interface StoragePort {
  read<T>(key: LsKey): T | null;      // LsKey = stable/contracts/keys.ts 的字面量联合
  write<T>(key: LsKey, value: T): void;
  remove(key: LsKey): void;
}

// core/ports/clock.port.ts —— 为了可测
export interface ClockPort {
  now(): number;
  setTimeout(fn: () => void, ms: number): Cancel;
  setInterval(fn: () => void, ms: number): Cancel;
}
```

**端口契约必须写进类型注释**（否则实现时被忽略）：
- `SitePort.scan`：**必须显式调用**，不得自启定时器（不开自动轮询抓取）。
- `AccountPort`：cookie 由宿主管理，**前端不碰**（不传 CF cookie）。
- `HostPort` 的批量/事件方法：**返回 Result 而非抛错**（一抛错整批失败）。
- `ClipboardPort`：实现内部保证 `clear()` → `writeText()` 且 `await`，对外**只暴露一个 `writeText()`**。
- `adapters/site/*`：**禁止注入**（不得用 JS 改 `navigator`/`screen`/`webgl`）。

## 五、契约类型（完整可用）

```ts
// core/model/result.ts
export type FailureKind =
  | 'quota' | 'auth' | 'rate-limit' | 'network' | 'timeout'
  | 'page-error' | 'bad-request' | 'cancelled' | 'unknown';  // 按项目补充
```

## 六、SSOT 文件清单（唯一真源，别处不得重复定义）

| 内容 | 唯一真源 | 谁不能重复定义 |
|---|---|---|
| UI 文案 / 失败 label / 错误横幅映射 | `constants/text.ts` | state / core / ui 都不得硬编码 |

| 设计 token（颜色 / 间距 / 圆角） | `styles/tokens.css` | 组件不得写硬编码色值 |
| 存储键 | `stable/contracts/keys.ts` | 各处不得写字符串字面量 |
| 模型表 / 风格预设 | `constants/models.ts` / `constants/styles.ts` | — |

## 十、代码骨架（照着填）

**用例（编排 + 错误透传）**
```ts
// core/usecases/generateImage.ts
import type { SitePort } from '../ports/site.port';
import type { ClockPort } from '../ports/clock.port';
import type { Result } from '../model/result';

export interface GenerateImageDeps { site: SitePort; clock: ClockPort; }

export async function generateImage(
  deps: GenerateImageDeps,
  input: GenerateImageInput,
): Promise<Result<GenerateImageOutput>> {
  try {
    const payload = buildPayload(input);          // 纯逻辑放 core/rules
    const sent = await deps.site.send(input.account, payload);
    if (!sent.ok) return sent;                    // 转发，不改写 message
    return await pollResult(deps, sent.value);    // 用 deps.clock，不直接用 setTimeout
  } catch (e) {
    return { ok: false, reason: classifyFailure(e), message: e instanceof Error ? e.message : String(e) };
  }
}
```
