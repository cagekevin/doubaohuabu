# 10 · 自进化（流程细则 + 日志）

> **用途**：让技能**能长** —— 把实现、评审、改版、外部对照中产生的新知识**记回来**，避免技能与现实脱节。
> **本文件只追加、不删改**（保留演进轨迹）。规则类变更同步更新 `SKILL.md`。

---

## 一、流程细则

**触发点（任一发生即进化）**：

| 触发 | 动作 |
|---|---|
| 做了新架构决策 / 偏离默认模板 | 记录决策 + 依据（哪条约束 / 判据） |
| 评审发现越权 / 新反例 | 补进对应判据的"反例 / 检查" |
| 外部对照发现缺口并采纳 | 新增判据 / 推理链（走 `09-求最优与补缺.md`） |
| 站点改版 / 后端变更 | 更新对应 reference（volatile 层） |
| 某条判据被证伪 | 修正或废弃，写明原因 |

**四步**：
1. **记** —— 在下方日志追加一条。
2. **改** —— 更新 `SKILL.md`（判据库 / 推理链）或对应 reference；**保持单一真源**（别在两处写）。
3. **验** —— 规则类变更 → 更新检查清单 / 验收用例。
4. **审** —— 确认不破坏既有判据（尤其 SSOT 与依赖方向）。

**约束（自进化不能破坏架构）**：
- 新知识必须**可追溯到约束或证据**，不得凭感觉加规则。
- 改判据必须**同步反例与检查**，否则判据不可执行。
- 默认模板的偏离必须**写明原因**。
- 日志只追加、不删改。

**日志条目格式**：

```
### E-XXXX · <一句话标题>
- 日期：
- 类型：决策 / 判据 / 反例 / 对照 / 改版 / 证伪
- 变更：改了什么（文件 + 位置）
- 依据：哪条约束 / 判据 / 证据（可引用 00~10 文档）
- 影响：影响哪些判据 / 用例 / 模板
```
