# UI 细节 8 查（界面验收 SOP · 一票否决）

> **定位**：任何"看得见的东西"（页面 / 面板 / 弹窗 / mockup / 组件改样式）在说"做完了"之前，**必须过这 8 查**。
>
> **一票否决**：**任何一查没过 ⇒ 整份不许打勾**。不许"部分通过"、不许"这条以后再改"、不许用"看起来没问题"当凭证。
>
> **效力边界**：用户裁定 > 本文件 > 个人审美。用户明确否过的东西直接进红线，不必再讨论。
>
> ---
>
> ### ★ 本 SOP 的核心：**判据是人做的，不靠脚本**
>
> **不写"机器守卫"、不建 lint 脚本、不挂门禁。** 理由（血的教训）：
>
> 1. **脚本会骗人** —— 实录三个：对比度脚本把品牌槽解析成了**最后一个品牌**（绿），差点误判；
>    死类扫描**误报 13 个**（模板字符串拼接没处理）；三态扫描的"命中"必须人解读才知道是不是真违规。
> 2. **脚本给虚假的确定感** —— "跑绿了"会让人跳过**看**这一步，而 UI 的问题恰恰只能看出来。
> 3. **脚本锁死了判据** —— 判据在演进，脚本跟不上；而且**例外表**会变成藏污纳垢的地方。
>
> **所以**：下面的每条判据都写清「**怎么验**」（Grep 什么 / 看哪里 / 量什么），
> 由**人**跑、**人**判、**人**写结论。Grep 只是"帮你看全"，不是"替你决定"。
>
> ---
>
> ### 取证纪律（本仓血泪）
>
> | # | 纪律 | 为什么 |
> |---|---|---|
> | ① | 一律用 **Grep 工具（ripgrep）**，不许用 shell `grep` | 本仓 shell 下 `--include=*.ts` 被 zsh 当 glob 报错、`\|` 交替**静默返回空** —— **空结果 = 最危险的假证据** |
> | ② | 每查都要**能复算**：把命令 + 输出贴进记录 | 别写"已检查" |
> | ③ | 目标是**会动的文件**（并行会话常见）⇒ 下结论前核 mtime | 结论一律标"**截至 HH:MM**" |
> | ④ | **改完再扫一遍，直到扫描结果为空** | 实录：`LibraryPanel .actions button` 是**第三次扫描**才抓到的 —— "我改完了"不可信 |
> | ⑤ | **"扫过 = 0"不等于"这族没问题"** | 实录：扫 `z-index: <数字>` → 0 处就收工，**漏了查"规范里有没有写这一层"**（见查 5.1）|
> | ⑥ | **份数 >1 ≠ 违规；同名 ≠ 同物** | 必须**读内容**，不能只看数字（见查 7.1）|

---

## 用法（三步）

1. **逐查逐子项跑一遍**，每条填 `✅ / ❌ + 证据`（命令输出或"看了哪一行"）。
2. **❌ 就改**，改完**重跑那一查**（不是只改那一处就算过）。
3. 8 查全绿 ⇒ 才允许在「验收栏」打勾。

# 查 1 · 颜色：**一处定义，按意图引用**

## 1.1 没有裸色值

**判据**：字面量色值**只允许出现在 `src/styles/tokens.css`**。组件 CSS 里出现 `#6366f1` / `rgb(99 102 241)` 即违规。

**怎么验**：

```
Grep  "#[0-9a-fA-F]{3,8}\b|\brgba?\("   → 只允许命中 tokens.css
```

**允许的例外**（必须**逐个登记理由**，不是"忘了"）：
mockup 的占位素材渐变 `ph-a`~`ph-f` —— 那是"假图"不是设计色，已在源码里写明理由。

## 1.2 不越层引用

**判据**：三层契约 —— L1 原始值（`--p-*` / `--brand-*`）**只有 L2 能引**；L3 组件旋钮**只有组件能引**。

**怎么验**：

```
Grep  "var\(--p-|var\(--brand-"   → 组件 CSS 里应为 0
```

**违规形态**：组件直接写 `var(--p-indigo-500)`（跳过了语义层）—— 换品牌时就它不变。

## 1.3 ★ 对比度（WCAG AA）

**判据**：文字 / 底色 ≥ **4.5:1**（正文）、≥ **3:1**（大字：≥18.66px bold 或 ≥24px）。

**怎么验**：逐对核心组合算 —— 正文/页底、弱文字/卡片、按钮文字/主色底、反馈文字/卡片。
**四个品牌 × 明暗两主题都要算**（品牌色可切，每个都该够）。

**违规形态（都是实录）**：

| 形态 | 表现 | 修法 |
|---|---|---|
| **暗色主题的按钮白字** | 品牌色在暗色下**提亮**到 400 档，白字压上去只有 **2.98:1**（四个品牌全不达标）| 暗色按钮应是「**浅底 + 深字**」|
| **弱文字太浅** | `--color-text-faint` 只有 2.54:1（连大字标准都不到）| 整体下移一档 |
| **反馈色当文字** | 警告色只有 **2.15:1** | 加"**文字版**"语义（`--color-*-text`），比底色版**深一档**；**别改底色**（那会改观感）|
| **半透明底在深色下消失** | `rgb(ch / 0.08)` 压在深底上几乎看不见 | 暗色段把 α 提到 ~1.8× |

> ⚠️ **算对比度时注意**：品牌槽（`--brand-*`）在文件里**定义了 4 次**（indigo/blue/violet/green）。
> 手工/脚本核对时**必须取首个**（= `:root` 的默认品牌），否则会拿最后一个（绿）当基准 —— 实录踩过，差点误判。

## 1.4 ★ 暗色主题覆盖完整

**判据**：L2 的**每个色值语义**都必须在 dark 段有个决策 —— 要么**覆盖**，要么**有理由地不覆盖**。
**漏了不报错，只会在暗色下悄悄串色。**

**怎么验**：比对 light / dark 两段的变量清单，逐条看差值。

**实录**：漏了 `--color-action-primary-hover` ⇒ 暗色下按钮 hover 从 `brand-400` 跳到 `brand-600`（**变暗**），与"暗色提亮"的直觉相反。

**有意不覆盖的**（要能说出理由）：
`--shadow-*`（引用 `--color-shadow`，后者已被 dark 覆盖 ⇒ 自动适配）、`--color-node-*`（**标识色**，跨主题一致才对）。

## 1.5 底色与文字色不混用

**判据**：同一个语义变量**不在两个对立角色上复用**。
`--color-danger` 当**底色**用（红底）、又当**文字色**用（红字）⇒ 必然有一边不对。

**怎么验**：`Grep "color: var(--color-(danger|success|warning))\b"` —— 当**文字**用的地方，应走 `--color-*-text`。

# 查 2 · 尺寸与间距：**来源唯一，档位在册**

## 2.1 间距来源唯一

**判据**：同一段间距**只许有一个来源**。外层给了 padding，子项就不许再写同方向的值；**不许用负 margin 打补丁**。

**三种"重复来源"**：

| 形态 | 长什么样 | 怎么抓 |
|---|---|---|
| ① **散落** | 同一个 32px 写在 `.header` / `.banner` / `.drop` / `.container` 四处 | 数出现次数 |
| ② **叠加** | `.grid{margin-bottom:24px}` + 下一块 `.header{padding-top:16px}` ⇒ 实际 40px，两个来源 | 看相邻容器 |
| ③ **与父容器 `gap` 重复** | 父 `.panel{gap:var(--space-2)}` + 子项 `margin-top:var(--space-1)` | **查父选择器有没有 `gap`** |

**怎么验**：

```
Grep  "margin:\s*-|margin-(top|left|right|bottom):\s*-"        → 0（负 margin 补丁）
```

**修法**：外层一处 padding；区块间距交给**一个**选择器（首项 `:first-child` 归零）；
父容器有 `gap` 时，**子项删掉同方向的 margin**。

## 2.2 间距 / 尺寸走 token

**判据**：间距（padding / margin / gap）一律 `var(--space-*)`，**不写裸 px**。

**怎么验**：

```
Grep  "^\s*(padding|margin|gap)[^;]*:[^;]*[0-9]+px"
```

**实录**：曾经 28 处全是 `2px` —— 根因是间距尺度**缺 2px 这一档**（最小只到 4px），
大家只能写裸值。⇒ **档位不够就加档（改 tokens.css），别就地写值。**

## 2.3 同排必须等高

**判据**：同一排的控件**高度必须相等**（差 1px 就能看出来）。

**怎么验**：量同一排各控件的高度来源（是 `--btn-height`？`--field-height`？还是 padding 撑出来的？）。

**实录反例**：顶栏三个控件 28 / 36 / 30 三种高度；弹窗按钮靠 inline `height:30px` 单独调。

## 2.4 圆角规格在册

**判据**：圆角走 `--radius-*`（`--shape-*` 经 `data-shape` 切换），不写裸值。

**怎么验**：

```
Grep  "border-radius:\s*(50%|[0-9]+px)"
```

**实录**：`border-radius: 50%`（圆点）和 `2px`（chip 内小图标）散落 ⇒ 补 `--radius-full` / `--shape-xs` 两档。

> ⚠️ **下沉判断**：不是"每处都该用同一档"，而是**每处都该走档位**。
> 圆点用 `--radius-full`、小图标用 `--radius-xs` 是对的 —— 错的是写 `50%` / `2px`。

# 查 3 · 排版：**字号有阶，行内有高**

## 3.1 字号在阶内

**判据**：`font-size` 只走 `--font-size-*`，且**只有登记在册的那几档**（当前：9 / 11 / 12 / 14 / 16 / 20 / 32）。

**怎么验**：

```
Grep  "font-size:\s*[0-9]+px"     → 0
```

**实录**：出现 `32px`（空态大图标）、`10px`、`8px` 都不在阶里 ⇒ 补了 `--type-2xl` / `--type-2xs` 两档。

## 3.2 字重与行高在册

**判据**：`font-weight` 走 `--font-weight-*`（400/500/600）；`line-height` 走 `--line-height-*`（1.3/1.4/1.5/1.6）。

**怎么验**：

```
Grep  "font-weight:\s*[0-9]|line-height:\s*1\.[0-9]"
```

**实录**：`font-weight: 600` 散落 6 处、`line-height: 1.3/1.4/1.5` 散落 4 处 ——
**这两族的 token 当时根本不存在**，所以只能写裸值。⇒ **先建族，再收口。**

## 3.3 图标 + 中文必须 `line-height: 1`

**判据**：图标与中文**同一排**的按钮，必须 `line-height: 1`
（中文在 flex 里默认 `normal`，会**多出 2~3px 行距**，字看着往下掉），图标加 `flex: none`。

**怎么验**：找"图标 + 汉字"同排的控件，看它的 `line-height` 和图标是否 `flex: none`。

## 3.4 长文本有截断

**判据**：可能超长的文本（素材名、账号名、路径、错误信息）必须有 `overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`（或 `min-width: 0` 配合 flex）。

**怎么验**：逐个"会显示用户数据"的标签看有没有这套；父容器是 flex 时**还要看有没有 `min-width: 0`**（否则 ellipsis 不生效）。

# 查 4 · 布局：**不写死，不撑爆**

## 4.1 同排不写死宽度

**判据**：**菜单 / 下拉 / 提示条**不许写死宽度（用 `width: max-content` + `min-width` + `max-width`）。

**怎么验**：

```
Grep  "width:\s*1[0-9][0-9]px"
```

**实录反例**：菜单写死 `width:150px` ⇒「删除分组（技能回到未分组）」**折成两行**。

> ⚠️ **网格列宽、缩略图尺寸**写死 px 是**正常**的；查的是"**内容长度不可预知**却写死宽度"。

## 4.2 不撑爆

**判据**：任何面板 / 浮层 / 行，在**最长的真实内容**下都不能溢出容器、不能被压变形。

**怎么验**：**逐个浮层看"最坏情况"**：
- 节点名的**最长**那条
- 错误信息的**最长**那条
- 素材名的**最长**那条

**常见根因**：`flex` 子项缺 `min-width: 0`；`node-head` 缺 `nowrap`；
把**互斥的状态元素同时渲染了**（原版是"发送中 / 倒计时 / 换号中"三选一，全画就会挤爆）。

## 4.3 窄屏不挤压

**判据**：窗口变窄时，**要么横滚，要么布局自然收窄** —— 不许压成一坨、不许浮层盖住内容。

**怎么验**：把窗口拉到很窄，看主区。

# 查 5 · 层级与动效：**档位有册，动画不抖**

## 5.1 z-index 走档位

**判据**：不写 `z-index: 999`，走 `--z-*`（canvas 1 / panel 100 / overlay 500 / modal 900 / toast 1000）。

**怎么验**：

```
Grep  "z-index:\s*[0-9]"
```

**规矩**：新浮层先问**"它属于哪一档语义"**，不是"我要比谁高"（后者是军备竞赛）。
**档不够就加档**（改 tokens.css + 写理由），别就地写 999。

> ★ **陷阱实录**：我扫过 `z-index: <数字>` → **0 处就收工**，以为这族没问题。
> **漏了查"规范里有没有写这一层"** —— 结果规范里根本没有层级阶梯表，
> 看规范的人不知道有 `--z-*`、也不知道该选哪档。
> **⇒ 对每个 token 族，除查"有没有违规"，还要查"它的档位表进规范了没"。**

## 5.2 阴影走阶梯

**判据**：走 `--shadow-sm/md/lg`，不写裸值。

**怎么验**：

```
Grep  "box-shadow:\s*[^v][^;]*[0-9]+px"
```

**实录**：改造前 4 种值散落 9 处（`0 4px 16px` ×5 / `0 8px 32px` ×2 / `0 8px 24px` / `0 2px 8px`）⇒ 归成三档。

> ⚠️ `box-shadow: 0 0 0 Npx var(--x)` 是**选中光环**（描边），不是投影，不受此约束。

## 5.3 过渡只用合成属性

**判据**：`transition` / `@keyframes` 只用 **`transform` / `opacity`** —— 用 `left` / `top` / `width` / `height` 会触发 **layout**，掉帧。

**怎么验**：

```
Grep  "transition:[^;]*\b(left|top|right|bottom|width|height|margin|padding)\b"
```

**例外**：进度条的 `width` 过渡 —— 它本来就是"宽度"的语义，改 `scaleX` 要动 TSX 与视觉。
**这类例外要写清理由。**

## 5.4 动效时长在册

**判据**：`transition` / `animation` 时长走 `--duration-*`（120ms / 200ms）。
**旋转类周期**（如 spinner 转一圈）是另一回事，用专门的旋钮（`--spinner-duration`）。

**怎么验**：

```
Grep  "(transition|animation)[^;]*[0-9]+(\.[0-9]+)?m?s"
```

# 查 6 · 交互态：**可点必须有反馈**

## 6.1 可点元素有 `:hover`

**判据**：凡 `cursor: pointer` 的元素都该有 `:hover` 反馈（**走真源的不算**，真源已提供）。

**怎么验**：列出所有带 `cursor: pointer` 的规则，逐条看有没有 `:hover`。

**实录反例**：`.rowMain`（**点整行会进详情**）无 hover；`.colorDot` / `.swatch`（颜色选择）无 hover。

## 6.2 按下反馈（`:active`）—— **按需**

**判据**：`:active` **不是"每个可点元素都要"**。有更贴切的状态表达时，硬加位移反而怪。

**实录**：**真源 `.btn` 曾缺 `:active`** ⇒ **全仓按钮按下去都没反应**（一条规则，影响面最大）。

**有意不加的**（要能说出理由）：

| 处 | 理由 |
|---|---|
| 开关的 label | 点击反馈就是 checkbox 自身状态变化 |
| 颜色选择器 | 选中态本身就是反馈 |
| 可点行 | 按下反馈可选（不是按钮）|

## 6.3 disabled 态真实可见

**判据**：按钮 / 输入框被 `disabled` 时，视觉上要**看得出不能点**（变淡 / 灰底 / `cursor: not-allowed`）。

**判据细节**：**主按钮** disabled 宜用"整体半透明"、**次要按钮**宜用"文字变淡" —— 两种策略并存是**有意**的，不算不统一。

**怎么验**：`Grep ":disabled"`，逐条看它作用于哪种按钮。

## 6.4 键盘可达（focus）

**判据**：所有可点元素**键盘 Tab 能到、能有可见 focus 环**。
focus 环颜色走 `--color-focus-ring`。

**怎么验**：Tab 走一遍主要流程；看 focus 环有没有被 `outline: none` 掉而没补替代。

# 查 7 · 组件与令牌：**一份真源，一名一物**

## 7.1 ★ 复用真源（不许自造）—— 这是本查最难的一步

**判据**：已有真源就照它，不另造近似的。
- **交互组件**真源 = `src/ui/common/`
- **CSS 形态**真源 = `src/ui/common/shared.module.css`

**★ 怎么找"有人自造了"**（自造不会自己招认）：

```bash
cd src/ui
for c in btn field panel card chip badge menu overlay empty row item thumb dot spinner; do
  n=$(grep -rhoE "^\.${c}[A-Za-z0-9_-]*[ ,{]" --include="*.css" . | wc -l | tr -d ' ')
  [ "$n" -gt 1 ] && printf "%-10s %s\n" "$c" "$n"
done
```

**命中 >1 的族逐个读**：

| 读出来是 | 处置 |
|---|---|
| 形态**相同**（逐字或近乎逐字）| **收口**：`composes` 到真源 |
| 形态**不同**（如按钮 vs 卡片）| 在真源表**注明"为什么它不复用"** —— 不收也要有理由 |

> ⚠️ **份数 >1 不等于违规**：`.emptyTitle` / `.emptyIcon` / `.emptyDesc` 是**不同用途**的类。
> 一个族里有 17 个定义很正常。**必须读内容判断，不能只看数字。**

**`composes` 的三个语法约束**（都踩过）：

| # | 约束 | 后果 | 解法 |
|---|---|---|---|
| 1 | 被引用的类必须在**引用点之前**定义 | `CssSyntaxError: referenced class name … not found` | **挪定义顺序**（首选），别放弃收口 |
| 2 | 只能用于**单个类选择器** | 不能用于 `.st_success .chip` / `.head button` | 本地写（色值仍走 token），或给 TSX 加类名 |
| 3 | 同文件 `composes` 也受 #1 约束 | `.close` 定义在 `.btn` 之前就无法引用 | 同上：挪顺序 |

> ★ **通用解法**：`composes` 报 "not found" 时，**优先挪定义顺序**。
> 实录：`.close` / `.saveErrorClose` / `.menu` 都是这么解决的 —— **别退化成元素选择器，别放弃收口。**

## 7.2 ★ 同名不同物 —— 最危险的一类

**实录**：`nodes/shared .spinner`（**文字型**："生成中…"）与 `AnalyzePrompt .spinner`（**旋转圆环**）——
**名字相同，实现完全无关**。

**判据**：两个类**同名**但**实现不同** ⇒ 必须**改名**。
名字要**说明它的形态**（`.spinnerText` / `.spinnerRing`），不是说明它的时机。

**怎么找**：扫各族份数时，命中 >1 就**必须读内容** —— 同名不同物**只有在读的时候**才会露出来。

**另一类同名冲突**：**布局容器**与**浮层卡片**都叫 `.panel`
（`LibraryPanel` / `AccountPanel` 的 `.panel` 是栏容器，`CreatePanel` / `GenPanel` 的 `.panel` 是浮层）
⇒ 前者改名 `.column`，让 `.panel` 只表示浮层。

## 7.3 每条线都要说得出职责

**判据**：每一条线（border / 分隔线）都必须能回答"**它分隔了哪两种东西**"。答不出 ⇒ **删**。

**怎么验**：

```bash
for f in $(find src/ui -name "*.css"); do
  awk '/^[^ \t].*\{$/{sel=$0; sub(/ \{$/,"",sel)}
       /border-(top|bottom|left|right):|^[ \t]*(height|width):[ \t]*1px/{
         gsub(/^[ \t]+/,""); printf "%s:%d | %s | %s\n", FILENAME, FNR, sel, $0}' "$f"
done
```

**该留的**：容器边框、拖拽区虚线、头部 `border-bottom`（标题区/内容区）、
底部 `border-top`（内容/动作条，**仅限确认框**）、栏边界。

**该删的**：卡片本身已有边框 + 红字图标已说明"这张有问题"，再画一条是**重复表达同一件事**。

> ⚠️ `border-*: Npx solid transparent`（三角箭头）**不是分隔线**。

## 7.4 令牌体系完整

**四个子项，逐个验**：

| 子项 | 判据 | 怎么验 |
|---|---|---|
| **无悬空** | 引用的变量都有定义 | 比对"引用的" vs "定义的" |
| **无自引用** | `--x: var(--x)` = **无效值**（不报错、像别名）| 看 tokens.css 里有没有同名自指 |
| **无 `!important`** | 出现即违规 | `Grep "!important"` |
| **死变量先分类** | 见下 | 比对"定义的" vs "引用的" |

**死变量分类**（**别一看"没人用"就删**）：

| 类 | 处理 |
|---|---|
| **枚举型**（色板 / 字号 / 间距 / 圆角 / 层级）| **保留** —— 完整刻度是资产 |
| **语义型**（`--color-danger-bg` 这类）| 有定义就该有用途；没有就该删 |
| `--xy-*`（ReactFlow 官方变量）| **误报** —— ReactFlow 内部消费，外部 grep 不到 |

**实录**：本项目 68 个"死变量"里，**没有一个该删**。

> ★ **自引用的阴**：`--ease-out: var(--ease-out);` —— 看着像别名，实际是**无效值**，
> 导致**所有 `transition` 的缓动失效**（落到浏览器默认 `ease`）。**不报错、不警告。**

## 7.5 选择器结构干净

**判据**

1. **不用元素选择器写组件样式**（`.head button` / `.row input`）—— 无法被 `composes` 复用，且作用域失控。
   例外：**形态确实不同**的（`<select>` 高度由内容决定）—— 要写明理由。
2. **选择器深度 ≤ 2 层后代**（`.textEditor :global(.ref-chip)` 这类是必要的；再深就是耦合）。
3. **不用三层以上复合类**（`.a.b.c`）。
4. **同一规则里同一属性不写两遍**（笔误检测）。

**怎么验**：`Grep` 出所有规则头，逐条看。

## 7.6 无死类

**判据**：CSS 里定义了但**既没被 TSX 引用、也没被 `composes`** 的类 ⇒ 删（或写明"未接线，保留待对齐"）。

**怎么验**：比对 CSS 类名 vs TSX 的 `styles.x` + `composes` 引用。

> ⚠️ **必须处理动态拼接**：`styles[`st_${status}`]` / `styles[`gen_${cls}`]` 静态扫不出来。
> 实录：我的扫描把 13 个动态拼接的类**误报成死类**。

**"未接线"的处理**：原版有、重写还没接的样式（如 `.groupLabel`）——
**保留 + 注释写明"未接线"**，别当死代码删。

# 查 8 · 语义与文案：**正常零状态，异常带出口**

## 8.1 正常态零状态

**判据**：**正常态不显示** 徽章 / 状态 / 版本 / 计数 / 时间。

**怎么验**：逐个"状态显示"看它在**一切正常时**会显示什么。

> ⚠️ **要区分"冗余状态"与"有用指示"**：
> 可用：`NodeStatusDot` 的"有/无账号"（用户需要知道）、张数计数。
> 冗余：绿点写"连接正常"、版本号、"已就绪"。

## 8.2 异常带出口

**判据**：**异常才多说一句**，且**必须带一个动作**（不许只描述不给出口）。

**怎么验**：找所有错误 / 失败 / 空态，看它有没有"重试 / 去某处 / 换一条路"。

**实录**：异常都有出口 ✅（`SendQueuePanel` 失败项有「重试」、`ErrorBoundary` 有「重试渲染」）。

## 8.3 读不到 ≠ 没有

**判据**：读盘 / 取数失败**不许渲染成空态** —— 必须**保留已读到的内容 + 重试**。
（承 `Agent.md` §4：失败必须诚实可见。）

**怎么验**：找"catch 之后渲染空列表"的分支。

## 8.4 文案不出现实现黑话

**判据**：用户可见文案里**不许出现**：磁盘 / 目录 / 索引 / 注入 / 预算 / 兜底 / **尚未落地** / **序列化**。

**怎么验**：

```
Grep  "尚未落地|未落地|磁盘|索引|注入|预算|兜底|序列化|M1[0-9]"
```
（**只查字符串**，注释里的术语不影响用户。）

**实录反例**：

| 原文案 | 问题 |
|---|---|
| `工程数据序列化失败，未保存` | 黑话「序列化」，且是**自造**非源版 |
| `「扫描 Tapnow 画布」尚未落地：它走站点页内脚本读取画布节点（同 M11 剩余三项，属同一层）` | **三处内部术语**泄漏给用户 |
| `（分组功能尚未落地）` | 开发术语「落地」 |

**修法**：改成用户语 + **补出口**（"尚未实现。可先在画布框选素材，再点「加入选中素材」"）。

> ⚠️ **区分"源版原文"与"自造"**：源版带黑话的文案**保留**（忠实还原）；
> **本仓自造**的带黑话的文案**必须改**。判据是**来源**，不是"有没有黑话"。

## 8.5 动作语义单一

**判据**：同一个动作不许有两个入口（组级「全开全关」与行开关同时存在 = 违规）。

**怎么验**：列出所有"能触发同一件事"的入口。

# 三条不许

1. **不许分批打勾**：这不是"完成度进度条"，是**闸门**。
2. **不许用截图代替取证**：截图表象，判据要**可复算**。
3. **不许把"某个位置不好"写成"这个机制不许用"**
   ⇒ 立判据前先自检：**用户否的是实例还是规则？** 否实例 ⇒ 判据写成"**约束条件**"，不写"禁止"。

**已确认的用户裁定**（可直接引用，不必再讨论）：

- **不钻层**（"返回上一级麻烦"）⇒ 分区用折叠，不用进出页面
- **读失败不许说成空态**
- **能力不许砍**
- **规范要能自生长**（发现更好做法 ⇒ 改规范 + 写理由，而不是绕过它自己造一份）
- **不要机器守卫**（见文首）—— 判据由人跑、人判

# 附录 · 陷阱清单（最容易骗人的八条）

| # | 陷阱 | 教训 |
|---|---|---|
| A | **"扫过 = 0" ≠ "这族没问题"** | 扫 `z-index: <数字>` → 0 就收工，漏了查"**规范里有没有写这一层**" |
| B | **份数 >1 ≠ 违规** | `.emptyTitle` / `.emptyIcon` 是不同用途。**必须读内容** |
| C | **同名 ≠ 同物** | `.spinner` 文字 vs 圆环 —— 只有读的时候才会露出来 |
| D | **"我改完了"不可信** | `.actions button` 是**第三次扫描**才抓到的。**改完再扫，直到为空** |
| E | **死变量 ≠ 死代码** | 68 个"死变量"里没一个该删（枚举型保留完整刻度）|
| F | **自引用不报错** | `--x: var(--x)` 看着像别名，实际是无效值 |
| G | **量具会骗人** | 对比度算错品牌（拿了最后一个）差点误判 —— **工具的输出要交叉验证** |
| H | **原版文案带黑话要留，自造的黑话要改** | 判据是"**来源**"，不是"有没有黑话" |
