| **L0 文字** | **无** | ADR / 文件头 / 注释 | 极低 | **只解释"为什么"**，不作防线 |
| **L1 类型层** | **编译期报错** | 必填字段 · 判别联合 · `as const` + 穷尽分支 | 低 | **优先** |

### 0.6 本文自身的验证与维护（**治本：不再存快照**）

> ⚠️ **2026-09-24 回改（原因实证）**：本节原写「谁改了被本文引用的东西，谁负责回头更新本文」+
> 「本文引用了 15+ 个落点，它们会过期」—— **该防线已实证失败**：本次实测本文已腐 **12 处**
> （6 处子目录化 + 4 处跨域搬迁 + 1 处漏前缀 + 1 处行号），而 V2 落盘后**无人回来改过一次**。
> 结论：**「靠自觉回头更新」= `母仓 ADR-0052` 第 6 级（无机器防线）；而"存快照"本身就是在制造腐坏面。**

**治法：不存快照。** 本文的落点一律写成 **`grep` 查法**（查符号名，不查行号）：

| 不写（会腐） | 改写成（不腐） |
| --- | --- |
| `createPersistController` @ `state/persist.ts:41` | `grep -rn "export function createPersistController" src` |
| `ErrorBoundary` @ `ui/shell/ErrorBoundary.tsx:1` | `grep -rn "export function ErrorBoundary\|export class ErrorBoundary" src/ui` |

**为什么查法不腐**：`grep` 匹配**符号名** —— 符号名是真源（改了它就该改引用），
行号只是它的**瞬时坐标**（每次无关改动都会平移）。**"必然腐的东西"不进文档，是唯一治本的做法。**

**仍存的少量路径**（如 `electron/`、`src/state/slices/`）只到**目录/文件名**粒度 ——
它比行号稳得多，且**改名会被 `npm run lint:boundaries` / `npm run typecheck` 立刻发现**。

**若本文件的某处仍腐了，最小动作**（改动 `base/` 或本仓落点后）：

```bash

grep -nE "\`[A-Za-z0-9_./-]+\.(ts|tsx)(:[0-9-]+)\`" .codebuddy/commands/架构师写新业务代码.md

# ② 引用过的 ADR / 债号 / 工具是否仍存在

```

- **描述与签名冲突时，以函数签名为准**（`filesApi.ts` 头部与 `@returns` 都曾与真实签名漂移）。
- 发现漂移 ⇒ **就地改**（A7），并在 note 里写明"旧描述错在哪"，**不要只在新文档里加修正表**。

## 1 · 交付金标准：四零一毁

### 1.1 数据 0 副本（状态绝对收敛）—— **结构偏好（强）**

- **红线**：同一个真相（SSOT）在物理内存只能有一份；UI 不许 `useState` 复制核心业务数据。
- **边界**：
  - **核心业务数据** = 会在别处被读/被落盘/被别人改的（如 items 列表、选中 id、落盘结果）⇒ **必须住 store**；
  - **纯 UI 状态** = 只在组件内用、不落盘、无他人关心（受控输入草稿、折叠展开、hover、局部筛选）⇒ **允许 `useState`**。
  - 判据问句：**「这个 state 删掉，别处会失忆吗？」** 会 ⇒ 是业务数据，不许放组件。
- **🔍 违反时怎么发现**：
  - `grep -n "useState" <组件>` 且该 state 初值来自 store/props ⇒ 副本嫌疑；
  - 出现 `useEffect(() => setLocal(x), [x])` 式**双向同步** ⇒ 铁证；
  - 手测：改 store 的值，UI 局部 state 不同步 ⇒ 已分裂。

### 1.2 异常 0 猜测（类型逼迫处理）—— **🔴 红线**

- **红线**：契约自带强迫性，不让调用方猜。禁止 `Data | null` / 隐式 `throw Error`；
  失败分支必须带**可展示文案**（否则消费者只能自己编话术 —— 那是"编造真相"）。
- **契约形状 / 字段口径（`Result` 的 `reason` + `message`）/ throw 边界 / 🔍 违反时怎么发现** ⇒ **真源 = `docs/11-架构与契约定稿.md` §六·五 原则 6 + `src/core/model/result.ts`（`UsecaseResult<T>`）+ `src/core/rules/failure.ts`（14 类分类表）**；本项目 `docs/adr/` 从 母仓 ADR-0001 起重新编号，该主题尚无条 ⇒ 首次确立时走 `node scripts/adr.mjs add`（本文不再复制）。
- **ACL 侧**：第三方 / 浏览器 API 的 throw 必须在**边界**转成判别联合（模板见 §3.2）。

### 1.3 UI 0 业务（无脑视图）—— **结构偏好**

- **红线**：UI 只做「状态投影仪 + 指令发射器」；业务条件由 core 算完，只吐视图指令。
- **本仓真实例子**（本项目**无角色系统**，勿套用"权限判断"类举例）：
  - ❌ **反例（原实现真实发生过）**：UI 写 `if (nodes.length === 0) return <空态/>`
    ⇒ **把"读盘失败"渲染成"这个工程还没有节点"**（失败被伪装成空）。
  - ✅ **正例（本项目已落地）**：失败由生产者产生 `Result` → `state` 写 `saveError:{message,at}`（**保留原文**，`bootstrap/container.ts:65`）→ UI 用 `ui/common/ErrorBanner` 渲染；
    空态走**另一个组件** `ui/common/EmptyState`。**失败与空是两个字段、两个组件**，UI **不做 `length === 0` 推断**（`docs/11` §六·五 原则 7 的配套形态）。
- **🔍 违反时怎么发现**：
  - 组件里出现对**数据层字段的语义推断**（`length === 0` 当"没有"、`!x` 当"失败"）⇒ 越权；
  - 组件里出现跨实体判断（额度/权限/状态机/重试语义）⇒ 越权。

### 1.4 架构 1 键毁灭（可废弃性）—— **结构偏好，且只适用于业务模块**

- **红线**：新业务可随时安全切除：删掉业务目录 + 改路由/注册表 1~2 行，项目零错跑通。
- **⚠️ 适用范围**：这条**只约束"业务模块"**，**不适用于横切地基**
  （`logger` / `contentStore` / `idGen` / `contracts` / `httpClient`…）。地基本就该被依赖，
  拿"能不能删"量它们 ⇒ 得出错误结论（会去拆地基）。
- **🔍 违反时怎么发现（可执行）**：删目录 + 改注册 ⇒ 跑 `npm run typecheck` 必须 **0 错**；
  再跑 `npm run lint:boundaries` + `npm run lint`，并用 `node scripts/mv-sync-refs.mjs find-dead src` 复核没留孤儿引用。

## 2 · 施工 4 步法

### Step 0 · 先写最优解 + 普查拦截（唯一开工前置）

> 🔒 **第一动作不是"查"，是"先写出最优解"**（真源：`架构师改码7步法` Step 0 + A14）。

**0.1 一屏以内写出「正确落地时长什么样」** → **真源 = `架构师改码7步法.md` Step 0**（查法：`grep -n "先写出最优解" .codebuddy/commands/架构师改码7步法.md`；本文不再复制）。

**0.2 新建三问**（存量改造不会有）：
1. **真的需要"新"吗**？（新建模块是最贵的选项，能加几行就别建）
2. **边界在哪**？（哪些**确定**属于它、哪些**确定**不属于；模糊 ⇒ 会长成万能模块）
3. **一键毁灭点在哪**？（需要它不与谁耦合）

**0.3 普查（三查）**：查原语（§5-B 速查表）→ 查相似链路 → **🔥 横向盘查**（同需求在别入口怎么满足的）。
→ **真源 = `架构师改码7步法.md` Step 0 第 3 步**（查法：`grep -n "横向盘查" .codebuddy/commands/架构师改码7步法.md`；本文不再复制）。

**0.4 放行判据（红线）** → **真源 = `架构师改码7步法.md` Step 0 开工指令**（查法：`grep -n "开工指令" .codebuddy/commands/架构师改码7步法.md`）。
**产出**：表①最优解（一屏）· 表②入口对照表 —— **未出不进 Step 1**。

### Step 1 · 定真相与边界

1. **SSOT**：锁定核心数据的唯一物理位置。
2. **所有权**：生产者/消费者划分；**消费者严禁执行所有方的动作**，只能发指令。
3. **禁幽灵预留（YAGNI）** —— **本文定义段，其余处只引用本节**。
   - 只为当前真实需求写接口；禁为"以后可能"预留 `interface AbstractX` / 无效参数。
   - 判据：**指不出"现在谁在什么场景用它" ⇒ 删**（本仓实证 TD-05-16：`onApply` 的 `fragment` 参数三处上抛恒等于 `item.prompt`）。
   - 🔍 **怎么发现**：`grep -rn "<新符号>" src` ⇒ **除定义处外 0 命中** 即为幽灵预留；
     `grep -n "interface Abstract\|TODO\|以后" <新模块>` 抓"为未来预留"的痕迹。
4. **钉死模型**：强类型写死，消灭 `any` 与无意义 `Record<string, unknown>`。
   - **类型权威下沉到"最低变化速率层"**（纯逻辑层，无 React/存储依赖）；快照层/节点 props/UI **引用它**。
   - 判据：**具名类型没人 import ⇒ 权威虚设**（实证 TD-05-18）。
   - 🔍 **怎么发现**：`grep -rn "import .*<MyType>" src` 是否 **0 命中**；
     `grep -rn "Record<string, " src` 是否各处仍在手抄（手抄 = 权威没下沉）。
5. **🔥 建了原语 ≠ 完成 —— 必须同时规定「谁必须调它」**（本仓最痛教训 · TD-05-12 母体）
   **本节为定义段；Step 4 第 3 条 / 自检 / 审计 prompt 第 8 条只引用本节。**

   每个新增原语写两行：**① 谁必须调它（路径清单，必须穷尽）② 验收方式**。
   - **只列一条 = 假接线**（实证 TD-05-13：漏了 Agent 路径，单测照样绿）；
   - 验收 = **生产消费 > 0**（`grep` 除定义处外真有命中；**只有测试命中 = 幽灵预留**）；
   - 能用类型就别用力（`as const` + 穷尽 switch ⇒ 忘接线**编译期报错**）。

### Step 2 · 定契约与防腐层

1. **ACL 防腐层**：外部/旧接口/第三方数据**必须在边界洗脱**，转成 Step 1 的纯净类型后才准进 core。
   - 🔍 **怎么发现**：`grep -n "as unknown as" <新模块>` / `grep -n "as any" <新模块>`（绕过类型洗脱）；
     core / adapter 之外出现 `Record<string, unknown>` 形参 ⇒ 脏类型已进 core。
2. **失败契约（判别联合）**：见 §1.2（**`code` + `message`**）。
   - 🔍 **怎么发现**：`grep -nE "\): (Promise<)?[A-Za-z]+ \| null" <新模块>`（`T | null`）· 逐个看 `ok:false` 分支是否带 `message`。
3. **切断默认值兜底**：查不到 ⇒ 抛错或 `NotFound`；**严禁私自塞 `""` / `{}` 让逻辑跑通**。
   - 🔍 **怎么发现**：`grep -nE "\?\? *([\"']{2}|\{\}|0)" <新模块>`（静默补默认值）· `grep -n "?? \[\]" <新模块>`。
4. **异常也要洗脱**：第三方/浏览器 API 的 **throw 在 ACL 转成判别联合**
   （`try { … } catch (e) { return { ok:false, code:'InvalidPayload', message: String(e) } }`），不许把裸 throw 放给 core。
   - 🔍 **怎么发现**：`grep -n "throw " <新模块>` ⇒ 逐个确认是「不该发生」的编程错误（母仓 ADR-0005 那种根部抛），
     凡是"预期会失败"的分支都必须改成判别联合返回。

### Step 3 · 核心组装与 UI 投影

1. **纯化运算**：「怎么算」抽成无外部依赖的纯函数（可单测）。
   - 🔍 **怎么发现**：`core.ts` 里出现 `use*`（hook）、`from 'react'`、直接读 store ⇒ 已被污染。
2. **中心调度黑盒（Store / Core）**：收敛数据与规则，对外**窄接口**；外部"无脑传参"，不在外部拼业务逻辑再调。
   - **store 选型见 §4.3**（两种模式，**按域一致**）；真源 + 快照引用稳定（范本查法同 §4.3）。

     `grep -rn "<新模块>" src` 看调用方有没有"先拼一段业务逻辑再调"（拼装逻辑应在 core）。
3. **UI 极致降级**：UI 只做投影 + 派发（见 §1.3）；横切出口见 §4.6 表。
4. **生命周期 / 并发 / 取消**（V1 完全没有，V2 补齐 —— 新业务最容易忽视的一类）：
   - **订阅必须可退订**：适配器只暴露 `subscribeXxx(cb): () => void`（`docs/11` §六·五 原则 2），退订函数必须在 effect cleanup 里释放（`<StrictMode>` 会双调用，不退订 = 双份监听）；
   - **落盘要节流**：高频写入走 `state/persist` 的 `createPersistController`（防抖 `PERSIST_DEBOUNCE_MS`，经 `ClockPort`）—— **禁每次 mutation 直写 `StoragePort`**（那等于绕过唯一持久化链路）；
   - **异步必须可取消 + 有超时**：`AbortController` + **时序一律经 `ClockPort`**（`docs/11` §4.4）。
     ★ **统一超时原语 = `src/lib/async.ts` 的 `withTimeout`（已落地）** ⇒ 新代码**一律用它**，不要自写超时（阈值用具名常量、时序仍经 `ClockPort`）；
   - **并发**：本项目**仍无并发锁原语**（当前并发由 `state/sendQueue` 的"在跑计数" + `state/slices/queue.ts` 的每账号并发上限控制）

   - 🔍 **怎么发现**：`grep -n "useEffect" <新模块>` ⇒ 每个订阅是否都有 cleanup；
     `grep -n "await " <新模块>` ⇒ 每个长任务是否都有超时或取消路径。

### 4.1 目录（按层归位 + 物理隔离 + 一键删除）

> ⚠️ **本项目不是 `src/components/<域>/` 那种"一个域一个目录"** —— 而是**按层归位**（`docs/11` §二）。
> 新业务按职责拆到下列位置，**不新建平行目录树**：

```
src/core/model/<域>.ts        # Step1 唯一模型（判别联合；冻结后移 src/stable/model/）
src/core/rules/<域>.ts        # Step3 纯函数（无 React / 无 window / 无存储）
src/core/usecases/<域>.ts     # 编排（返回 Result，**不写 store**）
src/core/ports/               # 需要外部能力时才开端口（**只开 4 个**，见 docs/11 §四）
src/adapters/<host|site|storage|clock>/   # Step2 ACL（数据 + 异常 双重洗脱；**唯一接触外部世界**）
src/state/slices/<范围>.ts    # 状态真源（按「共享范围」切，见 4.3）
src/ui/<域>/                  # UI 木偶（只依赖 state + core/model 类型）
```

**import 约定**：一律用 `@/` 别名（`tsconfig.json` 的 `paths` + `vite.config.ts` 的 `alias`），**不写扩展名**；
层间方向由 `npm run lint:boundaries` 强制，**禁反向、禁跨层跳跃**（规则 1/2/3）。
**禁 barrel**：每层暴露**若干小入口点**，不写一个巨型 `index.ts` 全导出（`docs/11` §3.1 第 4 步）。

**命名强制项 —— 域专用物必须带域前缀**（用户裁定，**强制，非可选**）：

> 凡是**只服务某一个域**的导出（原语 / 适配壳 / 常量 / 组件），**名字里必须带该域名**。
> 目的：避免与通用原语**撞名** ⇒ 调用方 `import { x }` 出现两个来源，误引且难查。
> - ✅ 正例（本项目）：`createMockHost` / `createElectronHost`（域 + 能力名）、`persistProject`（用例名自带动词）、`externalizeProjectImages`（能力名）。
> - ❌ 反例形态：某个只在单域使用的适配壳却叫 `logger` / `storage` 这类通用名 —— 一旦第二处出现同名导出即撞名。
> 🔍 **怎么发现**：`grep -rn "export \(const\|function\|class\) <通用名>" src` 若**命中 ≥2 处**且分属不同层 ⇒ 违规（需加前缀或证明是同一实现）。

### 4.4 adapter.ts（数据 + 异常 双重洗脱）

```ts
export function mapExternalToMyItem(raw: unknown): BizResult<MyItem> {
  if (typeof raw !== 'object' || raw === null) return { ok:false, code:'InvalidPayload', message:'外部数据格式非法' };
  const r = raw as Record<string, unknown>;
  // ⚠️ 必填字段缺失 = 失败；**不许 `?? ""` / `?? 0` 静默补**（那正是本文禁的默认值兜底）
  if (typeof r.id !== 'string' || typeof r.title !== 'string' || typeof r.count !== 'number')
    return { ok:false, code:'InvalidPayload', message:'字段类型不符' };
  return { ok:true, data:{ id:r.id, title:r.title, count:r.count } };
}
```

### 4.5 io / 数据访问（不裸调宿主 / 不裸 throw / 不吞错）

```ts
export async function loadMyList(deps: Deps): Promise<Result<MyItem[]>> {
  try {
    // 数据源 = **端口**（本项目数据源是 window.api，不是 HTTP）⇒ 经 HostPort，禁 UI 直调宿主
    const raw = await deps.host.api.listMyItems();
    // ⚠️ 先校验**形状**再逐个过 ACL：**不要把整个数组塞给单元素 mapper**
    // （数组 `'id' in []` 为 false ⇒ 那样写会永远返回 ok:false —— 本模板前一版就犯过这个错）
    if (!Array.isArray(raw)) return err('unknown', '响应不是数组');
    const items: MyItem[] = [];
    for (const one of raw) {
      const r = mapExternalToMyItem(one);
      if (!r.ok) return r;                    // 生产者给全 ⇒ 只转发，不重编话术
      items.push(r.value);
    }
    return ok(items);
  } catch (e) {
    // ★ 原则 6：原样透传 —— **不改写成"列表加载失败，请重试"**（那属展示层，按 reason 在 constants/text.ts 映射）
    return err('unknown', toMessage(e), e);
  }
}

/** 落盘 —— 本项目**最常见的收尾动作**：走唯一入口，绝不吞失败 */
export function saveMyItems(items: MyItem[]): Result<void> {
  try {
    deps.storage.write(LS_MY_ITEMS, items);   // 键必须先在 stable/contracts/keys.ts 登记（LsKey）
    return ok(undefined);
  } catch (e) {
    // ★ 原样透传（原则 6）：不美化、不吞、不编 reason
    return err('unknown', toMessage(e), e);
  }
}
```
> ⚠️ `LS_MY_ITEMS` **必须先在 `src/stable/contracts/keys.ts` 登记**（`LsKey` 字面量联合 ⇒ **拼错编译期就报错**；
> 散落的 `'doubao-*'` 字面量会被 eslint 的「原则5」拦）。
> 返回 `Result` 而非 `boolean` 是给调用方的**真话**：失败就是 `ok:false` + **原始 `message`**，
> **不许无条件 `return ok(...)`**（那会让 UI 宣布"已保存"）。

```ts
  it('必填字段缺失 → ok:false（不许静默补默认值）', () => expect(mapExternalToMyItem({ id: 'x' }).ok).toBe(false));
});
```
**上例非自证式的判据**：输入是现实给的（空/11 条/`null`），断言的是行为；改坏实现必红（阈值 `> 10` 改 `> 100` ⇒ 第 2 条红）。
❌ 自证式（禁止）：`expect(typeof fn).toBe('function')` · `expect(mockFn).toHaveBeenCalled()` · 只断"没抛错"。
⚠️ **只测纯逻辑，不测 UI**（`docs/11` §六·五 原则 7）：`ui/**` 与 `adapters/**` 下**不得有测试文件**（eslint（`npm run lint`）的「原则7」规则会拦）；UI 用 `node scripts/verify-*.cjs`（无头 Chromium）验**真实用户路径**。
