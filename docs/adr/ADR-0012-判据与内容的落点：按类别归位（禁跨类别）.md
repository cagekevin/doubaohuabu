# ADR-0012 · 判据与内容的落点：按类别归位（禁跨类别）

- **状态**：生效
- **结论**：每句话只有一个类别归属：判据→ADR · 现状→DATAFLOW · 红线→硬约束 · 细节→代码头 · 流程→commands。写错类别 = 结构性错位（同一真相两份）；入口文档只装路由与例外，不装正文。
- **日期**：2026-10-16
- **裁定人**：用户
- **触发**：系统性搬运ADR-0012（本仓 3 处引用）

## 背景

本仓 **3 处**引用它：`架构师写新业务代码.md` 的内容落点表 ＋「**取自 `ADR-0012`：撬不动 ⇒ 红线；撬得动但要有代价 ⇒ 判据/偏好**」＋ `架构师改码7步法.md`「判据原文见 `docs/adr/ADR-0012`（内容落点：按类别归位，CONTEXT 只装路由与例外）」。

本仓 **已有半条**：`AGENTS.md` §七「**文档地图（结果只有一份）**」—— 但它是**索引**，不是"**类别 → 该住哪个文件**"的归位判据 ⇒ 写的人仍然要猜"这句该放哪"。

**被推翻的旧形态**：按"内容重要程度"或"顺手写在哪"决定落点。后果是**可判的**（不是审美问题）：

| 写错方向 | 后果 |
| --- | --- |
| **现状**写进 `docs/adr/` | 现状会变 ⇒ 条目**过期**，且判据与事实混在一句里（读者分不清哪半是判据） |
| **判据**只写在代码头 / 命令文件 | 判据住在"读者不会打开"的地方（`ADR-0002` 第 6 级：判据要写在读者一定会打开的那一行） |
| **红线**写进 `commands/` | 被当"参考"而非"约束" ⇒ 越线时没人拦 |
| 同一句在两类载体各一份 | **第二份真相**（`AGENTS.md` 母体表禁止） |

## 判据（它凭什么成立 / 为什么不成立）

- **类别是互斥的**：一句话不是判据就是现状（或红线/细节/流程），**没有"都算"** ⇒ 归属有唯一正确答案，因此**可判**。
- **类别决定"寿命与读者"**：判据活到被取代 · 现状活到下次改动 · 红线活到物理约束变 · 细节随代码走 · 流程随工作方式变 ⇒ **把短命内容放进长命载体 = 结构性错位**。
- **「撬不动 / 撬得动」是同一分类动作的另一面**：撬不动 ⇒ 它由物理约束背书（红线）；撬得动但要有代价 ⇒ 是判据/偏好 ⇒ **两条都落到"它住哪 + 能不能被改"**。
- **只能人判**：类别识别是语义判断，无类型/结构可承载（`ADR-0002` 第 6 级：写明"不能"）。

## 决议

**① 落点表（本条为唯一真源）**

| 类别 | 判据 | 住哪 |
| --- | --- | --- |
| **判据**（凭什么成立 / 被谁推翻过） | 「这条规矩为什么是这样」 | `docs/adr/` |
| **现状**（谁依赖谁 / 链路怎么走） | 「现在实际上是什么样」 | `docs/DATAFLOW.md` |
| **红线**（物理约束） | 「不这么做会坏」 | `docs/11-架构与契约定稿.md` §三／§六／§六·五 |
| **细节**（怎么实现这一点） | 「这段代码为什么长这样」 | 代码头注释 |
| **流程**（怎么做这件事） | 「先做什么再做什么」 | `.codebuddy/commands/` |
| **真源与载体数** | 「这条判据的真源在哪、现在几份」 | `docs/判据登记表.md` |

**② 入口文档只装路由与例外**：`AGENTS.md` 是**索引 + 例外**（"该看哪个文件"），**不装判据正文**（正文只许住 `docs/adr/`；命令文件只留动作与指针）。

**③ 反滥用（双向）**：不许拿"这属于判据"把**现状**写进 `docs/adr/`；也不许拿"这属于细节"把**判据**只留在代码头（那正是"判据住在没人打开的地方"）。

**边界（对方未搬 ⇒ 保留仓外指针，禁省略）**：`母仓 ADR-0031`（同一判据的域外副本三分：**探测重复**／**判据重复**／**不可收口** —— 定落点后按它分类，**未搬**）。与 `ADR-0011` 的分工：**那条管"几份"**（载体账 N→M），**本条管"该住哪"**；与 `AGENTS.md` §七 的分工：§七 只做**地图**（去哪找），本条给**归位判据**（该放哪）。

**落点**：`AGENTS.md` §七（文档地图 →「结果只有一份」＋ 指向本条）· `docs/DATAFLOW.md` · `docs/判据登记表.md` · `docs/adr/`（判据本体）。

## 后果

- ✅ **收益**：落点从"顺手写"变成"有唯一答案"；长命/短命内容不再互相污染；本仓 §七 从"只有地图"补齐为"地图 ＋ 归位判据"；3 处仓外指针收敛为 1。
- ⚠️ **回潮风险**：现状悄悄写进 ADR（最省事）；或把判据抄进 `commands` 当"方便查阅"。
- 📌 **违反时的判据**：
  1. 一条**会随后续改动而变的现状**写在 `docs/adr/**` 里 ⇒ 违规（处置：抽到 `DATAFLOW.md`，条目只留判据）；
  2. **判据正文**只出现在代码头 / 命令文件，而 `docs/adr/` 无对应条 ⇒ 违规（处置：落条，原处留指针）；
  3. 同一句话在**两类载体**各有一份 ⇒ 违规（保留判据那份）；
  4. 拿「撬不动」当"不许改"的挡箭牌，却指不出它属 §三/§六/§六·五 的哪一条 ⇒ 违规（红线必须有物理约束背书，`ADR-0004`）。
  ⚠️ **诚实边界**：4 条**均不可机器判定**（类别识别是语义判断）⇒ 按 `ADR-0002` 第 6 级给人工判据，**禁硬凑 grep**。
