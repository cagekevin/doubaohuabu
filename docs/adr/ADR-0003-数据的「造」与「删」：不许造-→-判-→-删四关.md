# ADR-0003 · 数据的「造」与「删」：不许造 → 判 → 删四关

- **状态**：生效
- **结论**：删只有一个理由 ＝ 清障：不许为设想消费方铺路；报零 ≠ 没人用（先定位本该消费处）；过四关（目的／能力／消费／红线）才可删，查不清 ⇒ 改为修。禁为过闸删本次新写的码。
- **日期**：2026-10-16
- **裁定人**：架构师（取证后自定）
- **触发**：系统性搬运ADR-0003（本仓 12 处引用指向它，被引最多）

## 背景

本仓 `架构师改码7步法.md` 的 `Step 6` 顶部与 `.codebuddy/commands/删.md` 都把"删"的判据挂在仓外（**12 处**引用同一编号）⇒ 执行者读到的是指针，目标读不到。

**被推翻的旧形态**（两个方向都错过）：把"该接上"的当"幽灵预留"删了 ⇒ **第二份真相（内联实现）当场合法化**；把"假守卫"留着 ⇒ 声称守契约、实际无人读，**骗过所有读它的人**。⇒ 病根不是"它没人用"，是**它的 export 面与"本该被消费的位置"对不上**。

## 判据（它凭什么成立 / 为什么不成立）

- **报零 ≠ 没人用**：`lint:dead-code`（knip `--production`）只看得见**构建图内**的引用；本仓明写两类**边界外消费者** —— `scripts/**`（闸脚本以运行时拼路径读 src 导出）与 `electron/**`（宿主壳独立工程）⇒ 它们消费的导出会被**误判为零消费**。
- **删的宾语是「能力」，不是「文件」**：本仓红线「**删掉它，用户能做的事不许变少**」。
- **闸不许凌驾正确性**：为让死代码闸变绿而删**本次新写**的功能码 ⇒ 违 `AGENTS.md` §九。
- **只能部分机判**：「假守卫」可机判（负例探针强制变红即证）、「有第二份内联」可机判；但「本该消费处是空的 / 是第二份 / 在边界外」**结构上不可判**（ADR-0002 第 6 级）。

## 决议

**① 造**：不许为设想消费方铺路 —— 不留"落了但没人调"的件（`AGENTS.md` §八 DoD ④）；不为不确定性预留开关 / 字段 / 类型。

**② 判（报零后的定位，先于任何删除）**：先定位「**本该消费它的地方**」，看那里现在是什么，六类分档：

| # | 本该消费处现在是什么 | 类型 | 处置 |
| --- | --- | --- | --- |
| ① | 空，且谁也用不上 | 幽灵预留 | **删** |
| ② | 空，但**同文件内自用** | 导出面过宽 | **摘掉 `export`**（不删） |
| ③ | 不空，同段逻辑**已有第二份**（内联） | 被内联取代 | **接上**，删掉内联那份 |
| ④ | 不空，**有调用点但漏接** | 接线未完成 | **接上**（补缺失参数与链路） |
| ⑤ | 消费在 knip **边界外**（`scripts/**` · `electron/**`） | 跨边界 | 在**声明处**打 `@public 跨边界消费者：<路径>`（机器核验三条件：句式 + 路径存在 + 真含符号名） |
| ⑥ | **表达层缺档**（同一文件内的语义词族） | 设计词汇表 | **豁免** |

**横切警示 —— 假守卫**：**声称守契约、实际无人读**，是第 ① 类的**伪装**。识别动作唯一：**写一个负例探针**（故意改坏它），看闸是否变红；不红 ⇒ 它是空的，按 ① 处置并**销掉那条契约声明**。

**③ 删四关（缺一不可）** —— ⚠️ **本条的"删"＝代码 / 能力**；**判据落点选"删"（取消一条判据）**走 `ADR-0002` 第 1 级，两者不是一回事。

| 关 | 判据 |
| --- | --- |
| **目的** | 答得出「**降了哪项复杂度**」；答不出 ⇒ 不删 |
| **能力** | 用户能做的事**不变少**（命令 / 入口 / 功能 / 对外契约属"变少" ⇒ 不许删） |
| **消费** | **逐个消费点回扫**（不是逐类载体）：`node scripts/mv-sync-refs.mjs refs <file>` 顺链查到底 |
| **红线** | 它是不是某条红线的**唯一执行者**；是 ⇒ 答不出"谁接替它" ⇒ 不删 |

**④ 时机**：清偿是**收尾动作**，不是准入门槛 —— 先把功能写完跑通再清。新增 / 替换时旧实现**短暂零消费是必然**；**禁**为让 `mv-sync-refs.mjs find-dead` 报零而删本次新写的码 / 退回被替代的老实现。正确形态 = **同批完成**（新接上 + 旧删除）。

**⑤ 举证责任在「删」这一方**；查不清 ⇒ **改为修**。**`--update-baseline` 红线**：闸报「基线外新增」时**不许**直接 `--update-baseline`（= 把回潮塞进基线发合法证）；必须先判"这份零消费实现该不该存在"。

**⑥ 删 / 退役的后置对账**：对账它的**半径外一步**（它独占消费的上游符号），逐条定性：真死 → 删 · 被取代 / 断链 → 接上 · 能力 / 契约 → **留痕**（写明它承载什么能力，不是判它该删）。

**⑦ 落点**：本条 = 判据本体 · `scripts/check-dead-code.mjs`（knip 基线**永不复涨** ＋ `@public` 三条件核验）· `scripts/mv-sync-refs.mjs refs` · `commands/删.md` 与 `Step 6` = **指针**（12 处收敛为指针 1 处）。

**⑧ 边界（对方未搬 ⇒ 保留仓外指针，禁省略）**：`ADR-0009`／`母仓 ADR-0045`（同一能力已有在用实现时，**先判哪一份正确**，不得默认保留内联那份）· `ADR-0011`（**收口**验收：载体账 N→M）· `ADR-0003`（②-b 落点定位的六类动作，**只给动作不给裁决**）。本条只管**删**。

## 后果

- ✅ **收益**：「删」从**默认**降回**有条件结论**；堵住"砍用户能力 / 白删 / 为过闸删新码"三条路；12 处指针收敛为 1 处。
- ⚠️ **代价 / 回潮风险**：门槛变高。反风险三处：① 拿"能力"当借口**留真死代码** ② 拿"过渡态"当**永久豁免** ③ 拿"该接上"当留死代码的挡箭牌（故必须指得出**具体调用点 / 内联份**）。**最常见偷懒 = 只清数值层**（类型／配置／文档三层载体天然不可见）。
- 📌 **违反时的判据**：
  1. 删掉的东西含**命令 / 入口 / 导出 API / 对外契约**，而 `git diff` 里**没有"用户已裁定"的痕迹** ⇒ 违规；
  2. `git diff` 出现「为过死代码闸而删掉 / 回退**本次新写**的功能码」⇒ 违规；
  3. 提交里出现 `--update-baseline` 而理由未写明"先判了该不该存在" ⇒ 违规（可机判）；
  4. 报零即删、答不出"本该消费它的地方在哪、那里现在是什么" ⇒ 违规；反向（把该**接上 / 该打 `@public`** 的当幽灵预留删掉）同样违规；
  5. 交付说明写「删了 X」却答不出「复杂度降在哪一项」⇒ 违规（白删）。
  ⚠️ **诚实边界**：可机判的只有 2、3；1、4、5 须人工核对（ADR-0002 第 6 级：写明"不能"，不许硬凑 grep）。
