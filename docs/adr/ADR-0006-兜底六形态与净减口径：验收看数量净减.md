# ADR-0006 · 兜底六形态与净减口径：验收看数量净减

- **状态**：生效
- **结论**：兜底只有六形态（静默 catch／失败归一空值／占位对象＋事后补／默认值兜底／UI 层提前宣告成功／只在某入口补的补偿步骤）；验收口径 ＝ **数量净减**，不是症状消失。
- **日期**：2026-10-16
- **裁定人**：架构师（取证后自定）
- **触发**：系统性搬运ADR-0006（本仓 2 处引用指向它）

## 背景

本仓 **2 处**引用这个编号（失败判据交叉校验清单），本体在仓外。本仓的执行面已存在：`eslint.config.js` 的 `no-empty`（禁空 catch，**无豁免逃逸口**）· `src/core/model/result.ts` + `src/core/rules/failure.ts`（失败分类与透传）。

**被推翻的旧验收口径**：「症状消失了 = 修好了」。在这条口径下，最省力的"修复"是**在报错处加一层接住** —— 症状立刻消失、体验"变好"，而真实代价（**报错的位置不变，但再也看不见**）被推迟到三个月后。

## 判据（它凭什么成立 / 为什么不成立）

1. **因果不可逆**：兜底让症状消失 ⇒ 你会以为修好了 ⇒ 错误被埋得更深 ⇒ **真正的问题再也排查不出来**（信息已丢，不可逆）。
2. **可数**：兜底是**代码实体**，可枚举、可清点、可比对改前改后 ⇒ 口径能落到**数字**上，不靠感觉。
3. **封闭枚举**：六形态是**封闭集**——"接住失败"的手段在 TS/JS 里只有这些位置（catch / 返回值 / 对象构造 / 默认参数 / UI 状态 / 补偿步骤）。**答不出形态 ⇒ 你还没理解它**（不是发现了第 7 种）。
4. **边界**：类型守卫（`if (!x) throw`）**不是兜底**，是 **fail-fast**；不许拿"这是兜底"当借口**删掉正常的防御性校验**。

## 决议

**① 六形态（看到自己在写这些 ⇒ 停，问"我在掩盖什么"）**

| # | 形态 | 说明 |
| --- | --- | --- |
| ① | **静默 catch** | `.catch(() => {})` 零留痕（本仓已无"标记豁免"机制：`no-empty` 是唯一载体） |
| ② | **失败归一空值** | 把各种失败压成一个 `null` / `[]` / `{}`，调用方无从判别（与 `ADR-0005` 互补：那条管**怎么表达**） |
| ③ | **占位对象 ＋ 事后打补丁** | 先塞个假对象让它跑通，再在别处补 |
| ④ | **默认值兜底** | 拿不到就给个默认值，假装成功 |
| ⑤ | **UI 层提前宣告成功** | 上层先显示"成功"，下层其实还没落盘 |
| ⑥ | **只在某一入口补的补偿步骤** | 哪里报错补哪里，而不是改结构 |

**② 强制动作**：每发现一处兜底，**逐个问「它在掩盖哪条地基缺陷？」** —— **答得出 ⇒ 改地基、删兜底**；**答不出 ⇒ 你还没理解它，不许加成第 7 种**。

**③ 验收口径（唯一）**：**兜底数量净减**（改前 N → 改后 M，M < N，并列给出）；**不是**"症状消失了"（症状可能只是被兜底埋了）。⚠️ **净减的动作本身**（删兜底 / 删死代码）走 `ADR-0003` 四关 —— 净减**不是**许可随便删。

**边界（对方未搬 ⇒ 保留仓外指针，禁省略）**：`母仓 ADR-0003`（logger 之下失败只能由返回值表达 —— **本仓无对象**）· `母仓 ADR-0048`（运行时守卫写法：边界判据 ＋ 可见失败 ＋ 按后果选 fail-soft/fail-fast —— 未搬；本仓"守卫"的落点见 `AGENTS.md` §九 与 `ADR-0002` 第 5 级）。与 `ADR-0003` 的分工：本条管"**不许把失败表达成没事**"，`ADR-0003` 管"**能不能删**"。

**落点**：`eslint.config.js` 的 `no-empty`（禁止空 catch 的唯一载体）· `src/core/model/result.ts` · `src/core/rules/failure.ts` · `.codebuddy/commands/架构师改码7步法.md` 的 Step 4「拆兜底」与交付六闸的「减一」。

## 后果

- ✅ **收益**：验收从"看起来好了"改为**可数**；把"加一层接住"从"修复"重新定义为**新债**；2 处指针收敛为 1 处。
- ⚠️ **代价 / 回潮风险**：删兜底期间**用户可见报错会变多**（失败不再被藏住）—— 容易被误报为"改坏了"。回潮动因 =「上线要紧，先接住」。⇒ 落账**必须同时给度量**（兜底数改前 / 改后）。
- 📌 **违反时的判据**：
  1. 改动的 diff 里**新增**了六形态之一，而落账未说明"它掩盖了哪条地基缺陷" ⇒ 违规；
  2. 一个 bug 被"修复"后**兜底总数未降**（改前 / 改后度量答不出）⇒ 违规；
  3. 出现第 7 种"接住失败"的写法且无法归入六形态 ⇒ 违规（= 理解不足就动手）；
  4. 测试为让新增兜底通过而**新增适配分支** ⇒ 违规；
  5. 拿"这是兜底"去删**类型守卫 / 正常防御性校验** ⇒ 违规（反滥用）。
