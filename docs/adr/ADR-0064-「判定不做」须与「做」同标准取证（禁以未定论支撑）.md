# ADR-0064 · 「判定不做」须与「做」同标准取证（禁以未定论支撑）

- **状态**：生效
- **结论**：「判不落／不做／不移植」是零成本高价值判断，也最易掺偷懒 ⇒ 必须与「做」同一套取证（回源 file:line · grep 调用方 · 查后端/端口是否已存在）；禁用另一个「未定论」支撑「不做」（循环论证）；查不出 ⇒ 不许下「不做」。
- **日期**：2026-10-13
- **裁定人**：用户
- **触发**：准备下「判不落／判定不做／不移植」结论之前

## 背景

旧口径 = `架构师改码7步法` Step 1 第 4 条：「拿不出证据 → **不做**。但"不做"也必须在账本写明理由」。
它把「不做」的门槛定得**比「做」低**：说「做」要回源取证、grep 调用方、出三张表；说「不做」只需一句形容词。
而「不做」恰恰是**最省力、最容易被偷懒冒充**的判断 —— 它零成本、又天然"高价值"（省下整轮工作）。

**实证（本仓 · 2026-10-13）**：把 `vP`（主进程批量下载 `lovartFetchImages`）判成「不移植」，
用了 **① 循环论证**（拿「BP-34 不移植 `mp`/`pP`」去封 BP-17，而 BP-34 自己的结论只是**「待裁」**）
＋ **② 事实错**（说"触发条件在本仓不存在"，而 `electron/lovart-fetch.ts` **早已完整落**、`window-api.d.ts:125` **早已声明**，只是前端零接线）。
⇒ 见 `daily/架构日志/16-跨区-批量取图接线-2026-10-13.md`。

## 判据（它凭什么成立 / 为什么不成立）

- **「做」与「不做」是同一枚硬币的两面**：都改变系统形态（多一个能力 vs 少一个能力），
  凭什么一个要取证、一个只要形容词？⇒ **必须同标准**。
- **「不做」天然更贵**：判错「做」= 多写代码（可见、可回退）；判错「不做」= **能力永久缺席**（无人再查，因为账本已写"不落"）。
  ⇒ 「不做」的举证责任**更重**，不是更轻。
- 这条判据够不着物理红线 / 类型层 / 唯一入口 / 对账测试（它是「下结论的严谨度」，非代码结构）
  ⇒ 载体只能是**文档留痕（ADR，手段优先级 5）**。**没有机器守卫** —— 靠输出前自查 + 退回速查表。

## 决议

**下「判不落／不做／不移植」之前，必须过《不做取证三问》（与「做」同一套取证）：**

1. **回源到 `file:line`** —— 不许凭符号名 / 记忆 / 注释（附 A1/A2）。
2. **grep 调用方** —— 含**分析边界外**（`scripts/**` · `electron/**`）；"件都在、缺接线"是本仓高频形态。
3. **查后端 / 端口 / 类型是否已存在** —— 先查"能力有没有"，再谈"前端接没接"。

**两条禁令：**

- ⛔ **禁用另一个「未定论」支撑「不做」**（待裁 / 待验证 / 待定）—— 那是**循环论证**。
- ⛔ **查不出 ⇒ 不许下「不做」** —— 只能写「**事实待实测**」（不许用形容词结案）。

**落点**：`架构师改码7步法` 的 **Step 1 第 4 条**（动作）+ **退回速查表**（触发退回）+ **附 A**（铁律 A16）。

## 后果

- ✅ **收益**：「不做」不再能用形容词换；每个「不做」都带一条可复现取证（回源行号 / grep 输出 / 后端存在性）。
- ⚠️ **代价 / 回潮风险**：「想清楚」**不可机器验证**（无闸、无负例探针）⇒ 一旦无人回读就退化成"多写三行字"。
  防线只有两道：输出前自查 + 退回速查表；**若发现它退化成形式，就升级为落账模板的必填字段**（那一刻才走「建闸前置评审」）。
- 📌 **违反时的判据（怎么发现"又回去了"）**：下「不做」时，**看它引的证据是「回源 file:line / grep / 查后端」还是「另一个未定论 / 形容词」** ——
  引后者 ⇒ **违反**。判据一句话：**把「不做」那句的"因为…"抽出来，逐条问"这是查出来的，还是想出来的？"**
