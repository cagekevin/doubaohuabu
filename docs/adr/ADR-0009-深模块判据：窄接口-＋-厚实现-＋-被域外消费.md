# ADR-0009 · 深模块判据：窄接口 ＋ 厚实现 ＋ 被域外消费

- **状态**：生效
- **结论**：深模块三判据（窄接口 · 厚实现 · 被域外消费）全中才算；行数／文件数**不作判据**（拆分只认真缝隙：变化速率不同或出现第二种实现）；浅而宽 ⇒ 收口出口面，不是拆文件。
- **日期**：2026-10-16
- **裁定人**：架构师（取证后自定）
- **触发**：系统性搬运ADR-0009（本仓 1 处引用；本仓 `max-lines` 已关，同源）

## 背景

这条判据在本仓**散在多处、无主场**（搬运前实测）：

| 位置 | 现在写的 |
| --- | --- |
| `AGENTS.md` §三 | 「单 slice ≤ 300 行 · state 字段 ≤ 25 个 · action 只编排」＋「**行数上限不由闸强制** —— 行数是代理指标」 |
| `eslint.config.js` 的 `max-lines` 处 | 关闭理由：行数是**代理指标**，对"纯数据/文案表"与"逻辑文件"用同一把尺会逼出"为拆而拆" |
| `ADR守护者.md:124` | 「判据是**接口宽度**，不是『有没有门面』」 |
| `架构师改码7步法.md` Step 6 | **白删信号**：接口宽度没变窄 / 少了一层却没少一个真相 |

**被推翻的旧形态**：「行数到了就拆」「文件多就是差」「有门面就是深模块」。

## 判据（它凭什么成立 / 为什么不成立）

1. **行数是代理指标，不是好设计的度量** —— 它对"纯数据/文案表"与"逻辑文件"用**同一把尺** ⇒ 逼出"为拆而拆"（本仓实证：四片文案链 `text.ts → 各分片`，每拆一次多一个文件 ＋ 一层 re-export 间接）。
2. **模块的好坏只有三判据**（全中才算深模块）：**窄接口**（出口少而稳）· **厚实现**（内部复杂度被吃掉）· **被域外消费**（边界之外真有人用）。
3. **fan-in = 0 不是深模块**，是幽灵预留 ⇒ 处置归 `ADR-0003`（该接上 / 该摘 export / 该删）。
4. **浅而宽 ≠ 该拆文件**：接口宽薄实现是**泄漏**，正解是**收口出口面**（摘 export / 归并），拆文件只把它切成两份宽接口。
5. **归属先于深浅**：先判它在哪（哪个域 / 哪一层），再判它好不好。

## 决议

1. **判好坏只看三条**：窄接口 · 厚实现 · 被域外消费（**缺一不算**）。
2. **行数 / 文件数不作判据**：禁以其为"拆分"或"登记债"的理由；合并/拆分只认**真缝隙**（变化速率不同 · 出现第二种实现）。
3. **新建能力先答**：「**谁在它的边界之外用它**」—— 答不出就别建（与 `ADR-0003`「不许为设想消费方铺路」同向）。
4. **门面判据 = 接口宽度**：禁拿"要有 / 不要有门面"当依据（`ADR-0004`：既有约定不是判据来源）；拆/建门面须过三关：**正确性不退（否 ⇒ 禁做）· 复杂度变低 · SSOT 变好**。
5. **反滥用**：不许拿"这是深模块别动"当**拒绝拆分**的挡箭牌 —— 三条必须逐条给证据，说不出三条证据就不许说"这是深模块"。

**边界（对方未搬 ⇒ 保留仓外指针，禁省略）**：`母仓 ADR-0044`（域内落点：域根只留门面＋装配入口＋例外 —— **未搬**；本仓等价载体 = `AGENTS.md` §十 目录速览 ＋ `docs/判据登记表.md` 的落点列）· `母仓 ADR-0031`（同一判据的域外副本：**探测重复收口 / 判据重复禁合并** —— 未搬）· `ADR-0011`（收口验收 N→M —— 未搬）。与 `ADR-0003` 的分工：**那条管"删不删"（准入门）**，本条管"**模块好坏怎么量 / 值不值得拆**"。⚠️ **同词不同物**：本条的**收口 = 出口面**（摘 export / 归并接口）；**判据副本**的收口走 `ADR-0011`（载体账 N→M）。

**落点**：`AGENTS.md` §三（接线约定与行数口径）· `eslint.config.js` 的 `max-lines` 处（依据）· `.codebuddy/commands/架构师改码7步法.md` Step 6（白删信号）· `.codebuddy/commands/ADR守护者.md`（指针）。

## 后果

- ✅ **收益**：巨型文件 / 拆分的裁定有统一判据（不再按行数登记债）；判据从 4 处散落收敛为 1 处本体 ＋ 3 处指针。
- ⚠️ **代价 / 回潮风险**：判定要跑 `refs` ＋ 数导出（取证成本）；「深」可能被误用为**拒绝拆分**的挡箭牌（故第 5 条反滥用）。
- 📌 **违反时的判据**：
  1. 以**行数 / 文件数**为拆分或登记债的理由 ⇒ 违规；
  2. 自称深模块却**答不出"边界外谁在用它"**（或 fan-in 只有域内 / 为零）⇒ 违规（按 `ADR-0003` 处置：接上 / 摘 export / 删）；
  3. 拆 / 并之后**接口宽度没变窄** ⇒ **白删/白拆**（违 `ADR-0003` 的目的关）；
  4. 拿「ADR 说要有 / 不要有门面」当依据 ⇒ 违 `ADR-0004`（先答"它凭什么成立"）。
  ⚠️ **诚实边界**：「窄 / 厚」无机器判据；可达的是**导出数**与 **fan-in**（`node scripts/mv-sync-refs.mjs refs <file>`）⇒ 按 `ADR-0002` 第 6 级给人工判据，**禁硬凑 grep**。
