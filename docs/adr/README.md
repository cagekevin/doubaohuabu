# ADR · 架构判据决议（Architecture Decision Records）

> **一句话**：本目录记录**已裁定的判据与约定** —— 尤其是**推翻了某条既有约定**的那些。
> **为什么要读它**：**既有约定未必是对的，它可能正是我们要消灭的对象**（`架构师改码7步法` 铁律 6）。
> **读债 / 普查 / 想引用任何"仓里一直这么写"之前，先过一遍本文件末尾的索引** —— 免得把已被推翻的旧约定当依据。

## 二 · 什么时候**必须**写一条 ADR（判据）

1. **推翻了一条既有约定**（或推翻了一条旧 ADR）—— **必须写**，否则后人照着旧约定再来一遍；
2. **确立了一条新约定**（含"默认不建闸""该闸不可放宽"这类治理判据）；
3. **用户裁定**（业务性拍板）—— **须先过下表 6 问 ⓿**；
4. **被否决的方案** —— 考虑过但没采纳的方案要留档 + 写明**否决理由**（`状态: 已否决`）。

> **不必写**：一次性操作（改个名、补个类型）、已被现有 ADR 覆盖的重复结论、**只影响一处的边界裁定 / 一次性产品取舍**。

**"写 / 不写"（写 ADR 前必须过这 6 问，即使用户裁定也要能过）**

| # | 问 | 不通过 ⇒ 处置（禁止写 ADR） |
| --- | --- | --- |
| **⓿** | **只影响一处吗？** | 只影响一处（一个组件 / 入口 / 一次性取舍）→ **死日记** → 记 `daily/架构日志/`，**不写 ADR** |
| ① | **它凭什么成立？** | 答不出「凭什么」⇒ 那个约定就是**待消灭的对象**（ADR-0004）；**"仓里一直这么写"不是依据** |
| ② | **能不用 ADR 守吗？**（ROI 判据） | 类型约束 / 结构隔离 / 唯一入口 / 对账测试能让"误用写不出来" ⇒ 去改代码、升 fitness function，ADR 判过期或毕业。**改动半径小且能根治 ⇒ 不许拿 ADR 守** |
| ③ | **有同义 / 近义的现行 ADR 吗？** | 有 ⇒ **必合并**（禁把同一语义抄 N 份买绿灯）；属**判据重复** ⇒ 只钉边界、不合并 |
| ④ | **违反时写得出判据吗？** | 写不出「📌 违反时的判据」⇒ 它是**没有防线**的声明，不许落盘。不能机判 ⇒ 须写明"不能" + 给人工判据（ADR-0002），**禁硬凑假 grep** |
| **⑤** | **写下它之后，下一个 AI 的具体动作会变吗？** | 答不出"我该做什么 / 不该做什么" ⇒ **不写**（记 `daily/架构日志/` 留痕，**不占编号**） |

> 🔴 **答卷人是 AI（逐条答），用户的角色是「决策：同意 / 不同意」** —— 别把"命令跑过了"当成"六问答过了"。
> **流程：AI 逐条答 6 问 → 把 6 问 + 答卷贴进对话给用户看 → 用户决策 → 加 `--user-approved` 落盘**（缺 ⇒ `exit 2` 拒写）。
> 这一步**没有机器防线**，防线是「贴进对话」这个动作本身（`ADR-0002` 第 6 级：诚实声明）。

## 三 · 模板与状态

### 状态枚举（6 态）

| 状态 | 图标 | 含义 | 机器校验（`audit`） |
| --- | --- | --- | --- |
| `草案` | 📝 | 待裁定（`add` 默认 `生效`） | — |
| `生效` | ✅ | 现行判据 | 必须有「📌 违反时的判据」 |
| `已取代` | 🔄 | **被另一条 ADR 取代** | 必须写「被取代于」，且取代方必须写「取代」 |
| `已弃用` | 🗑 | **不再相关，但没有取代者** | **不得**写「被取代于」 |
| `已否决` | ❌ | 考虑过但**没采纳**的方案（留档防重提） | — |
| `已毕业` | 🎓 | 判据已升为 **fitness function** | 必须写「毕业去向」 |

### 文件模板

> **别手写** —— 走 `node scripts/adr.mjs add --title "…" --conclusion "…"`，它会取号、建文件、重生成索引。

```md
# ADR-NNNN · <一句话标题>

- **状态**：草案 ／ 生效 ／ 已取代 ／ 已弃用 ／ 已否决 ／ 已毕业
- **结论**：<一句话，≤120 字 —— 直接进索引表，所以别写成段落>
- **日期**：YYYY-MM-DD
- **裁定人**：用户 ／ 架构师（取证后自定）
- **触发**：<哪个债 / 哪次施工 / 哪条旧约定>
- **取代**：（可选）ADR-XXXX —— 本 ADR 取代了谁
- **被取代于**：（可选）ADR-YYYY —— 谁取代了本 ADR（由 `status --by` 自动写）
- **毕业去向**：（可选）<升到哪个可自动检查的载体 · 文件:行>

## 背景
<旧约定是什么、它当初为什么这么定>

## 判据（它凭什么成立 / 为什么不成立）
<取证：物理红线？类型层？唯一入口？对账测试？—— 答不出就是待消灭的对象>

## 决议
<新约定是什么；落点（文件:行）>

## 后果
- ✅ 收益
- ⚠️ 代价 / 回潮风险
- 📌 违反时的判据（怎么发现"又回去了"）

## Lessons Learned
<**取代别的 ADR 时必填**（`audit` 会校验）：从被取代那条学到什么>
```

### 结论建议写成 Y-statement

> 在 **<上下文>** 下，面对 **<约束>**，我们选择 **<X>** 而否决 **<Y>**，以达成 **<目标>**，接受 **<代价>**。

### 不可变性（**本仓改了一条：修正在先，改主意在后**）

行业原话是「accepted 之后正文冻结」；**本仓修正为**：「冻结」保护的是这条判据的历史，不是这几个字的墓碑 —— 原文**本身写错了**，**修正它才是唯一合理的动作**。

| 情形 | 判据（怎么分） | 动作 |
| --- | --- | --- |
| **修正** | 把原文**按原样执行**会导出**错动作** ⇒ 原文有错 | **回改原文**（就地改）—— 不许只在新文档里打补丁（那是 SSOT 第二份） |
| **改主意** | 原文没写错，只是**决策变了** | **写新 ADR 取代**（旧条留档 + 取代链 + Lessons Learned） |

- **顺序：先问「能不能修」，修不了才写新条 —— 修正 > 改主意。**
- **回改必须留痕**：标日期 + 「原作 X ⇒ 现作 Y + 为什么」。**静默改写才是真正被禁的"改历史"**。
- **头部状态行**（`状态` / `取代` / `被取代于` / `毕业去向`）任何情形都可改。

## 四 · 常用命令

```bash
node scripts/adr.mjs doctor            # Step 1 一键体检（list + audit + hygiene + refs --check + extract-detours --check）
node scripts/adr.mjs list              # 现行判据
node scripts/adr.mjs audit             # 形式一致性
node scripts/adr.mjs index --write     # 重生成本文件末尾索引块（产物，禁手改）
node scripts/adr.mjs refs <NNNN>       # 回改引用面（按「必须回改 / 不动」分三类列全）
node scripts/adr.mjs add --title "…" --conclusion "…" --user-approved
node scripts/adr.mjs status <NNNN> --to 已取代 --by <新编号> --note "…"
```

> ⚠️ **闸绿 ≠ 健康** —— `audit` 只查形式（空壳 / 缺节 / 近义 / 状态自洽），**不查横向一致性**。
> 一上手就全绿，正是要继续查的信号（详见 `.codebuddy/commands/ADR守护者.md`）。
