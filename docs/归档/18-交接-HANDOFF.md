### 3.1 四个我反复踩的坑（写在 `docs/16`，这里再列一次）
1. **持久化形状的真源必须在 `stable/contracts`**（`core` 可 import 它，反之不行）—— 踩过**两次**。⇒ **转写持久化形状前先问"它住哪一层"**。
2. **渲染期不得调 `Date.now()` / `Math.random()`** —— 踩过**三次**。⇒ 一律 `useState(() => …)` 收进 state。
3. **同一个形状不要写两份**（纯 TS 类型的重复，`depcruise` 拦不到）。
4. **"我的期望写错"要当成常态去排查**：本仓的测试多次证明**实现对、期望错**（`formatElapsed(660s)`、`formatClock(-1)`、`Number.isFinite`、`-0`）。**断言前先手算一遍边界**。

### 3.2 一个"当轮就抓到 bug"的机制（值得保留）
我写过一个**幽灵 token 检查**（把 `src/**/*.css` 里所有 `var(--x)` 与 `tokens.css` 的定义对照，见 `docs/16` 里贴的 20 行脚本）。它当轮抓到**两个真问题**：我自己拼错的变量名、以及一个新表里不存在的 token。
⇒ 若谁要长期维护 CSS，**建议把它做成 `npm run check` 的一环**（`var(--不存在的变量)` 在 CSS 里**不报错**，这是唯一会静默失败的地方）。**这只是我的建议，不属于我这条线的交付。**
