# 判据登记表 · 每条判据的真源与副本数

> **本文件只回答一件事：哪件事归谁定、副本有几份。**
> **与 `docs/DATAFLOW.md` 成对使用（禁只看一张）**：DATAFLOW 说「谁经过谁」，本表说「哪件事归谁定」。
> - 只看 DATAFLOW ⇒ 会把「其实已有真源」的判据又抄一份；
> - 只看本表 ⇒ 不知道这条判据挂在哪条链上、该往哪收口。
> **本表是活表**：审计 / 读账时发现「真源挪了 / 载体数变了 / 点名是假的」，**就地改正**（追加不重排）。**失真比没有更糟。**

---

## §0 维护规矩

1. **只登记落点，不放判据正文**（判据正文归 `docs/adr/` 或 `docs/11-架构与契约定稿.md`）。
2. 每行三要素必填：**真源（`文件:行`）· 载体数 N · 跨板块副本落点**。答不出 N ⇒ 说明你没数过载体，**不算登记**。
3. 发现与代码不符 ⇒ **就地改**（并记入轮次文件「探债」段）。
4. 表按**板块**分节；板块划分与 `scripts/arch-index.mjs` 的 `AREAS` 对齐（避免两套编号）。
