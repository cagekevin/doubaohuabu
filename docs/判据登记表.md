# 判据登记表 · 每条判据的真源与副本数

> **唯一职责**：登记**哪件事归谁定、副本有几份** —— **只登记落点，不放判据正文**。
> **与 `docs/DATAFLOW.md` 成对使用（禁只看一张）**：DATAFLOW 说「谁经过谁」，本表说「哪件事归谁定」。
> - 只看 DATAFLOW ⇒ 会把「其实已有真源」的判据又抄一份；
> - 只看本表 ⇒ 不知道这条判据挂在哪条链上、该往哪收口。
> **本表是活表**：发现「真源挪了 / 载体数变了 / 点名是假的」⇒ **就地改正**（追加不重排）。**失真比没有更糟。**

---

## §0 登记规矩

1. **只登记落点，不放判据正文** —— 判据正文归 `docs/adr/`（已裁定）或 `docs/架构与契约定稿.md`（红线 / 契约边界 / 八原则）。
2. **每行三要素必填**：**真源（`文件` + 符号名）· 载体数 N · 跨板块副本落点**。
   ⚠️ **不写行号** —— 行号易漂；用**不易漂移的符号名 / 唯一入口函数名**定位。
   ⚠️ 答不出 N ⇒ 说明你没数过载体，**不算登记**（**口径类判据**无「载体」概念，N 记 `—`）。
3. **只写现状，不写日志**：本表不放**日期 · 债号 · 轮次叙事 · 「收口 / 结清」流水 · 「原来是 X ⇒ 现 Y」**（那归 `daily/架构日志/` 与账本）。**改了就地写新的**，不写「原来是别的」。
   - ✓ 该写：**判据本体** ＋ 让它**可复核**的证据（源锚点 · 为什么这是唯一真源 · 为什么不合并）。
   - ✗ 不该写：`★ <日期> 收口（<债号>）：…` 这类条目 —— 它回答"哪天谁改的"，而本表只回答"**哪件事归谁定**"。
4. 表按**板块**分节；板块划分与 `scripts/arch-index.mjs` 的 `AREAS` 对齐（避免两套编号）。
5. 发现与代码不符 ⇒ **就地改**（过程归轮次文件「探债」段，**不写进本表**）。
