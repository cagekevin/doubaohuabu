## 二、分层与目录

**分层契约**（L0 最底层 ⇒ L6 最上层）：

| 层 | 目录 | 职责（一句话） | 不得做什么 |
|---|---|---|---|
| **L0** | `lib/` · `constants/` · `styles/` | 无状态工具 / 业务常量与文案（SSOT）/ 设计 token | 不得 import 任何上层 |
| **L1** | `stable/` | **冻结契约的代码化**：20 键与值形状、工程 JSON / 快照格式、`img://` 协议、数据归一 | 不得 import 任何上层 |
| **L2** | `core/` | **领域核心**：`model/`（数据形状）· `rules/`（纯规则，全部可单测）· `usecases/`（编排，只返回 `Result`）· `ports/`（**只有类型**） | 不得 import `adapters` / `state` / `ui` / `bootstrap`；不得碰 `window` / `Date.now()` / `Math.random()` / `localStorage` / `setTimeout`；不得 import `react` |
| **L3** | `adapters/` | **端口实现**（唯一接触外部世界）：`host/{electron,mock,shared}` · `site/{doubao,dola,lovart,tapnow,gpt,shared}` · `media` · `storage/local` · `clock` | 不得 import `state` / `ui` / `bootstrap`（**不得写 store**） |
| **L4** | `state/` | store（zustand 5）：`slices/`（按**共享范围**切）+ 控制器（`hostOps` / `accountOps` / …）+ `persist` / `subscriptions` | 不得 import `adapters`（端口由 `bootstrap` 注入）；不得 import `ui` / `bootstrap` |
| **L5** | `ui/` | React 组件：`shell` / `pages` / `canvas` / `nodes`（8 类） / `edges` / `panels` / `common` | 不得 import `adapters`；不得直调 `window.api`（走 `state` 的控制器）。**可**依赖 `state` 与 `core`（`rules` 纯函数 + `model` 类型） |
| **L6** | `bootstrap/` | **唯一的接线处**：`main.tsx`（入口）/ `container.ts`（组装）/ `hydrate.ts`（启动灌入） | — |

> **逐文件清单 / 文件数 / fan-in 的真源 = 文件系统本身（`src/**`）** —— 本文件**不维护清单**（清单只随代码变、不随判据变，必然漂）。
> **依赖方向的真源 = `.dependency-cruiser.cjs`**（机器强制，见 §三）。

### 2.1 样式方案（**CSS 必须标准 + SSOT**）

> **不复用原产物的 CSS** —— 它是**构建产物**（编译结果），不是源码；拿它当真源 = 把「别人的编译结果」当地基。
> **CSS 必须标准**（原生 CSS，第三方库只用其**官方 CSS 变量**），**样式有唯一真源（SSOT）**。

#### 三层结构

```
src/styles/
├── tokens.css      ★ SSOT：设计 token（全部以 CSS 变量定义）
│                     --color-* / --space-* / --radius-* / --font-* / --z-*
├── reset.css       ★ 标准化基础样式（normalize + box-sizing + 字体栈）
└── theme.css       ★ ReactFlow 主题（覆盖官方 --xy-* 变量，见下）
src/ui/**/*.module.css   组件样式（CSS Modules，作用域隔离）
```

#### 关键决策

| 决策 | 内容 | 理由 |
|---|---|---|
| **样式语言** | **原生 CSS + CSS Modules** | 标准、零运行时、Vite 原生支持 |
| **SSOT** | `tokens.css` 的 **CSS 变量是唯一真源** | 组件**禁止硬编码色值 / 间距**，只引用 `var(--color-primary)` |
| **ReactFlow 主题化** | ✅ **用官方 `--xy-*` CSS 变量**（真源 = `@xyflow/react/dist/style.css`） | **这是"标准"做法**；不写 `.react-flow__*` 类名覆写 |
| **不用 Tailwind / CSS-in-JS** | — | Tailwind 把 token 打散进 className（**破坏 SSOT**）；CSS-in-JS 引运行时开销 |
| **不搬原产物 CSS** | — | 它是编译产物，无法作为真源维护 |

#### ReactFlow 标准主题化

```css
/* src/styles/theme.css —— 只用官方 CSS 变量，不碰 .react-flow__* 类名 */
.xy-theme {
  --xy-background-color: var(--color-canvas-bg);
  --xy-background-pattern-color: var(--color-grid);
  --xy-node-border-radius-default: var(--radius-md);
  --xy-edge-stroke-default: var(--color-edge);
  --xy-controls-button-background-color: var(--color-surface);
}
```

```ts
import '@xyflow/react/dist/style.css';   // ① 官方样式
import '@/styles/tokens.css';            // ② SSOT
import '@/styles/theme.css';             // ③ 主题覆盖
```

> 官方样式表仍用 `.react-flow__*` 类名作**选择器**，但我们**只通过 CSS 变量覆盖**，不写类名覆写规则。

#### SSOT 检查（可执行）

- **禁止** `*.module.css` 与 `ui/**` 出现字面量色值（`#xxx` / `rgb(`）
- **字面量只允许出现在** `styles/tokens.css`

> 样式的**唯一契约** = `docs/17-CSS规范.md`（token 四层 · 新样式放哪 · `composes` 规则 · 例外表）。

## 三、依赖规则（**用 dependency-cruiser 强制**）

```
lib / constants          ← 谁都能用，它不依赖谁
      ↓
stable                   ← 只依赖 lib / constants
      ↓
core                     ← 依赖 stable；**不依赖** adapters / state / ui
      ↓
adapters                 ← 依赖 core/ports（实现它）+ stable
      ↓
state                    ← 依赖 core/usecases + core/ports（用注入的 adapter）
      ↓
ui                       ← 依赖 state + core（model 类型 + rules 纯函数）
      ↓
bootstrap                ← 唯一可以 import 全部的地方
```

**三条铁律**：

1. **`core` 不得 import `adapters` / `state` / `ui`** —— 保证领域核心可纯测
2. **`ui` 不得直接调 `window.api`** —— 必须经 `state` → `usecases` → `ports`
3. **`stable` 不得 import 任何上层** —— 冻结契约不可被业务污染

> **`volatile` 在哪？** = `adapters/site/*`。站点改版只动它，`stable` / `core` **零改动** → 回归面最小。

### 3.1 约束范围（**选择性强化，不全局套深模块**）

> **判断依据不是"哪个规则更好"，而是"风险在哪、约束就打在哪"。**

深模块要求**扁平包**（包中不得再含包），而本项目目录是**嵌套**的（`core/` 下再分 `model/ rules/ usecases/ ports/`）。若全局套用「入口点边界」⇒ `adapters → core/ports`、`ui → core/model` **全部非法**，整条依赖链断掉。故**只做选择性强化**：

| 判断 | 结论 |
|---|---|
| 深模块的收益 | **局部的** —— 真正需要强隔离的只有 `adapters/site/*`（volatile）与 `adapters/host/*`（冻结契约）。`core/rules` 之间的深导入**零风险**（纯函数、无状态、无副作用） |
| 全局套用的代价 | **实打实的** —— 强制扁平包 ⇒ 目录形状锁死 + 包数膨胀，**违反 §十一「防止过度设计」** |
| 项目阶段 | 已知形态应用的重写（非绿地）⇒ 认知负担优先 |

**规则的设计意图**（**条数与逐条内容真源 = `.dependency-cruiser.cjs`**，`npm run lint:boundaries`）：

| # | 规则 | 类型 | 说明 |
|---|---|---|---|
| 1 | **层级方向** | 层间 | `ui → state → core → stable → lib/constants`；**禁止反向** |
| 2 | **`ui` 禁 import `adapters/**`** | 层间 | 必须经 `state` → `usecases` → `ports` |
| 3 | **`stable/**` 禁 import 上层** | 层间 | 冻结契约不被业务污染 |
| 4 | **`adapters/site/*` 只允许 `adapters` / `bootstrap` import** | ★ **入口点边界（选择性）** | **volatile 隔离**：外部拿不到站点选择器 |
| 5 | **无环** | 结构 | 禁止依赖环 |

> **为什么用 `dependency-cruiser` 而不是 eslint**：它能**查环**、能表达"层间方向"、能**证明规则真的会咬**（`no-restricted-imports` 三样都做不到）。

**barrel 规则**：**禁止「再导出全部」的巨型 barrel** —— 每层暴露**若干小入口点**（窄接口），不要一个 `index.ts` 把**整层**再导出；**层入口点本身是允许的**（如 `ui/nodes/index.ts` 的 `nodeTypes`）。

> ⚠️ 本条**无机器守卫** —— 靠人工 + 评审。

### 3.2 依赖注入的落点

`bootstrap/container.ts` 是**唯一**知道"用哪个 adapter 实现"的地方：


## 四、端口定义（只开 5 个）

> ★ 端口的**真源 = `src/core/ports/`**；下面的代码块只画**形状**，逐方法以端口文件为准。
> 「只开 5 个」指**顶层端口数量**（`clock` / `host` / `site` / `storage` / `backendPage`）；`HostPort` 内部再按用途切 **8 个子接口**（file / clipboard / project / media / account / license / api + `os`）⇒ **实际接口面 ≈ 12 个** —— 抽象量不小，**别低估**。

### 4.1 `HostPort` —— 宿主能力（按用途切分，不是照抄方法清单）

```ts
export interface HostPort {
  readonly os: 'windows' | 'macos' | 'linux';        // 用 preload 的 process.platform，不读 navigator
  file:    FilePort;      // importFiles / saveFile / loadFile / selectFolder / download*
  clipboard: ClipboardPort; // readClipboardImage / copyText / copyImage / attachImagesToWebview / pasteToWebview / onChanged
  project: ProjectPort;   // activateProjectStorage(sync) / saveSnapshot / saveBackup / logOperation / storageSize
  media:   MediaPort;     // saveImageSync(sync) / saveVideoFromUrl / resolveImageRef / imageFetchDataUrl / captureRect
  account: AccountPort;   // ensureFingerprint / ensurePlainSession / ensureLovartContainer / clearSession / setProxy
  license: LicensePort;   // getMachineCode / getLicenseStatus / activateWithCode / exportMachineCode
  api:     ApiPort;       // apiProvidersList / apiConfig* / apiJob* / apiSetup* / onApiJobEvent
}
```

**为什么切分**：`window.api` 的方法按用途分成 8 组 → 用例只依赖它需要的那一组（**接口隔离**）。`adapters/host/electron` 实现它（**唯一 `window.api` 接触点**），`adapters/host/mock` 提供开发期实现。

### 4.2 `SitePort` —— 站点适配（**最易变**）

```ts
export interface SitePort {
  readonly kind: 'doubao' | 'dola' | 'lovart' | 'tapnow' | 'gpt';
  scan(account: Account, opts: ScanOptions): Promise<ScanResult>;   // 抓取（降级链内部实现）
  send(account: Account, payload: SiteSendPayload): Promise<SendResult>; // 发送（★ 品牌类型，只由 toSitePayload 产出）
  probe(account: Account): Promise<SiteProbe>;                       // 登录态/可用性探测
}
```

> **选择器集中在本 adapter 内**（多级降级、`data-input-engine-*`、`ability_type=17`），**不外泄**。
> 站点改版 → 只改 `adapters/site/<站点>/`，`core` 不动。

### 4.3 `StoragePort` —— 持久化

```ts
export interface StoragePort {
  read<T>(key: LsKey): T | null;
  write<T>(key: LsKey, value: T): void;
  remove(key: LsKey): void;
  // 磁盘（走 HostPort.project）
}
```
> `LsKey` = `stable/contracts/keys.ts` 的**字面量联合**（20 个键）→ **拼错键名编译期就报错**。

### 4.4 `ClockPort` —— 时序（**为了可测**）

```ts
export interface ClockPort {
  now(): number;
  setTimeout(fn: () => void, ms: number): Cancel;
  setInterval(fn: () => void, ms: number): Cancel;
}
```
> 让「生成轮询 3s / 静默 9s / 持久化防抖 600ms / 撤销合并 800ms」**可单测**（用假时钟），不用等真实时间。

## 五、状态分层

> **核心原则：store 的 slices 按「共享范围」切，不按「业务域」切。**

### 5.1 四类状态与归属

| 类 | 判据 | 归属 | 本项目例子 |
|---|---|---|---|
| **① 全局共享** | 跨多个顶层子树 | `state/slices/global.ts` | `activeId`、`projects`、`accounts`、`groups`、`proxyPool`、`apiSetup`、`saveError`、`backendErrors`、`toast` |
| **② 子树共享** | 只在画布子树内 | `state/slices/canvas.ts` | `nodes`、`edges`、`library`、`past`/`future`、`snap`、`fitViewAction` |
| **③ 纯局部** | 单个/相邻组件 | **`useState`** | 面板开合、输入框内容、拖拽中态、右键菜单位置、`splitPresetPicker` |
| **④ 派生** | 能算出来 | **渲染时计算，不入 state** | 过滤视图、可用账号列表、占用空间 |

> **结构判据（违反即违规）**：
> - 同一次业务动作的多个字段 **合并为一个对象**（官方「Group related state」）
> - 能由结果推导的字段 **不入 store**（官方「Avoid redundant state」）
> - 在途 / 保存中标记一类的瞬时态 **派生**，不存 store

### 5.2 三类不该进 store 的东西

1. **能算的**（派生）→ 渲染时算
2. **只在子树内的** → Context 或局部 state
3. **高频变化的** → 绝不进 Context（会全树重渲）；局部 state 或 `useSyncExternalStore` 选择器

### 5.3 slice 规模约束

| 规则 | 判据 |
|---|---|
| **单 slice 建议 ≤ 300 行** | 超了就**再按「共享范围」细分**（如 `global/` → `projects` / `accounts` / `settings`） |
| **单 slice 的 state 字段 ≤ 25 个** | 超了说明混了多个共享范围 |
| **action 只做编排，不做业务** | 业务逻辑必须在 `core/rules` 或 `core/usecases`；slice 里出现"算哈希 / 比较 / 组装提示词" = 违规 |

> ⚠️ 规模约束**无机器守卫**（行数是代理指标：对纯数据/文案表与逻辑文件用同一把尺，会逼出"为拆而拆"）⇒ 由**人工 review 把关**。

## 六、契约边界

> **原则**：`electron/**` **不是绝对冻结** —— **若动后端比动前端便宜，就动后端**。
> 重写的目的是"更好的实现"，不是"自我设限"。为迁就旧后端而在前端堆 workaround，是**把技术债从后端搬到前端**。

| 层 | 能否改 | 说明 |
|---|---|---|
| `electron/**` | ⚠️ **可改，但按成本判据**（见 §6.1） | 默认不动；**改动成本 < 前端绕行成本 ⇒ 改后端** |
| `window.api` 方法 / channel / 形状 | ⚠️ **可加，慎改** | 可**新增**方法/字段；**改已有签名**需评估调用面 |
| **20 个 localStorage 键 + 值形状** | ❌ **不能**（除 §6.2 例外） | 值形状冻结；**加新键可以，改老键不行** |
| 磁盘布局 / 快照格式 / `img://` | ❌ **不能** | 老用户数据在磁盘上 |
| `core/**` `state/**` `ui/**` `lib/**` `constants/**` | ✅ 可改 | 重写范围 |
| `adapters/site/**` | ✅ 可改（**且预期会频繁改**） | 站点改版就打这里 |
| `adapters/host/mock` | ✅ 可改 | 开发期用 |

> **老数据口径**：20 键与磁盘格式**值形状冻结**；但**不为旧版本数据兼容**（不存在旧版本数据）⇒ `stable/migrations` 只留两条数据归一（**无启动迁移**），机制位置见 §八。

### 6.1 判据：什么时候「改后端」比「前端绕行」便宜

| 判据 | 例（本项目已知） | 结论 |
|---|---|---|
| **后端改一行，前端省几十上百行** | `lovartChromeEval` 未暴露 ⇒ 前端 Chrome 采集通道**整条死掉** | **改后端**（暴露它）比前端绕行便宜 |
| **后端能力缺失导致前端无法实现** | `open-lovart-chrome` 有 handler 但 preload 没暴露 | **改后端**（暴露） |
| **契约本身有缺陷，前端只能 workaround** | `saveImageSync` / `activateProjectStorage` 用 `sendSync`（阻塞主进程） | 评估：改异步要动调用面；**若调用频次低则不动** |
| **站点改版** | 选择器失效 | **改前端**（`adapters/site`），与后端无关 |
| **性能问题在前端** | 画布重渲染 | **改前端** |

**改后端的约束（3 条硬性）**：
1. **不得破坏已有方法签名**（只能新增/重载）
2. **不得改变数据格式**（localStorage / 磁盘 / 协议）
3. **改动必须回写文档**（`docs/05-配置契约层.md` 同步更新）

### 6.2 数据格式的**唯一例外**

若某项数据格式本身是**设计缺陷**（如 base64 内联导致配额超限），可以改 —— 但必须：

- 写入时用**新格式** + 记版本号

## 六·五、职责归位（**八原则**）

> **越权 = 一个模块做了不属于它的职责。** 依赖方向一旦被破坏，架构就退化成"什么都能调什么"。

### 原则 1 · 谁拥有状态，谁负责写

| 谁 | 能写 store? | 说明 |
|---|---|---|
| `state/**` | ✅ **唯一** | store 只能被自己改 |
| `core/usecases` | ❌ **绝不能** | 依赖方向 `state → usecases` ⇒ 反向调用 = 环 |
| `adapters/**` | ❌ **绝不能** | 同上 |
| `ui/**` | ⚠️ 只经 `state` 暴露的 action | 不得 `useStore.setState()` 直改 |

**契约（★ 必须写进代码注释）**：

```ts
// core/usecases 的返回值契约 —— 唯一的交付方式
type Result<T> =
  | { ok: true;  value: T }
  | { ok: false; reason: FailureKind; message: string };

// ✅ 正确：usecase 返回结果，由 state 层写入
const r = await generateImage(deps, input);
if (r.ok) store.attachImageResultToNode(nodeId, r.value);

// ❌ 越权：usecase 内部直接改 store
useStore.setState({ nodes: [...] });   // 禁止
```

### 原则 2 · 事件推送只能"订阅转发"，不能"写入"

主进程推送（`onApiJobEvent` / `onDolaMedia` / `onClipboardImageChanged` / `onLovartFetch*`）的归属：

```
adapters/host/electron  →  暴露 subscribeXxx(cb): () => void   （只有订阅）
        ↓
state 层  →  订阅 + 写入 store                                  （唯一写入点）
```

**adapter 只做转发，不做解释、不做存储。**

### 原则 3 · 端口只有类型，实现只在 adapters

| 层 | 内容 |
|---|---|
| `core/ports/**` | **只有类型**（interface / type），**零实现** |
| `adapters/**` | **唯一实现处** |

> 运行时常量（如扫描协议枚举）住 `core/rules`，端口文件只 `import type` 转发。

### 原则 4 · 纯的归 core，脏的归 adapters

**前半（纯归 core）**：`core/**` **不得**接触：`window` / `document` / `Date.now()` / `Math.random()` / `localStorage` / `setTimeout`
→ 时间与随机性一律经 `ClockPort` 注入；其余经各自端口。

**后半（脏归 adapters）**：**宿主能力的实现只许住 `adapters/**`**；`lib/**` 是 L0 **无状态工具**，**不得**碰**宿主**（`window.api` / electron / 文件系统 / 系统剪贴板 …）。
**Web 标准能力**（`canvas` / `Selection` / `contenteditable` / `AudioContext` …）的工具归**消费它的层**：只被 `ui` 用 ⇒ 住 `ui/`（`ui/lib/`）；**被 ≥2 层共用** ⇒ 才留 `lib`（那是唯一合法位置）。
判据一句话：**碰的是「宿主能力」还是「Web 标准能力」？** 宿主 ⇒ `adapters`；Web ⇒ 归**消费层**（共用才留 `lib`）。

> ⚠️ **`lib` 现存的唯一 Web 标准能力工具**：`lib/image.ts`（`createCanvas` / `loadImage` / `drawMaskEffect` …）——
> **被 `ui` 与 `adapters/media` 同时依赖** ⇒ 移 `adapters` 撞铁律 2（`ui` 不得 import `adapters`）、
> 移 `ui` 会让 `adapters` 撞「不得 import `ui`」⇒ **只能留 `lib`**。
> （只被 `ui` 用的那些 Web 工具住 `ui/lib/`：`videoPoster` · `compressCover` · `editorText` · `selection` · `chime` 的播放部分。）

> ⚠️ **守卫现状**：前半由 eslint `no-restricted-globals/properties`（`src/core/**`）承载；
> **后半无机器守卫**（depcruise 看不见裸引用，eslint 选择器只覆盖 `core/**`）⇒ 靠**归属 + 人工**。
> **不为它建闸**的理由：那会变成"贴在 `lib` 每个文件上的白名单"，而**把实现放进该在的层**本来就够
> —— 结构上收口 > 事后报红（§六·六 手段优先级）。

### 原则 5 · 文案 / 常量 / 阈值有唯一真源（SSOT）

| 内容 | 唯一真源 | 谁不能重复定义 |
|---|---|---|
| UI 文案（普通展示文案） | `constants/text.ts` | `state` / `core` / `ui` 都不得硬编码 |
| **失败 label / 错误横幅映射**（`FAIL_LABEL` / `BACKEND_ERROR_LABEL`） | `constants/failure.ts` | 同左；⛔ `text.ts` **不得**再导出这两张表（与 `constants/index.ts` 的 `export *` 重名 ⇒ TS 静默丢名）；消费方走 `@/constants` 或 `@/constants/failure` |
| 业务常量（网格 20 / 超时 / 阈值） | `constants/` | 各处不得写魔法数 |
| 设计 token（颜色 / 间距 / 圆角） | `styles/tokens.css`（CSS 变量） | 组件不得写硬编码色值 |
| 20 个 localStorage 键 | `stable/contracts/keys.ts` | 各处不得写字符串字面量 |
| 模型表 / 风格预设 | `constants/models.ts` / `constants/stylePresets.ts` | — |

> 错误类型 → 文案的**映射表**归 `constants/failure.ts`（`FAIL_LABEL` / `BACKEND_ERROR_LABEL`）；store **只存"当前有哪些错误"**。

### 原则 6 · 错误透传（**生产者报错，消费者只转发**）

> **铁律**：**错误只能由生产者产生，消费者只能转发。缺错误 ⇒ 去生产者那里补，不得在前端造。错误不可被掩盖。**

| 角色 | 谁 | 能做什么 |
|---|---|---|
| **生产者** | `adapters/**`、`core/rules/**` | **产生**错误（`{ok:false, reason, message}`）；`message` 必须是**原始错误原文** |
| **消费者** | `core/usecases`、`state`、`ui` | **只能转发**（可附定位信息），**不得改写 / 不得吞掉 / 不得编造** |

**四条禁止**：

| # | 禁止 | 说明 |
|---|---|---|
| 1 | **禁止吞错** | `catch {}` / `catch (e) {}` 空实现 = 掩盖真相 |
| 2 | **禁止改写 message** | `message` 必须是原始错误（`e.message` / 后端返回原文）。"友好文案"属**展示层**：在 `constants/failure.ts` 里按 `reason` 映射，**不覆盖原文** |
| 3 | **禁止编造 reason** | 分类表没有的错误 → 归 `unknown` **但必须保留原始 message**，并**去 `core/rules/failure.ts` 补分类**（修在源头） |
| 4 | **禁止消费者兜底造错** | usecase 不得因"怕 UI 崩"就返回自造的错误对象 |

```ts
// ❌ 消费者造错（掩盖真相）
catch (e) { return { ok: false, reason: 'unknown', message: '操作失败，请重试' }; }

// ✅ 转发（保留原文）
catch (e) {
  return { ok: false, reason: classifyFailure(e), message: e instanceof Error ? e.message : String(e) };
}
```

**与「成本优先」的联动**：批量宿主调用「一抛错 ⇒ **整批失败**」是**生产者（主进程）该修的** —— 应返回 `{ok:false, error}` 而非抛异常。按 §6.1 判据，**改后端**比前端逐处 `try/catch` 便宜。

**可执行检查**（载体 = eslint，`npm run lint`）：
- 空 `catch {}` ⇒ 标准规则 `no-empty`，**必须 0 命中**。本仓**不设**"标个理由就放行"的出口（那种出口无法校验理由 ⇒ 形同虚设）；修法只有一条：**去处理它**。
- `core/usecases/**` 里不得出现 `message:` **字面量**（只能来自 `e.message` 或上游 Result）
- 错误文案映射**只能**在 `constants/failure.ts`

### 原则 7 · 测试边界（**只测纯逻辑，不测 UI**）

> **铁律**：**测试只覆盖纯逻辑；UI 不写组件测试。避免"假守卫"。**

| 层 | 测不测 | 内容 |
|---|---|---|
| `core/rules/**` | ✅ **必测** | 去重阈值、环检测、提示词幂等、失败分类、指纹比较 |
| `core/usecases/**` | ✅ **必测**（注入 mock adapter） | 编排、**错误透传**、状态机、重试/换号决策 |
| `stable/migrations/**` | ✅ **必测** | 数据归一（`08` W2 / W14） |
| `state/**` | ⚠️ 只测 slice 的**纯 reducer** 部分 | — |
| `adapters/**` | ❌ 不测实现细节 | 它是外部世界的薄封装，测它 = 测别人 |
| `ui/**` | ❌ **不写组件测试** | **会产生假守卫** |

**为什么 UI 测试是"假守卫"**
1. 组件测试**通过 ≠ 功能正确**（测的是"渲染出了什么"，不是"用户能不能用"）
2. UI 变化频繁 ⇒ 维护成本高、**价值低**
3. 更糟：它给人**"有测试保护"的错觉**，掩盖真正的行为缺陷

**UI 怎么验** ⇒ **端到端冒烟**（`08` W15，Playwright）：测**真实用户路径**，不测组件内部。

**可执行检查**
- 测试文件只允许出现在 `core/**/tests/`、`stable/**/tests/`
- `ui/**` 下不得有 `*.test.tsx` / `*.spec.tsx`

### 原则 8 · 三振出局（Rule of Three）—— **同一段代码 >2 次必须抽出**

> **铁律**：同一段代码出现 **>2 次**（即第 3 次出现时）⇒ **必须抽出共享实现**。
> 不是"看着像就抽"（那会导致过度抽象），而是**第 3 次出现即触发**。

**抽到哪（按性质）**

| 重复内容 | 抽到 |
|---|---|
| **UI 交互模式**（弹窗遮罩点击关闭 / X 关闭 / ESC 关闭） | `ui/common/` 共享组件（**复合组件**，见 §9.4 组合模式） |
| 纯逻辑（计算 / 转换 / 校验） | `core/rules/` |
| 通用工具 | `lib/` |
| 常量 / 文案 | `constants/`（SSOT，原则 5） |
| 宿主调用模式 | `adapters/` |

> 界面统一的**总原则**「能一种的别搞两种」（同一形态收成一份）住 `AGENTS.md` §五，本文件不复制。

**与原则 5（SSOT）的分工**
- 原则 5 管**数据**的唯一真源（文案 / 常量 / token）
- 原则 8 管**代码**的唯一实现（交互模式 / 逻辑 / 组件）

**为什么必须写死"第 3 次"**：不定量的话，要么过度抽象（第 2 次就抽，抽象错方向），要么放任重复。

**可执行检查**
- `ui/common/` **必须**存在：`Modal` / `ContextMenu` / `ToastHost` / `ErrorBanner` / `EmptyState`
- `'Escape'` 字面量**只允许**出现在 `ui/common/`（弹窗/菜单键盘处理）；其它目录出现即说明手写重复
- `aria-modal` / `role="dialog"` 只允许出现在 `ui/common/`
- PR 审查项：新增代码若与既有实现**第 3 次重复**，必须先抽再合

## 六·六、结构约束（**让"写错结构"编译不过**）

> **手段优先级**（高→低）：**结构上不可能** ＞ **类型层** ＞ **唯一入口** ＞ **对账测试** ＞ 文档留痕 ＞ 机器闸。
> **本节只收"能落在类型上的约束"** —— 闸与 ADR **不进本节**（它们是最低两档，且会漂）。
> 判据两条：**① 写错能不能编译不过？② 第二份真相有没有地方可写？**

**已成立的基线（不用重复设计）**：`window.api` **不在全局类型里** —— `adapters/host/electron/window-api.d.ts` 只 `export interface HostApi`（无 `declare global`），全仓唯一 import 者是 `adapters/host/electron/host-api.ts`，且 `tsconfig.include` 只有 `src`。
⇒ 除 `adapters/host/electron` 外，任何层写 `window.api.X` **编译不过**。

### M1 · 品牌类型 + 唯一构造器（治「同名两义」）

```ts
// core/rules/payload.ts —— 跨进程报文：**手写不出来的类型**
declare const WIRE: unique symbol;
export interface WirePayload { readonly [WIRE]: true; content: { text: string; images: unknown[]; params: Record<string, unknown> } }
export function buildVideoPayload(...): WirePayload        // ★ 唯一构造器

// core/ports/site.port.ts —— 站点入参：**只能由 toSitePayload 产出**
declare const SITE: unique symbol;
export interface SiteSendPayload { readonly [SITE]: true; text: string; images: readonly string[]; params: Record<string, unknown> }
export function toSitePayload(w: WirePayload): SiteSendPayload   // 放在 core/rules

// 契约：SitePort.send 只收 SiteSendPayload
send(account: Account, payload: SiteSendPayload): Promise<Result<SendResult>>
```

⇒ **把 `WirePayload` 直接传给 `send` 编译不过**；「两个同名接口」这件事**失去意义**（名字不再承载语义，品牌才承载）。

### M2 · 阶段即类型（治「顺序错」）

```ts
prepare(p: WirePayload): PreparedSession                    // 取租约 / 取页 / 组装
attach(s: PreparedSession, images): Promise<AttachedSession> // ★ 只接受 PreparedSession
fire(s: AttachedSession): Promise<FiredSession>              // ★ 只接受 AttachedSession
```

⇒ 「没填文本就点发送」「没附图就点发送」这类**跳步/换序编译不过**。

### M3 · 唯一所有者 + 私有构造（治「第二份状态」）

- 跨组件的可变状态**只**能是 `state/slices/**` 的字段；跨阶段的会话态收成**一个值对象**（如 `SendSession`）。
- 该类型的**构造函数只在 `state/**` 内可用**；`ui/**` 拿到的是 `ReadonlySendSession`。
⇒ `ui` 里 `new Map()` / `new Set()` 自己攒一张表 —— **类型上不成立**（没有那种形状可造）。

### M4 · 作用域即配对（治「忘了收尾 / 忘了写回」）

**已有先例**：`withBackendPage`（占号 → 备页 → 跑 → **必释放**）· `withInputLock`（加锁 → 跑 → 必解锁）。
**推广**：凡"读一份表 → 跑一段 → 必须写回"的东西一律给成 `withXxx(...)`（如去重表的读/写回）。
⇒ **不写 `with` 就拿不到那份表** ⇒ 「忘了写回 / 忘了释放」在结构上发生不了。

### M5 · 投影即「有生产者才有字段」（治「落了没人调」）

UI 只允许从 **state 暴露的投影**读（`useNodeTimer(id)` 这类 hook）。投影字段由**生产者**定义：
⇒ 某字段**没有生产者**时，那个 hook/字段**不存在** ⇒ UI **写不出来**。
「判据 B5」由此**从纪律上升为类型约束**。

### M6 · 注册表不导出（治「模块级第二份表」）

跨组件注册表（租约 / webview / 快照回调槽）**只**由端口实现内部持有：
`createBackendPage()` 返回**方法对象**，**表本身不导出** ⇒ 类上**没有第二个地方**能持有同一份表。

### 本节管不到的三件（**必须承认，别假装**）

| 管不到 | 为什么 | 唯一办法 |
|---|---|---|
| 运行时 `await` 交错 | 类型不表达执行序（M2 只保证"调用顺序的类型对"） | **当场跑一次** |
| `as` 逃生口 | TS 固有，杀不掉 | 让 `as` **不必要**（M1 / M3 就是干这个） |
| 语义是否与源等价 | 类型不表达行为 | **当场跑一次** + 纯层单测 |

### 归属规则（**落点怎么定**，不按文件好看，按生命周期）

| 判据 | 落点 |
|---|---|
| 跨进程能力 | `core/ports/**`（只类型）· `adapters/host/electron`（唯一实现） |
| 跨组件共享的状态 | `state/slices/**`（**唯一写点**） |
| 页面级资源（租约 / 注册表 / 就绪标记 / 快照槽） | `adapters`（端口实现内部，**表不导出**） |
| 页内交互与 DOM | `adapters/site/<site>` |
| 纯判据（顺序 / 匹配 / 阈值 / 格式化） | `core/rules/**` |
| 循环 + 落 store | `state/**` |
| 订阅 | `state/subscriptions.ts`（**唯一注册点**） |
| DOM 引用与纯展示态（折叠 / 开合 / 量高） | `ui/**` |
| 源的对外能力位但**源内 0 消费** | **不给入口** |

### 9.1 机器强制（**优先级最高**）

| 手段 | 作用 | 备注 |

| **`<StrictMode>`** | 官方原话："**We strongly recommend using Strict Mode alongside React's ESLint plugin**"。会**双调用**渲染与 Effect → 暴露副作用 bug | 我们大量轮询/订阅/持久化，**不启用必漏 bug** |

### 9.2 官方「Rules of React」9 条（逐条对照）

| # | 规则 | 落地 |
|---|---|---|
| 1 | Components must be **idempotent** | 同 props/state/context → 同输出；**渲染中不得改外部变量** |
| 2 | Side effects **outside of render** | 副作用只进事件处理或 Effect |
| 3 | **Props and state are immutable** | 不可变更新；`structuredClone` 只用于快照 |
| 4 | **Return values / args to Hooks are immutable** | 传给 Hook 的值不再改 |
| 5 | **Values immutable after passed to JSX** | 改动要放在 JSX 创建**之前** |
| 6 | **Never call component functions directly** | 组件只在 JSX 里用 |
| 7 | **Never pass hooks as regular values** | Hook 只在组件内调用 |
| 8 | **Only call Hooks at the top level** | 不在循环/条件/嵌套函数里调 |
| 9 | **Only call Hooks from React functions** | 不在普通 JS 函数里调 |

> **渲染期禁 `Date.now()` / `Math.random()`**（收进 `useState(() => …)`）—— 由 `react-hooks/purity` 拦。

### 9.3 官方「Thinking in React」5 步（**实施顺序**）

| 步 | 内容 | 本项目落地 |
|---|---|---|
| **1** | **拆组件层次** | 三栏 + 画布 + 8 类节点 + 面板的层次图（`ui/` 目录设计） |
| **2** | **先做静态版**（只用 props，**不用 state**） | **先渲染静态画布**（假数据），再加交互 |
| **3** | **找"最小但完整"的 state 表示** | 官方**三问**：① 会变吗？② 是 props 传入吗？③ **能算出来吗？** → 能算的**不是 state** |
| **4** | **state 该放哪** | 找**最近的共同父组件**；找不到就**新建一个专门持有的组件** |
| **5** | **加反向数据流** | 父持有 state，把 `setXxx` 传下去当回调 |

> ⚠️ **Step 2 是纪律**：先静态、后交互。"边写边加交互"会让组件失控膨胀。
