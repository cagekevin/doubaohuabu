## 0 一句话

源里**唯一**把「报文」真正送进后台页的通道是 `_Component43.jsx`（3303 行）通过 `useImperativeHandle`
暴露的 `sendPayload`。本仓用 `SitePort.send`（一条**更简单**的路：附图 → 贴文本 → **点发送** → 轮询出片）
替代了它 —— 本文件把**两者差在哪**逐件列清，并给出可分片的落地顺序。

**它挡着谁**（都是 `docs/13` 的未落项，**同因**）：
`account-send-btn`（恒禁用）· `account-feedback` 的生命周期（4s 自动清）· `account-feedback-close`（✕）·
`timer-inline` · 换号重发 · **出片归属**（新视频连回节点）· `runParamScript`（参数同步）· CDP 图片回流。

## 4 风险与前置

1. **无运行时验证**（要真账号 + 真后台页）。⇒ 每片的自证只能靠「**逐字对源 + 纯层单测**」，
   端到端**必须如实标注"未验"**（本仓既有惯例）。
2. **`SendResult` 要扩容**：源把 `{imagesAttached, imagesTotal, imagesOk, autoClicked, precheck, fillOnly}`
   放在返回里，账号节点据此拼摘要（`OL.jsx:342-357`）。本仓 `SendResult = {sessionId, endReason, results}`
   —— **不是跨进程契约**（`SendPayload` 才是），扩容只动 `core/ports/site.port.ts` 一处，风险可控。
3. **租约差异（已知）**：源复用发送时的租约做 180s 监测；本仓监测**自申请**一条
   （`state/sendWatch.ts` 头注已留痕）。片 4 要在这条差异上继续走。
4. **`wt`（参数脚本）的规模未知**：它会切模式 / 点入口 / 逐项核对 —— **待读**；若它依赖别的未落件，
   片 1 就要往后排。
5. **本仓 `READ_INPUT_SCRIPT` / `DEEP_QUERY_SCRIPT` 是简化版**（只回 `has`/`text`，不回源版的
   `sigs`/`count`/`inputTag`/`edCount`）⇒ 片 2 的"接线"**不是接线，是补全**（如实标注）。

## 5 已落的刀 & 下一步

### 5.1 已落：**片 0 = Phase 1 文本填入**（2026-10-12，**它其实是真 bug**）

探路时发现：`send` **从不把 `payload.text` 写进输入框**（`payload.text` 只被用来算 `sessionId`；
`pasteToWebview` = `wc.paste()` 贴的是**系统剪贴板**）⇒ 发出去的是剪贴板里的旧内容。
修法**不是新写**：`analyze` 的提问链（`MD` / 原 Phase 1 的同一段）**一直是做对的**
⇒ 抽成 `adapters/site/doubao/fillText`，**两边共用一份**（判据 C1），并把源 3a 的**文本那一档**
当闸（`autoSend` 且内容没进输入框 ⇒ 不点发送，`reason: 'precheck-fail'`）。
⇒ 片 2 的**文本半**随之完成（`Ql` 本仓早已是 `READ_INPUT_STATE_SCRIPT`，无需再移植）。

### 5.3 已落：**片 3 = 仅填入 + 账号节点接线**（2026-10-12）

账号节点那颗按钮**此前恒禁用**（用户根本用不了这个节点 —— 它的全部语义就是「填入」）。
本轮把它接通：`accountOps.sendAccountNode`（守卫 → 报文 → 租约 → `site.send`）+
`site.send` 尊重 `payload.autoSend`（关 ⇒ **只填不点**，返回 `endReason:'filled-only'`）+
反馈条三档 + 4s 自动清 + `err` 的 ✕（`clearNodeSendState` 由此有了第一个消费者）。

**★ 顺带挖出并修掉一处真 bug（比预想更深）**：`SitePort.send` 收的是**扁平形态**
（`text`/`images`/`params`/`autoSend`/`source`），而 `state/batchSend` 把 `prepare` 产出的
**跨进程报文**（字段全在 `content` 下）直接 `as SendPayload` 传了下去 ⇒ 适配器读到的
`payload.text` / `payload.images` **恒为 `undefined`**（`payload.images.length` 直接**抛**）。
`usecases/generate` 早就有一份私有组装器 `toSitePayload`（它是对的），而 `batchSend` 没走它。
⇒ 把组装器**提升**到 `core/rules/payload.toSitePayload`（三个调用方共用，判据 C1），
并顺手把「有意宽」的 `content.images`（`string[]` 或 `{label,dataUrl}[]`）**归一成 `string[]`**
（端口声明与适配器期望的形状）。

### 5.2 建议下一刀：**片 2b = 3a 的图数 / 图序**（或片 4 = 发送后监测）
