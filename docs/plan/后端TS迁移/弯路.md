## 预判（开工前已登记 —— 均来自本仓实证或本次调研，用于提前避坑）

### W1 · 拿 `git checkout` 当回退手段 ⇒ 丢未提交的工作
- 情境：改坏一个文件想恢复。
- 错路：`git checkout -- <file>` —— 本仓 HEAD 长期落后于工作树，已实证**丢过未提交改动**（`daily/架构日志/03-usecases-2026-10-11.md` 的「事故与恢复」：丢了 `skipKeys` 机制与守卫，靠逐条重建）。
- 正路：写盘脚本**自备份**到 `.migration-backup/<ts>/` 并打印回退命令。
- 判据：本仓工作树**长期大量未提交** ⇒ git 不是安全网。

### W2 · 为让红字消失而放宽 tsconfig ⇒ 产出假 TS
- 错路：`strict: false` / 关 `noUncheckedIndexedAccess` / 加 `skipLibCheck` 之外的大开关来"过闸"。
- 正路：G1 与 `src` 逐项同严；红线 S1-5 禁止放宽；红字就是工单。
- 判据：放宽配置把「未收窄」藏起来，比红字危险 —— 正是本任务要消灭的形态。

### W3 · 照注释／文档抄签名 ⇒ 契约失配
- 情境：给 `preload` / handler 定类型时，手边有注释和文档。
- 错路：照文档写签名。实证代价：剪贴板三 bug（传字符串不传 `{dataUrl,label}` · 漏 `webContentsId` · 无视 `{ok:false}`）· `ApiJobLite.id` vs 后端 `jobId`（所有任务塌成一条）· `size` vs `bytes`（恒 0）· `pickStorage` 从不传 payload（迁移永不发生）—— 均在 `src/core/ports/host.port.ts` 留痕。
- 正路：**回源 handler 取证**（读 `main.js` 的实际 `return`），再定类型。
- 判据：B 级证据（注释／文档）只能提假设，不能下结论。

### W4 · 保留 `module.exports` ⇒ 跨文件类型流断裂
- 错路：`.ts` 里继续 `module.exports = {…}` 图省事。
- 正路：模块边界改 ESM `import`/`export`（tsc 仍发 CJS，运行时不变）—— **用 `codemod-boundary.mjs` 改，不手改**：机械面（顶层 `require`/`module.exports`）自动完成，**模糊形态进拒绝清单**（函数内/动态 `require` · `module.exports = fn`），默认 dry ＋ `--write`。⛔ 手改**容易漏一个导出**（漏了 ⇒ 运行期断、编译期不报）。
- 判据：① `module.exports` 在 TS 里是 `any` ⇒ 消费方拿不到类型 ⇒ 转换的核心价值归零；② 机械活**脚本化的收益 = 不会漏**（见 W19）。

### W5 · 把 guest 世界脚本当普通模块转 ⇒ 注入链断
- 错路：给 `dola-duration-main.js` 加 `import` 并编译成模块。
- 正路：它维持 `.js`，由 `build-electron.mjs` 原样拷进 `dist-electron/`。
- 判据：它被 `fs.readFileSync` 读文本后注入 guest 主世界（`main.js` 的 `inject-dola-duration-main`），**不能 `require`**。

### W6 · 严格度晚开 ⇒ 已转文件成片回炉
- 情境：转了几批后觉得「某个旗太吵」，或一开始只开 `strict`、后来才补 `strictTypeChecked` / `exactOptionalPropertyTypes` / `noUncheckedIndexedAccess`。
- 错路：先松后紧（每加一个旗，此前转好的文件全部重新变红 ⇒ 成片回炉）；或更糟——**先松后就再也不紧了**（"反正现在绿的"）。
- 正路：**B0-b 一次锁死满载档**（计划 §4 S0）；关旗/降档 ＝ 改 `README.md` ＋ 本条 ＋ 留痕理由，**不静默**。
- 判据：严格度是**一次性**决定（见计划 P6）；而闸接线相反 —— **B0-b 就接**（`allowJs` passthrough 保证当天绿，之后随转换自动变严）。

### W7 · 把"满载档"当成写完就绿，不实测旗组合 ⇒ 误判为代码问题转而降档
- 情境：配好 tsconfig 直接开转。若某个**旗组合本身不成立**（疑点：`module: node16` ＋ `verbatimModuleSyntax` 在 `"type": "commonjs"` 目录下 ESM 语法的许可；`erasableSyntaxOnly` 与产物；`strictTypeChecked` 的 type-aware 挂载），会**当天全红**。
- 错路：① 以为"全红 = 代码太差"⇒ 降档（W6）；② 或者先写全配置，转到第一个文件才发现要改旗 ⇒ 已转文件回炉。
- 正路：**B0-a 试红 spike 前置** —— 最小样例（1 `.ts` ＋ 1 `.js`）逐项实测计划 §4 S0-6 的六项；**再拿 64 行的 `api/redact.js` 真转一遍量代价**（防"转到第 20 个才发现每行都要守卫"）。
- 判据：配置的成立性**只能实测**（计划 S0-6）＋ **技术性替代可自行采用、真降档必须用户拍板**；spike 排在任何转换之前 ⇒ 最坏只改几行配置。

### W8 · 混合期用 `export default` ⇒ 运行期断而编译期不报
- 情境：转换一个「单函数导出」的模块（`module.exports = fn`）。
- 错路：顺手写成 `export default fn`。tsc 的 CJS 产出是 `exports.default = fn`，**未转的 `.js` 用 `require()` 拿到的是 `{default: fn}`** ⇒ 调用处 `fn()` 崩（`is not a function`），而 tsc/eslint 全绿。
- 正路：**统一命名导出**（`export function` / `export const`）；`export =` 也不可用（被 `verbatimModuleSyntax` 禁）。
- 判据：混合期有**两种消费者**（`require` 与 `import`），只有命名导出对两者都成立（计划 §7.4）。

### W9 · 把函数内 `require` 改成顶层 `import` ⇒ 循环依赖下加载时机变化
- 情境：某个模块**故意**在函数内 `require`（懒加载，躲循环依赖 / 延迟到用时）。
- 错路：统一改成顶层 `import`（`import` 会**提升**到模块求值前）⇒ 环上的模块拿到半初始化的导出 ⇒ 运行期怪异错误（且只在冷启动那条路径上偶发）。
- 正路：函数内 `require` **保留原样** ＋ 注释理由 ＋ eslint 局部放行；转换前先用 `depcruise` 把环列出来（计划 §7.4）。
- 判据：模块加载**时机**是行为的一部分，不只是语法形态。

### W10 · 去掉 eslint 的 `electron/**` 顶层 ignore ⇒ 27 个未转 `.js` 被通用 TS 规则扫红
- 情境：B0-b 给 electron 加 lint 块，顺手把顶层 `ignores: ['electron/**']` 删了。
- 错路：删掉后 27 个 `.js` 落到 `tseslint.configs.recommended` ⇒ `no-require-imports` / `no-unused-vars` 等**成片红** ⇒ 误判为"electron 代码太差"，进而降档。
- 正路：electron 块**只匹配 `electron/**/*.ts`**，并**保留 `electron/**/*.js` 的 ignore**（注释写「未转 passthrough」）。
- 判据：**接闸当天必须绿**（计划 S0-5 / §7.2）；接线红 ≠ 代码差，先怀疑配置。

### W11 · 把 `allowJs` passthrough 当成"零改动"
- 情境：以为未转 `.js` 只是被搬运。
- 错路：不核对产物。tsc 对 `.js` 输入会按其 `target`/`module` 处理（可能重排语法），若产物与源有差异，**今天的运行期行为可能已经变了**。
- 正路：B0-a 里 diff 三个 `.js` 的源/产物；有差异 ⇒ 记日志 ＋ B3/B4 逐个核对。
- 判据：passthrough 是**过桥**，不是"不变"（计划 §6 S0-6 末行）。

### W12 · 产物放到仓库根 ⇒ 被判 ESM ＋ 找不到 `ws`
- 情境：为"与原 `electron/` 目录平级、省事"，把产物定在 `<仓库根>/dist-electron/`。
- 错路：两处**同时**炸（都有实证）：① 根 `package.json` 是 `"type": "module"`（最近的 package.json 决定模块类型）⇒ 产物被判 ESM ⇒ `require is not defined` —— 这正是 `electron/package.json` 注释里记的踩坑；② `electron/chrome-cdp.js` 有 `require('ws')`，而 `ws` 装在 **`electron/node_modules`** ⇒ 从仓库根下的产物往上走找不到 ⇒ `Cannot find module 'ws'`。
- 正路：**产物住 `electron/dist/`**（父链上是 `electron/package.json`=commonjs ＋ `electron/node_modules`）；代价 ＝ `main` 里 `../dist` 的引用同批改 `app.getAppPath()`（否则白屏）。**并同时 `exclude` 掉 `node_modules`/`dist`/guest 脚本**（否则 tsc 把自己的产物与 ws 当源码编译 ⇒ 自噬）。
- 判据：产物位置由**三条外部事实**决定（package.json 的 `type` · `ws` 的安装位置 · 相对路径引用），不是"放哪好看"（计划 §4 D-1…D-4）。

### W13 · 顶层 `require` 的顺序也是行为（`import` 会提升）
- 情境：把 `main.js` 顶部的 `require('./license')` 等改成 `import`。
- 错路：以为只是语法形态变化。`import` 的求值时机被提到 import 语句之前、且**你再也不能把某个模块挪到后面**——而 `main.js` 第 20-21 行才 `app.setPath('userData', …)`（那段注释正是"数据散落三处"的事故记录）。任何**顶层**读 `app.getPath('userData')`/写 `fs`/调 `init*` 自注册的模块，顺序一变就可能静默换目录。
- 正路：B0-a 先出**顶层副作用清单**；命中者**该 `require` 保留原样**（或同批挪位 —— 属逻辑改动，须留痕）。转换任何模块前对照三清单（计划 §7 I-1）。
- 判据：模块**求值拓扑**是行为的一部分；"语法等价"不等于"时机等价"。

### W14 · 以为"两端编译期受检"，实则名面是手写副本
- 情境：以为做完频道表，前后端契约就机器受检了。
- 错路：**没查渲染层那份**。实证：`src/adapters/host/electron/window-api.d.ts`（7.13 KB）是**手写的**冻结契约，头部自称"方法名必须与 `preload.js` 完全一致"、差集靠 `extract-host-api.cjs` **人工比对** ⇒ 名面一直写在两处（成员数**以 B0-a 快照为准：81**；此处不再写具体数字，防第二处漂移）。
- 正路：**三段式**（计划 §5）—— 后端原始面＝**真源**（频道表）· 渲染层原始面＝**产物**（由表生成到 gitignore 的 `build/host-api/`，prebuild 生成 ⇒ 过期结构上不可能）· 适配层 `HostPort`＝**另一层**（不同形 ⇒ 不算重复）。
- 判据：判"契约是否机器受检"要**顺着链走到渲染层**；只收口一半 ＝ 价值打折而声明没打折（母体 R4 的新实例）。

### W15 · 没有 before 证据，就永远证明不了 after 等价（且漏了"数据兼容"）
- 情境：G5 写着"行为等价"，验收靠"转换 commit 零逻辑改动 + 我小心了"。
- 错路：两处都错：① **没有迁移前的快照/样本** ⇒ 事后任何"等价"主张都无据可查（只能嘴证）；② 只盯**行为**，漏了**落盘格式**——`settings.json` / `项目工程.json` / `config-store` 密钥文件 / 账号导出 / skill-pack 缓存，转换若改了序列化或字段，**旧数据就读不出来**（AGENTS 的目标本就是"行为等价 + 数据兼容"两条）。
- 正路：B0-a 就录四件（计划 §4.2 D-10…D-13）：频道清单快照 · handler 回执形状快照 · **黄金样本**（纯函数/可注入部分，含 `license` 与存储布局探测）· **数据兼容样本**。之后每批按需比对。
- 判据：**before 不录，after 无从证明**；样本是**证据**不是第二真源（实现不许读它）。

### W16 · 规矩没有"寿命" ⇒ 任务结束留下僵尸约束
- 情境：迁移期为混合态立的规矩（禁 `export default` · 顶层 `require` 保留 · 未转清单 …）。
- 错路：全量转完后这些规矩**前提已消失**，但没人删 ⇒ 后续 AI 照旧遵守，甚至被当作"本仓一直这么写"（正是 AGENTS 提醒要过 ADR 索引的那类）。
- 正路：计划 §12 给每条规矩标**寿命**（混合期 / 永久）；任务结束时**混合期规矩删除或标注失效**，永久规矩进 eslint 块 / 判据登记表。
- 判据：规矩也是"同一真相"的一种 —— 前提没了还留着，就是第二处漂移源。

### W17 · 跨模块"改导出值"在 ESM 产出下静默漂移（CJS 值快照 vs ESM live binding）
- 情境：某模块导出可变状态，**消费方直接改它**（如 `require('./x').counter++` 或用 `exports.x = ...` 当共享状态）。
- 错路：把该模块转成 ESM 语法。tsc 的 CJS 产出里**内部变量与 `exports.x` 是两份** ⇒ 消费方改到副本上，模块内部读不到；**编译期不报、运行期静默漂移**（只在特定调用序列下显形）。
- 正路：清点表里查这个形态（计划 §2.1 A-6）；**命中 ⇒ 该模块保留 CJS 形态**（或同批改成"经函数改"—— 属逻辑改动，须留痕）。
- 判据：CJS 导出是**值快照**，ESM 是 **live binding** ——「语法等价」在这里不成立（计划 §7 I-4）。

### W18 · 把计划里靠推理的断言当事实用
- 情境：计划写了很多"已取证"，但**有几条是抽样推理**（§2.1 的 A-1…A-7：`api/**` 是纯净子域 · providers 是纯函数 · license 可注入 · 无环 · 无"改导出值" · guest 脚本只有一个…）。
- 错路：执行者照信 ⇒ 在错前提上**排批次、定可测边界** ⇒ 返工要到 B2/B3 才暴露（那时已转好几十个文件）。
- 正路：B0-a 用**脚本扫候选**（`require('electron')` / 顶层副作用 / 惰性 require / 环 / `module.exports = fn` / 改导出值 / 顶层 `this`）＋ 逐条核实 A-1…A-7；**人只判例外**；推翻就改本文。
- 判据：本仓血训是"笔记/推理会错，证据才对"（`docs/plan/04-防返工-机制.md` R1）—— **计划自己也必须被证伪**。

### W19 · 把机械活当人活（低估脚本价值）
- 情境：计划把大量**由语法就能定**的活排给"AI 逐个读、逐个抄"：清点表逐行填 · 频道表 82 个方法手抄 · `require`/`module.exports` 手改 · JSDoc 手翻 · handler `return` 字段名手抄。
- 错路：人做机械活的**两个代价**：① 慢；② **会漏**（漏一个导出 ⇒ 运行期断而编译不报；漏一个方法 ⇒ 契约缺位）。而"慢"只是次要的——**"漏"才是致命的**。
- 正路：**机械活一律脚本**（判据见计划 §11.5：由语法/结构能定 ⇒ 脚本），**判断活才用人**（字段类型 · 判别联合 · 该归谁 · 是否等价）。草稿脚本必须**留 `TODO` 占位**，完成判据 ＝ **TODO 清零 ＋ 编译期交叉校验通过**。
- 判据：脚本对机械活的优势不是"省时间"，而是**"不会漏 + 可重复 + 可复核"**；反过来，脚本产出的草稿**必须带 TODO**，否则草稿会被当成真源（那是新的返工源）。

### W20 · 用生成器解决"类型派生"问题（先问 TS 自己能不能算）
- 情境：要让渲染层拿到与后端频道表一致的 `WindowApi` 类型面。
- 错路：写一个 **AST 生成器** → 产 `.d.ts` → 让 src 消费 → 引入 `build/host-api` 产物 ＋ **prebuild 顺序耦合** ＋ src 侧 import 改动。**四样机器担子**，只为"派生一份类型"。
- 正路：**mapped type**（TS 自己就能从表的键/值算出 `WindowApi`）⇒ **零生成器、零产物、零顺序耦合**；真源搬到 `src/stable`（"冻结契约"的家），后端经 `@shared` **type-only** 消费。
- 判据：**"派生"优先交给类型系统（mapped/conditional type），脚本只用于"语法面改写"**；两者混淆会凭空造出构建管线。

## B0-a 现场新增（2026-10-15）

### W21 · 过桥核对用「文本行比」⇒ 真差异被**格式重排**埋掉（附带 CRLF 坑）
- 情境：核 `allowJs` passthrough 是否改了运行期行为（W11 要的就是这个证据）。
- 错路：把源与产物按行归一后比文本。**同一晚两次假红**：① 归一没先处理 CRLF ⇒ 行注释 `// …` 剥不掉（`.$` 被 `\r` 挡住）⇒ 26/28 报"实质"；② 补上 CRLF 归一后，tsc 把 `if (x) return;` **重排成两行** ⇒ 23/28 报"实质"。两次的"实质"里**真差异 0 处** —— 真差异（唯一那条 `"use strict"`）反而差点被淹没。
- 正路：比 **AST**（`@babel/parser`，剔位置/注释字段后 dump），并把 tsc 已知外壳（`"use strict"` / `__esModule` / `exports.X = void 0`）列成显式白名单 → 分档 `同 / 头 / 实质`。
- 判据：**重排会把格式差异无限放大** ⇒ 判据必须落在语义层（AST / 类型 / 样本），文本层只能当线索。

### W22 · 照计划的旗组合直接配 ⇒ 当天全红（首选与替代阶梯**都**不成立）
- 情境：§6 S0-2 首选 `module: node16` ＋ `verbatimModuleSyntax`；S0-6 写的替代是 `commonjs` ＋ `node10`。
- 错路：直接照配。**实测**：① **TS1295/TS1287** —— `electron/` 最近的 package.json 是 `"type":"commonjs"` ⇒ 文件按 CJS 处理，开 verbatim 时 **ESM 语法被拒**；② **TS5107** —— `moduleResolution: node10` 在 TS 6.0.3 **已弃用**，要靠 `ignoreDeprecations` 才跑得动（那是降噪开关，选了就是拿配置盖问题）。
- 正路：定稿 **`node16`/`node16` ＋ `verbatimModuleSyntax: false`**（实测绿，产物仍是 `require`/`exports.x` ⇒ 运行期形态不变）；「`@shared` 只许类型导入」改由 **eslint `no-restricted-imports`（`allowTypeImports`）**承担 —— **判据没松，载体换了**。
- 判据：**旗组合的成立性只能实测**（W7 的预判兑现：spike 前置把最坏情况压到"改两行配置"）。凡"计划里写着能这么配"⇒ 先跑最小样例。

### W23 · 把计划的"可注入"当事实 ⇒ 黄金样本**录不到**，after 无从证明
- 情境：§2.1 A-3 说「`license.js` 的机器码/验签路径可注入」；D-12 把 license ＋ 存储布局探测列为黄金样本。
- 错路：照 A-3 排 B3/B4 的对照工作。**实测**：`license.js` 的导出面只有 `initLicense` / `__setTrustedTimeOverride`；`detectStorageLayout` / `migrateEngineeringToFile` 在 `main.js` 内部未导出 ⇒ **两类都不可注入**（要触发只能起 Electron 壳）。
- 正路：按 A-3 自己写的"若被推翻"一档处置 —— **改手工清单 ＋ 如实标「未验」**（`replay-samples.mjs` 把"可达性 ＋ 手测清单"一起录进证据）；⛔ **不为取证新增导出**（那属逻辑改动，另走通道）。
- 判据：**「能不能取证」本身也是一条要现场核的断言**；录不到就写"未验"，⛔ 不许用"我会小心"顶替（W15 的后半段）。

### W24 · 契约名面对账的两种错：只按一侧抽表 ⇒ **真漏**；只按 callee 名扫 ⇒ **假缺口**
- 情境：核 A-4「频道表覆盖全仓 `ipcMain.handle/on`」。
- 错路：① 只从 `preload.js` 抽名面 ⇒ 漏掉**后端独有注册**：`open-lovart-chrome`（`chrome-cdp.js` 注册、preload 无成员、`src/` 也零消费 —— 幽灵频道）就是这么冒出来的；② 只按 callee 名（`.send(`）扫后端推送 ⇒ 报**假缺口**：`lovart-fetch.js` 用本地 helper `sender('lovart-fetch-item', …)` 转发，按名字根本认不出 ⇒ 一度把 `lovart-fetch-item`/`-done` 判成"只在 preload"。
- 正路：对账以**频道名**为中心、三侧并列（preload 种类 · 后端注册 · 全仓字面量出现）；**两侧都不许单边作准**。
- 判据：**对账脚本自己也会产出假证据**（本条就是被 `sender` 这个反例证伪的）⇒ 口径要能被反例打穿，否则它只是"看起来绿"。

### W25 · 计划给的**修法本身**不成立：`app.getAppPath()` 不是"仓根"
- 情境：D-4 写着「`main` 里 `../dist` 引用同批改 **`app.getAppPath()`**」。
- 错路：照它改。**实测**（最小探针，两种入口各跑一次）：`app.getAppPath()` ＝ **入口所在目录** ——
  `electron <文件>` ⇒ 该**文件**所在目录；`electron <目录>` ⇒ 该**目录** ⇒ 它会**随启动方式变**，
  拿它当"仓根"再拼 `dist` 会在某种启动方式下指错（而"白屏"这个后果恰恰要等启动才暴露）。
- 正路：`__dirname` 是**唯一可推定**的基准（入口文件永远在 `<app>/electron[\/dist]/`）⇒ 拼「上两级」；
  并且 **`main` 字段切换与路径修正必须同批** —— `../dist` 对**源码**落点是对的、对**产物**落点是错的
  ⇒ 分两批做，中间那一批**必然白屏**。
- 判据：**计划里的"怎么改"同样要被判据打穿** —— 修法要能自己解释"为什么它对"，不能只因为计划这么写。
  （与 W18 同族、方向相反：W18 是"别把断言当事实"，本条是"别把**处方**当事实"。）

### W26 · 地基只按"计划想起来的那一件"枚举 ⇒ 漏的那件恰好**失败不可见**
- 情境：D-5 只写了「`preload: __dirname/preload.js` ＋ guest 脚本拷贝**同目录**」。
- 错路：只照那一件做。`grep __dirname electron/` **实算**下来是 **4 处 / 3 类**资源：
  `preload.js`（tsc 产出）· `dola-duration-main.js`（注入脚本）· **`dola-skill-pack.json` ＋ `doubao-skill-pack.json`**
  （`dola-media.js` 读）· 外加**两处 app 根基准**（`appasset` 的 `dist` 根 · `firefox.js` 的内置件）。
  后两类漏掉的后果**不是崩**：`loadSkillPack` 的 `catch` 会把它**回落成空 pack**（只 warn 一行）⇒
  **"起窗没崩"的冒烟抓不到**，而功能（30s / 音频参考选项注入）已经废了。
- 正路：清单**用 grep 实算**（写进 §4.1 D-5 行）；把那条 warn 提成冒烟的**致命标记**；
  打包后再核一次 asar 清单（漏拷在 asar 里同样看得见）。
- 判据：**地基要按"所有依赖它的点"枚举，不是按"计划想起来的那一件"** —— 尤其当漏掉的那件属于
  **无痕兜底**（`catch` 后给个空值）时：它同时躲过编译、躲过存活型冒烟、躲过"我小心了"。

## B1 现场新增（2026-10-15）

### W27 · `node16` 下的**两条解析细节**，会被误读成"路径写错了"
- 情境：让后端经 `@shared` 引入 `src/stable` 的契约表（声明层产物住 `build/shared-types/`）。
- 错路（两条都实测过，报错文案都不指向真因）：
  ① `paths: {"@shared/*": ["../build/shared-types/*"]}` ⇒ **TS2307「找不到模块」**。
     `--traceResolution` 才看得出真因：`node16` 的 **ESM 解析不做无扩展名查找** —— 它把 `…/ipc-channels`
     当**目录**找，找不到就放弃。⇒ 映射必须自带扩展名：`["../build/shared-types/*.d.ts"]`。
  ② CommonJS 文件里 `import type { … } from` 一个 **ESM** 声明（共享源码在根 package.json 的
     `"type":"module"` 下 ⇒ 其 `.d.ts` 是 ESM）⇒ **TS1541**「必须带 `resolution-mode` 属性」。
- 正路：按编译器**点名**的修法走（它把两条都说清楚了）：路径带 `.d.ts` ＋ `with { 'resolution-mode': 'import' }`；
  并在**改动处**写清"为什么不换个更顺眼的写法"（换成运行时 import 会把渲染层源码打进后端产物）。
- 判据：**"找不到模块"的报告位置不等于原因位置** ⇒ 这类问题上 `--traceResolution`（A 级证据），别靠试。

### W28 · 「type-only 共享」下 **G3 的字面目标（频道名只写一次）结构上不可能**
- 情境：§5 定「真源 ＝ `src/stable` 的表；后端经 `@shared` **type-only** 消费」；G3 要「频道名只在表里写一次」。
- 错路：以为做完表就自然"只写一次"。实际两条硬约束顶在一起：
  ① 后端**不许**运行时 import `@shared`（那里只有 `.d.ts`）⇒ 表里的频道**字符串**到不了运行期；
  ② 成员名→频道名的映射**不是机械可推**的（`apiJobSubmit` → `api-job:submit`）
  ⇒ `preload` 里那些字符串**必然**要再写一遍。
  ⛔ 并且不能"顺手补上"：把 `open-lovart-chrome`（后端注册、渲染层无名面）塞进 `WindowApi`，
  会反过来**要求 `preload` 暴露它** —— 而原版也是注册而不暴露（回源结论）⇒ 那才是改行为。
- 正路：能拿到的最强形态分三层落地 ——
  ① **成员名 + 种类**：两端**编译期闭合**（`preload` 的 `satisfies WindowApi` ＋ 渲染面手写副本的
     名面同源守卫）⇒ 漏/多/改名/种类不符**当场红**（实测：改真源或改 `preload` 各红一次）；
  ② **后端独有频道**：留在**同一张表**里，用 `backendOnly` 位在**类型层**把它从 `WindowApi` 滤掉
     （滤掉 = 类型层分区，不是第二份清单）；
  ③ **频道字符串**：两侧各一次、**暂无人守**（要守只能靠"对账测试"，而 AGENTS 明令不新增对账测试）
     ⇒ 如实登记为**待决项**，不假装已闭合。
- 判据：**判据要按"结构能给什么"分层写清楚**，把"做不到的那层"**明写成待决**；
  ⛔ 最坏的做法是给一个"看起来覆盖了"的声明（那正是 W14 的病）。
