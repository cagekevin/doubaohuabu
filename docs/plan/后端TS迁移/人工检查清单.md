> **这份东西的用途**：回答一个问题 —— **「这个 `.ts` 的行为，和原来那份 `.js` 一样吗？」**
> 为什么只能人工：**我们不是机械转码，是人工重写**。机械转码可以逐字节断言；人工重写只能
> **逐步骤核对输入/输出**。脚本能做的只有"把该读哪里列出来"＋"列出它看见的差异"，
> **判断只能由人对着该处的源读出来**（README §11.2 原话：它只列差异、不下判断 —— 每一条都要人看，
> **对着该处的源看**，不是对着某张"允许清单"看）。
>
> **本清单锚定 README**（`G1`–`G6` · §7 改写不变量 · §8 DoD/通用战术 · §11.2 脚本定位 · §12 记录约定），
> ⛔ **不新增更松的判据**（尤其禁"抽样通过即算过"），⛔ 也不自立更严的判据去否定已提交批次
> （真要改判据 ⇒ 先改 README ＋ 留痕 —— §6 粒度：遇本文没写到的情形，停下来改本文）。

## 0. 先回答："只核契约够吗？" —— **不够，契约只锁边界**

| 层 | 覆盖什么 | 谁来做 | 为什么契约层盖不住 |
|---|---|---|---|
| **A 契约面** | IPC 边界：频道名 · 种类 · 形参 · 回执形状 | **机器可查**（频道表 ⇒ 派生面 ⇒ 两端 `satisfies`） | 它只描述"门的两侧接口"，**看不见门里面的分支** |
| **B 数据流步骤面** | 每一步的**输入从哪来 / 输出到哪去 / 副作用** | **人读两侧源码** | handler 内部有 CDP 调用、定时器、落盘、协议 handler —— 契约里一个字段都没体现 |
| **C 红区逐字** | 字符串常量：注入脚本 · 通道名 · 开关名 · 用户可见文案 | **人逐字比** | 契约对字符串只要求"频道名一致"，注入脚本整段都在契约之外 |
| **D 数据兼容** | 落盘格式（`settings.json` / 工程快照 / `img://`·`vid://` 引用 / cookie 导出文件） | **样本对照（§4.2）** | 契约只管 IPC 回执，不管**写到磁盘的字节** |
| **E 输入/输出对照** | 同一输入下 **旧实现 vs 新实现** 的输出（回执 / 落盘 / 副作用 / 日志） | **两侧各跑一遍 ＋ diff** | ⚠️ **后端没有 UI** —— "点界面"证不了后端等价；后端唯一可验的就是 in/out |

⇒ 一句话：**契约面是"可机器证明的那一小块"**，本清单的主体是 **B/C/D/E** 四层。

## 1. 基线：对照的是**哪一份**（这一步就是"避免误导"）

**定义**：某文件的基线 ＝ **git 里同一路径的 `.js`，在"该文件改名提交"的前一个提交**里的内容。
在飞的批次（改名未提交）回落到 `HEAD:<path>.js`。

**⛔ 三条禁用基线**（拿它们对照必然得出错结论）：

1. `docs/豆包画布原版参考/inputs/electron/**` —— **旧一代**（直注册 `ipcMain`、媒体域还没搬进
   `dola-media`、没有 `site-hosts`），与本次改写依据**不是同一份**。
2. 「迁移前提交」那版 —— 例如它的 `main.js` 是 **2,403 行**，而改写依据是**改名前的 HEAD 版**（**2,409 行**，
   多了 B0-b 的 D-4 改动：入口切产物、`../../dist/index.html`、`appasset` 的 dist 根）。
   （这份临时导出已删，原因就是会误导。）
3. 凭记忆 / 凭印象 / 凭"我记得源里是这样"。

**取基线与差异的命令**（每文件一行，粘上去即得确切 ref 与差异清单）：

```bash
# 基线引用 + 事实面集合差（字符串/数字/调用/运算符/属性/标识符 + 导入/导出/定义面）
node docs/plan/后端TS迁移/scripts/audit-conversion.mjs electron/<路径>.ts

# 逐语句·有序差异（只放行语言级等价，并把放行了什么全部打印）
node docs/plan/后端TS迁移/scripts/verify-identical.mjs electron/<路径>.ts --max 0
```

**⚠️ 脚本结论的正确读法**：`audit-conversion` 的第一行就是它用的基线（`原文 <sha>:<path>`）——
**先核这一行**（它必须等于 1 节的"改名提交的前一个提交"），再读差异。
`verify-identical` 报 `差异 0 条` **不等于**已证等价（见 §6）。

## 2. 判定栏：人工写，脚本不许代填

| 取值 | 含义 | 附加要求 |
|---|---|---|
| `等价` | 逐步骤核过，in/out 与副作用一致 | 写**依据**：读了哪段源码、比了哪两个符号 |
| `等价微改（已登记）` | 有改动，但属"类型/闸逼出来的"且已登记 | **必须在 `日志.md` 找得到那一条**；找不到 ⇒ 改判 `待解释` |
| `待解释` | 看见了差异，但当下解释不了 | 写清"看见什么"；解释不了就**不许**划等价 |
| `不一致 → bug/债` | 真行为差异 | 走 §10.2（真 bug 单独 commit / 记债），⛔ 不许就地改业务混进转换提交 |
| `未验` | 没做 | §1.2 允许存在；⛔ **不许**用"脚本绿"顶替 |

**硬规则**：选 `等价微改（已登记）` 的，登记里必须写明**为什么这么改**（两选一：① 类型必需
—— 收窄/断言/`asRecord`/`String()`/`Number()`；② 闸必需 —— `catch` 形状、未使用绑定、显式 `void`、
局部 `unknown`）。**其余任何理由** ⇒ 判 `待解释`。

#### 3.2 api 域的**取值口径**变化（**不是契约面**，逐条给出边界）

> 判据按 §2：这些都属**「类型必需」**（收窄 / `String()` / `|| ''` 归一），**同类已在 `日志.md` 登记**
> （B2-c 的审计结论 · B3 的「本批新增的全是类型必需的收窄（`asRecord` 收窄外部载荷 · `Buffer.from(match[2] || '')` ·
> `String(...)` 收成 `string`）」· B4 的「IPC 形参一律 `asRecord` / `String()` / `Number()` 收窄」）。
> ⛔ **但它们改的是取值，所以边界要写清**（可观察性 = 渲染层送来的东西不合契约时）：

| # | 处 | 旧 → 新 | 边界（何时可观察） | 判定 |
|---|---|---|---|---|
| ① | `api-job:submit` / `api-job:batch` | `payload` → `asRecord(payload)` | 渲染层送**非对象**（`null`/字符串）时：旧原样透传、新归一成 `{}` | 类型必需（已登记） |
| ② | `api-job:cancel` | `jobId` → `String(jobId)` | 渲染层送**非字符串**时 | 类型必需（已登记） |
| ③ | `api-config:test` | `cfgRow.baseUrl` → `cfgRow.baseUrl \|\| ''`（`model` 同） | 磁盘上该 provider 的行**缺 `baseUrl`**（手改文件）时：旧传 `undefined`、新传 `''` | 类型必需（已登记；与 `Buffer.from(match[2] \|\| '')` 同形） |
| ④ | `api-setup:set` | `setSetup(patch \|\| {})` → `setSetup(patch)` | **无可观察差异**：`setSetup` 内部本就 `patch && typeof === 'object' ? patch : {}` ⇒ 假值两条路都成 `{}` | 等价（去掉冗余） |
| ⑤ | `api-job:list` / `submit` / `batch` / `cancel` | `_apiJobManager.x` → `_apiJobManager?.x`（`list` 另加 `?? []`） | **无可观察差异**：`_apiJobManager` 在 `initApi` 内先赋值、handler 随后注册 ⇒ 能进 handler 时它必非空 | 等价（防不可达路径） |

**⇒ A 层 api 域结论：三方（表 / 旧 handler / 新 handler）在名面 · 种类 · 形参名 · 回执形状上全一致；无新增真不一致。**

#### 3.5 ★ 频道名收口（**类型层** · 2026-10-15）

**问题**：频道名此前**两侧各写一次裸字符串** —— 后端 `handle('…')` / `on('…')`（65 ＋ `api/bridge` 的 12 处）

⇒ 这正是这次迁移存在的理由（TD-13-26 / README §1：**契约漂移是本仓唯一实证过的 bug 类** ——
剪贴板三 bug · `jobId` vs `id` · `size` vs `bytes` 都是它）。

**收法**（类型层；优先级：结构上不可能 ＞ 类型层 ＞ 唯一入口／唯一产生方）：
1. `src/stable/ipc-channels.ts` 加派生类型 `IpcChannelName = NonNullable<IpcChannelMap[keyof IpcChannelMap]['channel']>`；
2. `electron/ipc.ts`：`handle` / `on` 的 `channel: string` → `IpcChannelName`；
3. `electron/preload.ts`：新增三个带约束的调用口 `invoke` / `send` / `subscribe`（既有 `syncUnknown` 收成同一联合），
   75 处裸 `ipcRenderer.*` 调用改走它们；5 个订阅点收成 `subscribe(…)`（此前每个订阅把**同一个频道名写两遍**）。

**凭证（先红后绿）**：
- 故意写错**后端**频道名（`handle('import-filess', …)`）⇒ `tsc -p electron/tsconfig.json --noEmit` **exit 2**：
  `error TS2345: Argument of type '"import-filess"' is not assignable to parameter of type 'IpcChannelName'`。
- 故意写错 **preload** 频道名 ⇒ **两处**报错（`TS2345` 频道名 ＋ `TS2322` —— `satisfies WindowApi` 也当场红）。
- 改回 ⇒ **exit 0** · `npm run check` **7 道全绿** · 构建 ＋ **冒烟 ✅** · `ipcMain` 仍只在 `electron/ipc.ts`（唯一持有者）。

**⚠️ 边界（如实）**：收掉的是"**不一致不可能**"，**不是"只写一次"** —— 字符串仍在两侧各出现一次
（后端**不许运行时 import `@shared`**，那里只有 `.d.ts`；且成员名 → 频道名不是机械可推的：
`apiJobSubmit` → `api-job:submit`）。要"只写一次"得改成**构建期生成 preload 面**（另一条路，未做）。

### 7.1b 怎么用双侧对照工具（`compare-inout.mjs`）—— 三条读法纪律

```bash
node docs/plan/后端TS迁移/scripts/compare-inout.mjs            # 全量：导出面 + 常量 + 有样本的函数
node docs/plan/后端TS迁移/scripts/compare-inout.mjs --list --only site-hosts   # 只看导出面与形参数
```

1. **"无样本"≠"验过"**：工具把没有输入样本的函数**显式列出来**（`⚠️ 无样本 N 个`）。那些行**必须写"未验"**，
   ⛔ 不许拿"它出现在这份报告里"当成通过。
2. **⛔ 语义面映射必须引用"已登记的约定"**，不许临时编口径：
   例 —— `api/providers/*` 旧侧是 `module.exports = adapter`、新侧是 `export { adapter }`（B2-b 日志登记过的约定变化），
   所以比的是"旧＝模块本体 / 新＝`.adapter`"；`kling` 还要把源里 adapter 上的 `signKlingJwt` **合回**（日志同条登记的"改具名导出"）。
   映射写错 ⇒ 会得到**假差异**（我第一版就误报过"缺 15 个导出"）。
3. **⚠️ "基线含中途改动"⇒ 该行只能人读**：若某文件的"改名前那版"**已被迁移中途的批次碰过**
   （工具会点名；实测 `api/bridge.js` · `firefox.js` · `main.js`），那它**不是纯源** ⇒
   报告里的"异"很可能是**假差异**（例：`bridge.js` 旧侧一加载就抛 `registerProvider: 缺少 id`，
   因为那份中途快照里 bridge 已按 `.adapter` 取，而同期的 providers 还是 `module.exports = adapter`）。
4. **⚠️ 对照前先问"这个模块加载时会不会写全局状态"**：会 ⇒ 它必须与其它模块**隔离**（或排末位）——
   否则量到的是**顺序差异**，不是代码差异。实测：`api/bridge.js` 加载即 `registerProvider(…)` 五次，
   同进程里污染了 later 的 `api/registry` 空表样本（新侧有、旧侧空）⇒ 假报"异"2 例。工具已用
   `DEFER` 清单把这类模块排到末位并**打印理由**。
5. **⚠️ "同"不是等价 —— 先问"是不是两侧一起失败了"**：两侧都失败时输出**逐字节相等**，会报"✅ 同"。
   实测：E2 曾因 `spawnSync` 堵死父进程（本地服务答不了）⇒ 前两例两侧**都**是
   `{ok:false,status:0,error:'timeout'}` ⇒ 报"同"。⇒ 用 **`--values`** 把实值打出来看（默认只在"异"时打印）；
   ⛔ 别把"探针回得慢/回得少"读成"探针死了"——先查**超时**（`requestJson` 默认 30s）与**对端是否可达**。
   详见 `弯路.md` W36。
