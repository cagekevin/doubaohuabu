## 2 覆盖表（按组配平 · **2026-10-13 逐项取证后**）

> **四档口径**（§5 的判据落到每一件上）：
> **直接** = 本仓有对应实现，能指到「文件 + 符号」· **等价** = 本仓用**不同机制**承担同一语义，能指到那个机制
> · **待落** = 指不到（记目标批）· **不落** = 指得到"**为什么不该建**"，两类理由：
> **① 源内 0 消费**（`Uu` 那族 · ★10 的 `le`/`At`/`_t`/`F`/`U`/`H` —— 只服务 `useImperativeHandle`
> 里那 3 个**全目录 0 消费者**的方法）· **② 本仓机制不经过该阶段**（`Je` —— 本仓附图是 CDP 一次直喂）。
> · **③ 归链**（属于另一条**已登记的未落链** ⇒ **不在本计划内单独落**）：批3 的 3 件 → `TD-16-83`/`TD-16-84`。
> ⚠️ **等价 ≠ 直接**：若"语义由谁承担"写不出来，一律退回**待落**（不许用"差不多"配平）。
> ⚠️ **不落 ≠ 非缺口**（旧叫法）：旧叫法只认"源里没接出去"，会把"本仓机制不同"误记成"源里没有" ⇒ 改名并给出两类理由。

## 5 配平的唯一补齐办法（**不是再算一遍，是逐项取证**）

上面 §2 的三个"已落"数（G3/G4/G7）**写作当时是估计**。**估计 = 洞**。补齐只有一条路：

> **对 G3/G4/G7 的每一项，在 `src/` 里指到「哪一层、哪个文件、哪个符号」；指不到的就是"待落"。**
> ① 指得到 ⇒ 记 `直接`（有实现）或 `等价`（语义由别的机制承担，须写出是哪个）；
> ② 指不到 ⇒ 记 `待落 + 目标批`；③ 指得到"**为什么不该建**" ⇒ 记 `不落 + 理由`（源内 0 消费 / 本仓机制不经过该阶段 / **归链**）。
>
> **规则：配不平（`直接 + 等价 + 待落 + 不落 ≠ 105`）不许开工。** 定性只能靠**回源 / 回代码**，不能靠文档、不能靠印象。

**执行结果（2026-10-13）**：G3/G4/G7 的 64 项**已逐项取证**（见 §2.1~§2.3 三张表）⇒ 配平 **`69 + 16 + 0 + 20 = 105` 成立**（**待落归零**）。
取证办法：源定义/用法逐条回源（`grep -nE` 取 `g.useRef`/`g.useState`/`g.useCallback` 定义 + 用法），再在 `src/` 里逐条指落点；指不到的 → 记目标批。
★ **原「一处待用户裁」已由源解决（2026-10-13）**：`d`/`oT`/`sT` 就是 **`Jn`（账号 → 后台页状态记录）的 key 快照**；**卸载事件 `lT` 不删记录**（`:26011-26022` 只置 `ready=false`），记录**只在「末条租约释放 ＋ `drainDelayMs`（`K$ = 1500ms`）到点」时删**（`eT` `:25916-25937` 里的 `Jn.delete`）⇒ **不是"两个文档矛盾"，是文档没写清"删在 drain 里"**。落点已按此实现（★8 已落）。
