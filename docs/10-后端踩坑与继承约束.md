## 八、对重写的「硬约束清单」（可直接当检查表）

1. **不得内联 base64** —— 一律 `img://` / `vid://`（否则配额超限复发）
2. **不得用 JS 改 `navigator`/`screen`/`webgl`** —— 零注入策略，改了会被探针判定「环境被篡改」
3. **不得声明高于真实引擎的 UA 版本**
4. **不要开自动轮询抓取**（默认关闭，开了被判机器人）
5. **不要传 CF cookie**（已剔除）
6. **所有宿主调用要 try/catch** —— 尤其 `lovartFetchImages` 这类会整批失败的
7. **缩略图一律走 `?w=`**，不要加载原图
8. **剪贴板文本必须先 `clear()` 再 `writeText()` 且 `await`**
9. **视频必须落盘**，不要依赖远端直链
10. **兼容层要读旧目录**（`images/`/`videos/`/`thumbs/`）与旧键（`doubao-canvas`）

## 九、React 19 决策的连带影响

**已定：直接用 React 19。**

| 影响面 | 说明 |
|---|---|
| 宿主契约 | **无影响** —— `react` 是纯渲染层依赖，后端不关心 |
| `@xyflow/react` | ⚠️ **需确认 peer 依赖支持 19**（这是唯一实际风险点） |
| 可用新特性 | `use`、Actions、`useOptimistic`、`useEffectEvent`（对「事件 vs Effect 分离」有帮助） |
| 类型 | `@types/react@19` |
| 与「零注入」的关系 | 无 —— 前端 React 版本**不会**被站点探测到（webview 里跑的是站点自己的页面） |

> ⚠️ **唯一要验证的**：`@xyflow/react` 当前版本对 React 19 的支持情况。若其 peer 仍是 `^18`，要么等升级，要么暂时双版本（不推荐）。**这条建议放进 `08-验证用例.md` 作为前置检查项。**
