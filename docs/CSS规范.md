# 17 · CSS 规范

> **定位**：CSS 层的**唯一契约**。
>
> 它不只说"不许什么"——更重要的是说清 **「新需求来了往哪儿加」**。
> 一个只列禁令的规范，会让后续的人 / AI **无路可走**，只好自己造一个更差的；
> 这份规范的目标是让每一步扩展都有**明确的落点**。
>
> ★ **这份文件本身可以改**，见 §0。
>
> 依据：`AGENTS.md` §五（SSOT 真源清单）· `docs/11-架构与契约定稿.md` §2.1

---

## §0 这份规范怎么演进

**规范是代码的一部分，不是刻在石头上。**

当你（人或 AI）发现**更好的做法**时：

1. **改这份文件**，在对应小节写清新规则 + **理由**；
2. 如果新规则**替代**某条旧规则，写清**迁移路径**（哪些文件要跟着改）；
3. 改完跑 §7 的验证。

### 什么算"更好"（优化判据）

| 判据 | 说明 |
|---|---|
| **更少重复** | 同一件事写的次数变少（如 7 处主按钮 → 1 处真源）|
| **更少名词** | 需要记的名字变少（如删掉别名，避免一名两物）|
| **换皮范围更大** | 改一处生效的地方更多（如 L3 旋钮一改，7 个面板同时变）|
| **不新增语法限制** | 不能为了省事引入 `!important` / 更深的选择器嵌套 |
| **可机械验证** | 新规则要能用一条 grep / 一次 build 检验真假 |

### 什么**不**算理由

- ❌ "这次来不及" / "先这样，以后再收" —— 那正是制造第二份真源的开始
- ❌ "只有这一处，无所谓" —— 只有一处时才是最便宜的收口时机
- ❌ "原版就是这么写的" —— 原版写法是**素材**，不是规范（原版也没有这套 token 体系）

### 不许做的事

- ❌ 绕过规范自己写一份（如新面板自造 `.panel`）——这是**本仓红线**
- ❌ 改规范但不写理由 / 不写迁移路径
- ❌ 破坏 §4 的四条硬红线

## §1 四层契约（不可越层引用）

| 层 | 文件 | 放什么 | 谁准引用它 |
|---|---|---|---|
| **L1 原始值** | `src/styles/tokens.css` 顶部 | 十六进制色值、px 基数（`--p-indigo-500` / `--dim-4`）| **只有 L2** |
| **L1.5 品牌槽** | 同上 | 指向 L1 的品牌色（`--brand-500`）| L2 |
| **L2 语义** | 同上 | 意图（`--color-surface-raised` / `--color-action-primary` / `--space-2`）| L3 **+ 组件 CSS**（通用语义）|
| **L3 组件旋钮** | 同上 | 具体控件参数（`--btn-primary-bg` / `--node-selected-ring`）| **只有组件 CSS** |
| **真源类** | `src/ui/common/shared.module.css` | 可复用类的**完整形态**（`.btn` / `.field` / `.overlay`）| 组件 CSS（`composes`）|

### 一句话记住

> 组件 CSS 里写 `var(--btn-primary-bg)` 或 `composes: btn`；
> **不写** `#6366f1`、**不写** `var(--p-indigo-500)`。

### 为什么 L2 允许被组件直接引用

大厂（Ant Design / Carbon）也一样：`--color-border`、`--color-text-muted` 这类**跨组件通用语义**
直接用在组件里是正常的。L3 只覆盖**需要单独调的控件参数**——
否则 L3 会膨胀到几百个旋钮，反而没人记得住。

**判据**：这个属性会不会需要"只改它、不动别的"？
- 会 → 给它 L3 旋钮
- 不会（跟着全局走就行）→ 直接用 L2

## §1.1 层级阶梯（z-index）

**规范默认不写 z-index** —— 写了就是"比谁高"的军备竞赛。需要分层时走这套：

| L1 原始值 | L2 语义 | 值 | 用途 |
|---|---|---|---|
| `--layer-canvas` | `--z-canvas` | `1` | 画布内元素 |
| `--layer-panel` | `--z-panel` | `100` | 常驻面板 |
| `--layer-overlay` | `--z-overlay` | `500` | 浮层：菜单 / 下拉 / 浮动按钮 / 工具条 / 提示浮窗 |
| `--layer-modal` | `--z-modal` | `900` | 模态：对话框 / 全屏面板 |
| `--layer-toast` | `--z-toast` | `1000` | 提示条（永远最上）|

**规则**：

1. 组件 CSS **只写 `var(--z-*)`**，不写字面量
2. 新浮层先问**"它属于哪一档语义"**，而不是"我要比谁高"
3. 档位不够时（例如"模态内还要弹菜单"）→ **按 §0 改这张表**（加档 + 写理由），别就地写 `999`
4. `--z-canvas` / `--z-panel` 当前无消费方 —— **保留**，见 §8.4「死变量」判据（刻度完整性）

> ⚠️ **已知待观察**：`shared.module.css .menu`（右键菜单）用的是 `--z-overlay`。
> 若菜单将来要在**模态内部**弹出，会被 `--z-modal` 的面板盖住 —— 那时按规则 3 处理。

## §1.2 其它尺度阶梯（与 §1.1 并列）

**凡是"有一套档位"的族，都从这里查 —— 别就地写值。**

| 族 | L1 原始值 | L2 语义 | 档位 |
|---|---|---|---|
| **字号** | `--type-2xs … -2xl` | `--font-size-*` | 9 / 11 / 12 / 14 / 16 / 20 / 32 |
| **字重** | `--weight-normal/medium/bold` | `--font-weight-*` | 400 / 500 / 600 |
| **行高** | `--line-none/tight/snug/normal/relaxed` | `--line-height-*` | 1 / 1.3 / 1.4 / 1.5 / 1.6 |
| **间距** | `--dim-half, -1 … -6, -8` | `--space-half, -1 … -8` | 2 / 4 / 8 / 12 / 16 / 24 / 32 / 48（**乘 `--density`**）|
| **圆角** | `--shape-xs/sm/md/lg/full` | `--radius-*` | 2 / 4 / 8 / 12 / 9999（受 `data-shape` 切换）|
| **阴影** | — | `--shadow-sm/md/lg` | 轻 / 常规 / 重 |
| **动效时长** | `--dur-fast/base` | `--duration-*` | 120ms / 200ms |
| **缓动** | `--ease-out` | （L1 直接可用，L2 不再重名）| `cubic-bezier(.16, 1, .3, 1)` |
| **层级** | `--layer-*` | `--z-*` | 见 §1.1 |

**规则**：

1. 上表任何一档**都不许在组件里写裸值**（间距 / 字号·字重·行高·圆角 / 阴影 / 动效时长）
2. 档位不够 → 按 §0 **加档**（改 `tokens.css` + 写理由），别就地写值
3. 加档时**一次给一整档**（加行高就 1.3→1.4→1.5→1.6 全给），别只加一个
4. **别让自己引用自己** —— `--x: var(--x)` 是**无效值**（不报错、看着像别名）

## §1.3 命名规则

**一句话**：名字说明**它是什么**（形态 / 部位），**不说明它什么时候出现**（时机）。

### 类名

| 场景 | 规则 | 例 |
|---|---|---|
| 真源基础类 | 单数名词 | `.btn` / `.field` / `.dot` / `.pill` / `.overlay` |
| 语气 / 形态修饰符 | `<基础><语气>` | `.btnPrimary` / `.btnGhost` / `.pillOk` / `.dotLg` |
| 布局容器 | 说明**方位或角色** | `.column`（栏）—— 实录：`LibraryPanel` / `AccountPanel` 的容器从 `.panel` 改成了它，好让 `.panel` 只表示浮层 |
| 可点修饰 | `<基础>Clickable` | `.listItemClickable` |

**反例（都是实录）**：

- ❌ **名字与语义相反** —— `SendQueuePanel` 的 `.bar` / `.progress`：`bar` 看着像填充、`progress` 看着像轨道，
  **实际正好相反**。⇒ 改名 `.track` / `.fill`（同步改 TSX）。
- ❌ **同名不同物**（最危险）—— `nodes/shared .spinner`（**文字型**："生成中…"）
  vs `AnalyzePrompt .spinner`（**旋转圆环**）—— 名字相同、实现无关。⇒ 拆成 `.spinnerText` / `.spinnerRing`。
- ❌ **容器与浮层同名** —— 布局容器（`LibraryPanel` / `AccountPanel` 的 `.panel`）与浮层卡片
  （`CreatePanel` / `GenPanel` 的 `.panel`）都叫 `.panel`。⇒ 容器改 `.column`，让 `.panel` 只表示浮层。

> **判据**：两个类**同名但实现不同** ⇒ **必须改名**，且新名要说明**形态**，不是说明**时机**。

### Token 名

| 层 | 规则 | 例 |
|---|---|---|
| L1 | `--<色板>-<档>` / `--dim-<档>` | `--p-indigo-500` / `--dim-4` |
| L1.5 | `--brand-<档>` | `--brand-500` |
| L2 | `--<角色>[-<状态>]`，**描述意图，不描述外观** | `--color-danger` ✅ / `--color-red` ❌ |
| L3 | `--<控件>-<部位>[-<状态>]` | `--btn-primary-bg-hover` / `--field-border-focus` |

## §2 决策树：要加一个视觉属性，放哪儿？

> ★★ **口径（先读）**：真源（`ui/common/shared.module.css`）**整份住 `@layer base`**，组件样式**未分层**
>   ⇒ 按 CSS 规范「未分层 > 分层（同特异性）」**组件天然压过真源**。
>   ⇒ **「在本组件里写 1~2 个属性改差异」是合法且直觉的**（「覆盖不生效」的坑已被 `@layer` 拆掉）。
>   ⇒ 真源变体（§3.1）只在**要给别人复用同一个变体**时才做。

```
要加/改一个视觉属性
│
├─ 是既有真源类的**变体**？（"要一个危险色的按钮"）
│   └─→ §3.1 加真源变体（composes + 覆盖 1~2 个属性）
│
├─ 是既有组件的**新旋钮**？（"按钮要更圆一点"）
│   └─→ §3.2 加 L3 旋钮 + 改组件引用
│
├─ 是**全新语义**？（"新增一种'警告'表面色"）
│   └─→ §3.3 加 L2 语义（值必须指向 L1）
│
├─ 是**全新原始值**？（"品牌要加一档 teal"）
│   └─→ §3.4 加 L1 + 在 L1.5/L2 接线
│
└─ 以上都不是（一次性、只此一处）
    └─→ 写在本组件的 module.css 里
        ⚠️ 但要先自问：**它是不是一个隐藏的新族？**
           （如果第 3 次出现同类写法 ⇒ 回来走 §5 提级）
```

**先查后写**：动手前先搜 `shared.module.css` 有没有现成的真源类。
真源表在 `AGENTS.md` §五，别靠印象。

## §3 四个扩展点（自生长的入口）

> ⚠️ **本节所有代码示例里的名字都是「假设要新增的」**（如 `--btn-icon-only-size` / `--color-surface-notice` / `--p-teal-*`），
> **当前并不存在** —— 别去 `tokens.css` 里找它们。示例要教的是**步骤**，不是"现有 token 清单"
> （现有清单看 §1.1 层级阶梯 / §1.2 尺度阶梯两张表）。

### §3.1 加真源变体（最常见）

**场景**：需要一个按钮 / 输入框 / 徽章的**新形态**。

**改哪儿**：`src/ui/common/shared.module.css`（真源文件本身）

**步骤**：

```css
/* 1) 在真源里加修饰符（放在基础类之后！见 §6）*/
.btnWarning {
  background: var(--color-warning);
  color: var(--color-text-on-brand);
  border-color: transparent;
}
```

```css
/* 2) 组件里 composes */
.retryBtn {
  composes: btn btnWarning btnSm from '../common/shared.module.css';
}
```

**要点**：
- 修饰符**只写差异**（底色 / 字色），尺寸 / 圆角 / padding 由基础类 `composes` 带过来
- 命名用 `.btn<语气>`（`.btnWarning` / `.btnGhost` / `.btnDanger`）保持族内一致

**验证**：`npx vite build` 不报 `CssSyntaxError`。

### §3.2 加 L3 组件旋钮

**场景**：某个控件的**某个参数**需要能单独调（"按钮高度想跟输入框不一样"）。

**改哪儿**：`src/styles/tokens.css` 的 `L3 · COMPONENT` 段

**步骤**：

```css
/* 1) L3 段加旋钮（值必须指向 L2 或 L1）*/
--btn-icon-only-size: var(--dim-8);
```

```css
/* 2) 真源类引用它 */
.btnIcon { width: var(--btn-icon-only-size); }
```

**要点**：
- L3 的值**必须**是 `var(...)`，不能写字面量（硬红线 1）
- 命名用 `--<控件>-<部位>[-<状态>]`（`--btn-primary-bg-hover`）

### §3.3 加 L2 语义

**场景**：出现一个**新的意图**，既不是已有的"动作 / 选中 / 强调 / 焦点"，也不是某个组件的私有参数。

**改哪儿**：`src/styles/tokens.css` 的 `L2 · SEMANTIC` 段

**步骤**：

```css
/* 1) L1 先有色源（若没有）*/
--p-teal-500: #14b8a6;

/* 2) L2 加语义（浅色 + 暗色两套都要给）*/
--color-surface-notice: var(--p-teal-500);         /* light */
/* [data-theme='dark'] 段 */
--color-surface-notice: var(--p-teal-400);         /* dark 要提亮一档 */
```

**要点**：
- **暗色主题必须同步**，否则暗色下会糊成一团（规则见 §8.1）
- 加完检查是否需要 L3 旋钮（§3.2）
- 语义名描述**意图**，不描述**外观**（`--color-danger` ✅ / `--color-red` ❌）

### §3.4 加 L1 原始值

**场景**：色板 / 尺寸基数不够用。

**改哪儿**：`src/styles/tokens.css` 的 `L1 · PRIMITIVE` 段

**步骤**：

```css
/* 1) L1 加（这是唯一允许写十六进制的地方）*/
--p-teal-400: #2dd4bf;
--p-teal-500: #14b8a6;
--p-teal-600: #0d9488;
```

```css
/* 2) 若是品牌色，改 L1.5 一处即可全局换 */
--brand-500: var(--p-teal-500);
```

**要求**：一次给**一整档**（400/500/600），别只加一个——
否则下一个要用 hover 色的人又得回来加。

## §4 硬红线（只有这四条）

**违反任一 ⇒ 不许合入。**

| # | 红线 | 怎么验 |
|---|---|---|
| 1 | **字面量色值只许出现在 `tokens.css` 的 L1 段** | 排除 `tokens.css` 后 grep 色值字面量为 0（**人工判读**，命令见 §7；**无目录豁免**，见下）|
| 2 | **组件 CSS 禁直引 L1**（`--p-*` / `--brand-*`）| `search_content "var\(--p-\|var\(--brand-"` 排除 `tokens.css` 后应为 0 |
| 3 | **禁 `!important`** | `search_content "!important"` 应为 0 |
| 4 | **有真源类就不许自造** | 新写的控件形态先查 `AGENTS.md` §五 真源表 |

**除这四条外，其余都是"约定"，可以用 §0 的流程改进。**

### 例外凭证（逐处显式记录理由，全仓一致）

**没有目录豁免** —— 整目录放行（如 `src/constants/**`）是个**漏洞**：
任何常量文件都能**静默**藏色值，规则形同虚设。
改为**逐处显式凭证**（人工留痕，机器不校验理由）：

- **行级**：该行加 `// ssot-color-ok: <理由>`；
- **文件级**：文件任意处写 `ssot-color-ok-file: <理由>`（仅限「整文件即数据 / 注入样式」）。

**只有三类能拿到凭证**（`var(--…)` 物理上做不到，或会破坏数据兼容）：

1. **canvas 2D `fillStyle`** —— 它**不解析 CSS 变量**（`src/constants/facemask.ts`）；
2. **注入第三方页面**的 CSS —— 对方 DOM 里**没有我们的变量**（`src/constants/inputLock.ts`）；
3. **用户数据预设** —— 值要写进用户数据、须为 hex 才能与原版数据兼容（`src/constants/groupPalette.ts`）。

> ⚠️ 除这三类外**一律 `var(--…)`**。

**间距 / 尺寸**的凭证形态（★ 2026-10-11 新增，`TD-16-33`）：同理，**逐处显式理由**，形态与上面一致 ——
行级 `/* ssot-space-ok: <理由> */`。

**能拿到间距凭证的只有一类**：**逐字对源**（值直接来自 `docs/mockup/assets/mockup.css` 或原版译法，
且**改它就会偏离源**）。理由里**必须写明出处**（`文件:行`），否则评审追问。

> ★★ **2026-10-11 口径更正（重要，别再犯）**：`docs/mockup/**` **不是设计真源** —— 它是
> **我们自己写的预演稿**（`docs/mockup/README.md` 自述用途 =「界面预演 / Token 试验田」；
> `assets/mockup.css` 头注自述「本文件的位置值是**推断值**……拿到原版 CSS 后只改『布局旋钮』一处」）。
> ⇒ **它缺某个类，不能推断成「原版没有它」**：
>   · 遇 mockup 未收录的类 ⇒ **照源语义补**（该给的样式就给），**并把补出来的类回填 `mockup.css`**；
>   · **不要**再走「mockup 没有 ⇒ 不输出 + 记一笔债」那条路 —— 2026-10-11 之前的
>     `TD-16-87`（状态类）/ `TD-16-88`（toast 操作按钮）/ `TD-16-92`（历史版本弹层）三笔债
>     就是这么来的，已按新口径收口（补类 + 回填 mockup，仅保留「推断，待原版 CSS 校」）。
> ⇒ **真源顺序**：**原版代码**（`docs/豆包画布原版参考/expanded_components/**`）> `docs/12` 结构树
>   > `docs/mockup/**`（**仅为便利参考，可缺可错**）。
> ⚠️ **为什么需要它**：`AGENTS §五` 的「禁硬编码间距」是**人工规则**（机器闸已于 2026-10-11 退役，见上），
> 而**逐字对源**优先于"snap 到 token 刻度" —— 例如 `mockup.css:463` 的 `.gvw-dots{gap:3px}`，
> 我们**必须**保持 `3px`（snap 成 `--space-1`(4px) 就是**偏离源**）⇒ 这类只能**保留 + 写凭证**。
>
> ⚠️ **凭证由人核，不由脚本核**：原 `原则5/ssot-color` grep 闸已于 **2026-10-11 退役**
> （行级文本匹配，系统性漏别名 / 多行 / 形态，且误报需人解读 —— 与 §7 同一裁定）。
> 凭证**保留为理由记录**：新出现的凭证会在评审里被追问理由（**不许默默写**）。

## §5 什么时候该「提级」

**判据：同类写法出现到第 3 次 ⇒ 提到真源**（原则 8 三振出局）。

| 现象 | 提到哪 |
|---|---|
| 同一段样式在 3 个组件各写一遍 | `shared.module.css` 真源类 |
| 同一个值在 3 处各写一遍 | L2 语义 或 L3 旋钮 |
| 同一句文案在 3 处各写一遍 | `src/constants/*.ts` |

**提级的动作**（按顺序）：

## §6 四个语法限制（不是我们的规矩，是 CSS Modules 的）

踩过的坑，记在这里免得重踩：

| # | 限制 | 后果 | 规避 |
|---|---|---|---|
| 1 | `composes` 引用的类**必须定义在引用点之前**（postcss-modules 单遍扫描）| `CssSyntaxError: referenced class name … not found` | ★ **优先挪定义顺序**：把**被引用的类**移到**引用它的类之前**。<br>⚠️ 不是"真源一律写文件开头" —— 实录：`.close` 是从**前部挪到** `.btn` **之后**才通的（方向取决于谁引用谁）|
| 2 | `composes` **只允许单个类选择器** | 不能用于 `.st_success .chip` / `.head button` | 这类本地写（色值/间距仍走 token），或**给 TSX 加类名**再 composes |
| 3 | 同文件 `composes` 也受 #1 约束 | `.close` 在 `.btn` 之前就无法引用 | 同上：**挪顺序**，别退化成元素选择器 |
| 4 | `:global()` 里的类名**不受作用域保护** | 全局污染 / 与别处撞名 | 只在"**内容不在 React 控制下**"时用（如 contentEditable 里动态插入的药丸），并**前缀限定作用域**：`.textEditor :global(.ref-chip)` |

> ★ **通用解法**：`composes` 报 "not found" 时，**优先挪定义顺序**，
> 而不是放弃收口或改成元素选择器（元素选择器还会撞上 #2）。

## §8 细则与豁免清单

> 这一节收的是"看起来像漏，其实是有意为之"的判据与白名单 ——
> 目的是让下一个人**不必重新论证一遍**，也别把已裁定的保留当成待办。

### §8.1 深色主题覆盖

**规则**：L2 的**每个色值语义**都必须在 dark 段有个决策 —— 要么**覆盖**，要么**有理由地不覆盖**。
漏了不会报错，只会在暗色下悄悄串色。

**已知两类必须覆盖**（曾经踩过）：

- **hover 态**：dark 段漏定义会让暗色下按钮 hover **变暗**，与"暗色提亮"相反 ⇒ 保持"深一档"，与 light 逻辑一致。
- **半透明底 / 边**（`*-bg` / `-border` / `selection-bg`）：同一个 α 压在**深底**上几乎看不见 ⇒ dark 段把 α 提到约 1.8×（0.08→0.18 等）。
- **实心底上的字**：底色提亮后，白字对比度会不足 ⇒ dark 段改用深色字（见 §8.3）。

**有意不覆盖的**（白名单，不是遗漏）：

| 处 | 理由 |
|---|---|
| `--shadow-sm/md/lg` | 引用 `--color-shadow*`，而 **dark 段已覆盖后者** ⇒ 自动适配 |
| `--color-node-material` / `-account` / `-other` | 节点**标识色**，跨主题保持一致才对（MiniMap 也用它）|

**验证方法**（可复算）：比对 light / dark 两段的变量差集 —— 剩下的应当只有「引用型」和「标识色」。

### §8.2 三态完整性（hover / active / disabled）

**判据**：可点元素应有 `:hover` 反馈；`:active`（按下）**按需**；`:disabled` 仅「可能被禁用」的元素需要。

- 真源 `.btn` / `.listItemClickable` 自带 `:active`（`transform: translateY(1px)`）—— 用到它们就自动获得三态。
- 自造小按钮（有边框、无 hover）⇒ 走真源 `composes: btn btnSm`，别自己补三态。

**有意不加 `:active` 的**（白名单）：

| 处 | 理由 |
|---|---|
| 开关的 label（`.autoSend` / `.snapToggle`）| 点击反馈就是 checkbox 自身状态变化 |
| 颜色选择器（`.colorDot` / `.swatch`）| 选中态本身就是反馈 |
| 可点行（`.rowMain`）| 可点行，不是按钮，按下反馈可选 |

> **判据**：`:active` 不是"每个可点元素都要"。开关 / 选择器 / 可点行**有更贴切的状态表达**时，
> 硬加位移反而怪。

### §8.3 对比度（WCAG AA）

**怎么算**（手工，本项目不用脚本）：

```
相对亮度 L = 0.2126·R + 0.7152·G + 0.0722·B     ← 各通道先做 sRGB 反伽马
对比度   = (L亮 + 0.05) / (L暗 + 0.05)
```

或用在线对比度计算器。**四个品牌 × 明暗两主题都要算**（品牌色可切，每个都该够）。

> ⚠️ **注意取哪个品牌**：`--brand-*` 在 `tokens.css` 里定义了 **4 次**（indigo / blue / violet / green）。
> 核对时**必须取首个**（= `:root` 的默认品牌）—— 实录：取最后一个（绿）会算出四个组合全是 2.54，误判成"indigo 也不行"。
> ⚠️ `rgb(ch / α)` 半透明底需与父底色混合才能算 —— 单独一色算不出比值。

**被裁定"保留不改"的 4 个**（都是 light 的「彩色实心底 + 白字」这一个模式，属设计决策）：

| 组合 | 比值 | 为什么不改 |
|---|---|---|
| light 按钮文字 / 主色底 | **4.47** | 差 0.03 到 AA。`#6366f1` 亮度居中 —— **白字 4.47、深字 4.29，两条路都不达标**；唯一解是加深底色（`brand-600` 可得 6.27），但那会改掉主色观感 |
| light 强调文字 / 卡片 | 4.47 | 同上（同一个色）|
| light 白字 / 成功底 | 2.54 | 要达标得把「绿底白字」改成「**浅绿底 + 深绿字**」（更规范），属视觉设计改动 |
| light 危险底文字 / 危险底 | 3.76 | 同上 |

> 这 4 个**只在 light**。要达标就得**加深底**或**把字改深**，等确认视觉后再动。

**已确立的解法**（新写这类组合时照此办）：

- 暗色主题的按钮应「**浅底深字**」，不是"浅底白字"；
- 「反馈色当文字」要单独给 **`--color-success-text` / `-warning-text` / `-danger-text`**（文字版比底色版深一档）；
- 弱文字（muted / faint）不够对比度时**上移层次**（`gray-300` / `gray-400`），而不是就地改字号。

### §8.4 「死变量」判据

`tokens.css` 里存在当前无 `var()` 引用的变量，**这不等于死代码** —— 分三类：

| 类 | 例 | 判据 |
|---|---|---|
| **ReactFlow 内部消费** | `--xy-*` | 外部 grep 不到是正常的，**别删** |
| **L3 成套旋钮** | `.pill` 的三个语气留了两个 | 成套设计，留档即完整 |
| **L1/L2 刻度** | 字阶 / 间距 / 层级 / 色板 | **刻度完整性** |

> **判据**：枚举型 token（色板 / 字阶 / 间距 / 层级）应保留**完整刻度**；
> 语义型 token 有定义就该有用途。

### §8.5 明确「不收口」的形态（白名单）

以下看起来像真源族的漏网者，**审查时不要误判为待收**：

| 处 | 为什么不是 `.listItem` / `.field` 一族 |
|---|---|
| `SendQueuePanel .item` | 纵向 + 分隔线，与 `.listItem` 不是同一族 |
| `LibraryPanel .item` | 卡片式可拖拽（`cursor: grab`），不是列表行 |
| `AccountPanel .row` | 只有 3 个属性的**布局容器**，无视觉 |
| `AccountPanel .rowMain` | 纵向可点主体，与 `.listItem` 形态不同 |
| `GenPanel .row` | 是「标签 + 控件」表单行，不是列表项 |
| `GenPanel .row select/input` | **只有 1 处**（未到 §5 的三振）；已**语义对齐** `--field-*`，但形态差异是有意的（select 高度由内容决定）|
| `AccountPicker .trigger` | 是**下拉触发器**，形态含箭头 + 最大宽度，与 `.field` 不同 |

**当前无"到期未收"项**；其余等新需求自然触发 —— 按 §5，同类写法到**第 3 次**时提级。
