# 18 · 剩余工作优先级排序（判据：不改会不会让后续新增更难）

> **这份文档干什么用**：把「还没做的」（`docs/13/14/15` 的缺口 + `daily/架构日志/债务.md` 的待还债）按一句话判据排序。
> **排序判据（唯一）**：**不做，会不会让「后续剩余功能的开发」变难。会 ⇒ 排前。**
> **性质**：**排序建议**（不是判据、不是闸、不是债）—— 不改任何缺口 / 债的状态，只回答"先做哪个"。
> **数据来源**：`daily/架构日志/债务.md`（走 `debt.mjs list`）· `docs/13` · `docs/14` · `docs/15` · 逐条对 `src/**` 复核。

---

## §0 判据展开：什么叫"让后续更难"

同一个"未完成"，让后续更难的方式有四种。按**复利成本**从高到低：

| 档 | 形态 | 特征 | 为什么排这个位置 |
|---|---|---|---|
| **P0** | **复利型** | 不做 ⇒ **每做一批新功能就被咬一次**（缺守卫 / 地图失真 / 假守卫 / 双源） | 越晚做越贵：功能越多，欠账越多、返工面越大 |
| **P1** | **地基型** | 不做 ⇒ **一批功能没有落脚点**、或只能各自临时凑 | 一次做好，后面 N 个功能省 N 次；晚做则每个功能都要先补地基 |
| **P2** | **最后一跳型** | **有实现、只差接线**；不接则相关功能长期 0 消费、或日后要重造 | 现在接最便宜；拖久了要么遗忘、要么重新实现 |
| **P3** | **纯工作量型** | 不做**只影响它自己**，不挡别人 | 随时可插空做，欠不下复利 |

> **一句话结论**：**P0 不产出任何用户可见的新功能** —— 它买的是「接下来每一批都不返工」。
> 若只想尽快"看起来多做了功能"，直接从 P3 做也成立；但只要打算长期把剩余功能做完，**P0 越早越省**。

## §2 逐档说明

### P0 · 复利型（序 1~5）

**共同点**：它们**不产出功能**，但决定"后面每一批功能要还多少债"。判据是**复利**：

- 序 1「守卫缺口群」是**根因**（其余 P0 都靠它防再生），但它最难、最需要用户裁定"建不建闸"（`docs/16` §4 已裁定：**能收口就不建闸**）⇒ 落地时应**优先结构收口**（类型穷尽 / 唯一入口 / 编译期约束），而非加闸。
- 序 2「地图失真」**成本最低、回报最快**：改文档即可，且它直接决定后续每一步的前提对不对。**性价比第一。**
- 序 3「假守卫」是**最隐蔽**的一类：它让你以为有防线。修它通常只需删断言/改注释/补校验，**便宜且立刻止损**。
- 序 4「账本机制」影响的是**后续的 AI/人是否信任账本**；不修则"已解决"三字不可信。
- 序 5「SSOT 双源」是**新功能必踩**的坑：每加一个节点类型/面板都可能再抄一份。

### P1 · 地基型（序 6~9）

**共同点**：**一批功能共用**同一块地基。现在做一次，后面省 N 次。

- 序 6 是**最被低估**的一条：`BackendPagePort.runScript` **通道已经造好**，只是没人调；而站点侧一堆功能（无水印 / 参数面板定位 / Dola 强开 / 回复分类）**都要"在页内跑脚本"**。这一条通了，是一整批功能的公共前置。
- 序 7/8 是**生成双通道的 API 半边**：一个管"配置面板"，一个管"结果回灌"。两条都通，API 通道才算真正可用。
- 序 9 是**数据地基**：`presets` 一项就同时卡着「保存为节点预设」「导入工程预设」（TD-16-69）「拆分套用预设」三处。

### P2 · 最后一跳型（序 10~13）

**共同点**：**实现都在，只差接线**。现在接最便宜；不接则相关能力长期 0 消费，日后既可能遗忘，也可能被重新实现一遍（重复造）。

### P3 · 纯工作量型（序 14~18）

**共同点**：**只影响它自己**。可以在任意间隙插空做，不欠复利。之所以排最后，**不是因为不值钱，而是因为它们不挡别人**。

## §3 边界与已知不确定

- 本排序**只回答"先做哪个"**，不改变任何缺口/债的状态；缺口真源仍是 `docs/13/14/15`，债真源仍是 `daily/架构日志/债务.md`。
- 序 1 的落地形态（**结构收口 vs 建闸**）**需用户裁定** —— 见 `docs/16` §4。
- 序 6 依赖 `SitePort.executeJavaScript` + webview 租约，**跨前端/后端**；后端改动须回写 `docs/05`（成本判据见 `AGENTS.md` 后端边界）。
- 序 14「图片编辑器 + 遮脸层」是**单件工作量最大**的项；它也同时解锁 `facemask`/`faceDetect` 的 0 消费 —— 若只按"解锁最多 0 消费"排，它会前移。
- 本排序基于**当前代码复核**；若并发线有新落地，序 7/8/10~13 的"未接线"状态可能变化 —— 变动即按 `DATAFLOW`/`判据登记表` 成对回写。
