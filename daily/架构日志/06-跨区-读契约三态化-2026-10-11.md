| 文件 | 改动 |
|---|---|

| `state/store.ts` | `readFlag` 三态化（只有 `ok` 且 `'1'` 才算开） |

**未改**：持久化**格式**（键名 / 值形状）· `StoragePort.readRaw`（端口方法 0 消费，属 `TD-06-2` 的幽灵簇）。

## 五、反向探针（零炸）

| 口径 | 命令 | 结果 |
|---|---|---|
| 全量门禁 | `npm run check` | ✅ `75 files / 1387 tests passed`（5 道闸） |
| 类型（契约变更逼出全部消费点） | `npm run typecheck` | ✅ **一次通过**（8 个消费点全被逼出） |
| 旧写法残留 | `grep 'PERSIST[...].read(...) ??' src/` ／ `grep '.read(...) === ' src/` | ✅ **均 0** |

**零炸三问**：

1. **哪些行为被改了？** —— **只有"读到损坏"这一条路径**变了：从前静默当"没有"并会在下一次写盘覆盖；
   现在**如实留痕 + 跳过该键的写回**。**正常路径（`ok` / `missing`）逐字等价**（`missing` ⇒ 默认值，与从前 `??` 同）。
2. **改前能走的路径仍能走吗？** —— 全量 1387 tests 绿；`missing` / `ok` 两态的行为与从前一致。
3. **改前会失败的仍失败吗？** —— 写失败照样抛（`writeRaw` 未动）；解析失败照样"读不出来"（只是现在**可区分**了）。

**用户可感知变化（显式声明）**：**损坏时不再静默覆盖**（这正是本轮的**目的**）；**正常使用零变化**。
⚠️ **一处刻意的时序依赖**（已在 §二 注明）：`container.hydrate()` 在 `hydrate()` 返回后**立刻** `setSkipKeys`；
而 `loadHydrated` 触发的写盘是 **600ms 防抖** ⇒ `skipKeys` 必然先就位（否则防不住）。
