## 四、探针（先红后绿 · `probe.mjs`）

> ⚠️ **为什么是"类型层"**：`adapters/**` 按 **原则 7 不写单测**。

```
🧪 probe ｜ TD-04-5 fail-closed 收口不可被静默删（类型层）
   注入：const c = checkOk<{path?:string}>(raw); if (!c.ok) return c; return ok({path: c.value.path});
      → 删掉中间的 if (!c.ok) return c;
   先红：退出码 2（期望 2）· expect-out 命中（error TS —— `.value` 只在 `Ok` 分支存在）
   ✅ 还原校验通过（sha256 一致）· 后绿：退出码 0 · ✅ 探针成立
```

- **② 注入语义（一行）**：删掉 `if (!c.ok) return c;` ⇒ 直接取 `c.value`。
- **③ 还原后的绿**：`npm run typecheck` → 退出码 0。
- ✅ **这条探针是强的**：它证明收口**删不掉**（`Result` 的判别联合让"不判 `ok` 就取 `value`"成为**类型错误**）。
- ⚠️ **诚实边界**：`attachImages` 那处 `!== true` **不是**类型强制的（它是协议判断 —— 由 handler 回源支撑：
  `out` 初始 `{ok:false,…}`、成功才置 `true`）⇒ 该处靠**回源证据**而非机器守卫。

## 五、反向探针（零炸）

| 口径 | 命令 | 结果 |
|---|---|---|
| 全量门禁 | `npm run check` | ✅ 5 道闸全过（1387 tests） |
| 类型 | `npm run typecheck` | ✅ 0 错 |
| 残留 `ok === false` **活代码** | `grep -rn "ok === false" src/adapters/host/electron/` | ✅ 只剩**注释** + `normalize` 本体（刻意 fail-open） |

**零炸三问**：

1. **哪些行为被改了？** —— **正常路径逐字等价**（10 条通道恒带 `ok` ⇒ `=== false` 与 `!== true` 同真值）；
   只有"后端漏 `ok`"这一**当前不可达**的分支由"当成功"改为"当失败（`boundaryViolation`）"。
2. **改前能走的路径仍能走吗？** —— 成功路径（`ok:true`）逐条等价；1387 tests 绿。
3. **改前会失败的仍失败吗？** —— `ok:false` 照样失败，且**原文 `error` 透传未变**（fallback 文案逐字保留：
   `PROJECT_TEXT.unknownReason` ／ `COMMON_TEXT.unknownReason` ／ `ACCOUNT_TRANSFER_TEXT.*` ／ `LICENSE_TEXT.*`）。

**用户可感知变化（显式声明）**：**无**（正常路径零变化；不可达分支的文案由"成功"变成 `boundaryViolation`）。
⚠️ 一处**纠正**：`activateStorage` 原先失败时 `message` 是 `String(r.error ?? '')`（可能为**空串**），
现由 `checkOk` 兜底成 `COMMON_TEXT.unknownReason`（「未知错误」）—— 只在后端失败却**没给 `error`** 时可见。
