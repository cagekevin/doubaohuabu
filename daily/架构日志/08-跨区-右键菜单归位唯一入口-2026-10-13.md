# 08-跨区 · 节点右键菜单归位唯一入口 — 2026-10-13

## 债

`TD-08-7`（症状：点锚浮层绕过共享件）

## 病因（不是"缺守卫"，是绕过唯一入口）

共享件 `ui/common/ContextMenu` **早已存在、且已有 2 个消费者**（`AccountPanel` / `LibraryPanel`），
它自带：**定位 · 点外部关闭 · 方向键 · `Enter` · `Escape` · `role=menu/menuitem/separator`**。

而 `NodeContextMenu`（画布节点右键）**自绘** DOM ＋ 自挂 `document` 的 `click`/`Escape` 监听
（**无键盘导航、无 ARIA**）。

★ 共享件的头注**逐字写着**：「原实现里**四处**各写一遍：画布空白 / **节点** / 边 / 组」
⇒ 它就是那「四处」里**漏收口的一份** —— 收口收了一半。

## 归位

| 文件 | 改 |
|---|---|
| `ui/canvas/NodeContextMenu.tsx` | 改为构建 `MenuItem[]` ＋ 渲染 `<ContextMenu …/>`；**删**自绘 DOM、**删**自挂监听 |
| `ui/canvas/NodeContextMenu.module.css` | **删除**（自绘样式随自绘 DOM 一起消失；唯一消费者已不引它） |
| `ui/common/ContextMenu.tsx` | `MenuActionItem` 补可选 `title`（禁用原因 tooltip —— 节点菜单原本有，**不丢行为**） |
| `ui/canvas/CanvasHost.tsx` | 空白右键守卫由 `[data-testid="node-ctx-menu"]` ⇒ **`[role="menu"]`**（菜单统一走共享件 ⇒ 判据用它的 role，不再依赖某个具体菜单的 testid） |

★ **归位之后不需要为它补任何守卫** —— 键盘导航／ARIA 由唯一入口自动覆盖。

## 凭证

- `npx tsc --noEmit` → 0
- `npm run check` → **6 道全绿（2064 条）**
- `grep` 确认 `NodeContextMenu.module.css` 零引用

> ⚠️ **视觉变动（如实记）**：菜单样式由 `NodeContextMenu.module.css` 换成共享件样式
