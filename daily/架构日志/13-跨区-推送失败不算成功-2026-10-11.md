## 一、做之前：数清楚（现场逐字）

`electron/lovart-fetch.js` 的下载循环里：

```js
if (r.ok) {
  okCount++;                                  // ① 先计数
  sender('lovart-fetch-item', { … item … });   // ② 再推送 —— 而 sender 内部 `catch (e) { /* ignore */ }` 全吞
}
```

⇒ **推送失败时**：渲染层**永远收不到那张图**，但 `okCount` 已经加了 ⇒ 最后的
`lovart-fetch-done` 报「已获取 N 张」⇒ **用户看到成功数虚高、实际缺图** ✗（假成功）。

---

## 二、改了什么（1 文件）

| 改动 | 内容 |
|---|---|
| `sender` **返回是否送达** | 有目标 ⇒ `target.send(...)` 后 `return true`；**无目标**（窗口/渲染进程已销毁）⇒ **留痕 + `return false`**；`catch` ⇒ **留痕 + `return false`**（此前是 `catch (e) { /* ignore */ }` 全吞）|
| 计数**先送后计** | `const delivered = sender(…)` ⇒ `delivered ? okCount++ : (failCount++ + 记入 `failures`，原因「图片已下载但未送达渲染层（IPC 推送失败）」)` |

⚠️ **语义选择**：图**确实下载成功**了，但对**用户**而言"没拿到" ⇒ 计 `failCount` 并给可读原因（而不是
默默算成功）。这与源的意图一致（`okCount` 是"用户拿到了几张"），只是源在这里**漏判**了推送这一环。
