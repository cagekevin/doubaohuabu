# 01 跨区 · 死代码基线「清偿」——孤儿文件 + 死 barrel 导出（2026-10-14）

## 起点：**死代码基线本身就是「已判死存量」清单**

`scripts/dead-code-baseline.json` 是机器闸（knip `--production`）**判死但容忍**的存量。
它 = 一份现成的「该清偿的死代码」roadmap（规则：永不复涨，**清偿后跑 `--update-baseline`**）。

## 本批清偿

| 项 | 病因 → 处置 |
|---|---|
| `stable/protocols/vid.ts`（**整文件**，`isVidRef`/`vidNameOf`/`toVidRef`/`vidMimeOf`） | **孤儿预写**：`vid://` 由**宿主独占**（主进程产生引用 `main.js:787` + 注册 handler `main.js:1017-1059`），前端只把引用当**不透明串**渲染、从不拼/拆 ⇒ 删整文件 |
| `stable/contracts/schemas.ts` 的 `PROTOCOL_VID` | 其**唯一消费者就是 `vid.ts`** ⇒ 删，注释写明「`vid://` 由宿主独占」 |
| `state/index.ts` 的 **16 个死再导出** | **barrel 第二出口**：`AppState`/各 slice 类型/`takeSnapshot`/`createSettingsSlice`/`createSubscriptions`/`defaultApiSetup` … 全仓 0 处 `from '@/state'` 取用 ⇒ barrel 只保留真被取用的（hooks / `createAppStore` / `AppStore` / `PERSIST` / `ProviderDraft`…） |

## 判据

- **`vid.ts` 不是「该接」**：回源确认前端**不需要**镜像该协议 —— 引用由宿主产生、`<video>` 由 Electron 供。
  （J3 路径防穿越是**主进程** `main.js:1021` 的职责，前端镜像一份＝第二份真相。）
- **死 barrel 导出 = 第二出口**：同一个 `import { X } from '@/state'` 之前有两条路能拿到，收成一条。

## 结果

死代码基线 **65 → 40 条**（`--update-baseline`；**diff 确认新增 0 条** —— 未把回归塞进基线）。
