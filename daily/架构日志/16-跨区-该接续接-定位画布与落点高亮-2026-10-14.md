## 一、`SendQueuePanel` 点「查看」→ 定位画布（原 `fitViewAction`）

**源**（`z3.jsx:80-89`）：队列项在**该节点已有出片**时渲染一颗「查看」（`sq-btn ok`，`title="定位到画布上的出片结果"`），
点它调 `I(nodeId)` → `store.fitViewAction([nodeId])`；`fitViewAction` 的实现住**画布组件**
（`_Component42.jsx:516-536`）：`setTimeout(…,80)` → `fitView({nodes: ids.map(id=>({id})), padding:0.2, duration:400, maxZoom:1})`。

**本仓口径**（与源不同、且更严）：**视图能力不塞进 store**（`state/slices/canvas.ts:494` 已有此约定）。
但 `SendQueuePanel` 与 `CanvasHost` 是 `AppShell` 里的**兄弟**（`AppShell.tsx:126-129`）⇒ 没有父子回调可走
⇒ 取仓库**已有同型先例** `splitKeywordModal` 的做法：**store 只带请求数据，`fitView` 由 `CanvasHost` 消费后自己调**。

| 落点 | 改动 |
|---|---|
| `state/slices/ui.ts` | 字段 `focusNodesRequest: { ids, seq } \| null` ＋ `requestFocusNodes(ids)` / `clearFocusNodesRequest()`（`seq` 保证同批连点两次也各触发一次；空数组不写） |
| `ui/panels/SendQueuePanel.tsx` | `hasResult`（原 `ke` = `data.resultUrl \|\| data.resultPoster`）⇒ 渲染「查看」，点了 `requestFocusNodes([it.nodeId])` |
| `ui/canvas/CanvasHost.tsx` | `useEffect` 消费 → `fitView({nodes, padding:0.2, duration: FITVIEW_FOCUS_DURATION_MS, maxZoom:1})`（80ms 延迟照源）→ 立即清空请求 |
| `constants/index.ts` | 新增 `FITVIEW_FOCUS_DURATION_MS = 400`（源那份是 400，**与初次 fitView 的 250 不是同一档**） |
| `constants/sendPanelText.ts` | `view` / `viewTitle`（`查看` / `定位到画布上的出片结果`，逐字） |

⚠️ 源那句「`CanvasHost` 还没暴露 fitView ⇒ **不做**」已删 —— 它本来就有（拆分弹窗在用），缺的只是**跨面板的桥**。

## 二、`NewImagesPanel` 落点高亮（原 `.nip-drop-active`）

**源**（`_Component26.jsx:261`）：按下缩略图时 `document.querySelector('.doubao-view-webviews').classList.add('nip-drop-active')` —— 给**跨层容器**挂**全局**类。

**旧裁定**（`docs/plan/06:145` · `TD-16-73`）：**判不落**，理由「要给跨层容器挂全局类，本仓只有 CSS Modules ⇒ 不为它开例外」。

**该理由一半是假的**：`NewImagesPanel`（`:477`）与 `.webviews` 容器（`:414`）**同在 `BackendView` 之下** ⇒
回调 prop ＋ CSS-modules 类就够，**根本不需要全局类**。真约束只剩「源样式真值不可得」。

**落**：`NewImagesPanel` 加 `onDropActiveChange?`（按下期间置 `true`，卸载时收回）；`BackendView` 持 `newImagesDropActive`
并给容器加 `.webviewsDropActive`（`outline: 2px solid var(--color-action-primary); outline-offset: -2px`，**自拟**，同 `.nip-ghost` 先例）。

**账本回写**：`TD-16-73` 结清；`docs/plan/06:145/188` · `13:247` · `05:173` 由「判不落 / 未落」改为「已落 / 已清零」。

## 三、教训（同一条，第二次）

**「不做」的理由必须能被证伪。** `.nip-drop-active` 的「需要全局类」听起来像硬约束，实际只是**没查渲染关系**——
面板与容器本来就是父子/兄弟。⇒ **写「不落」之前，先问：这条约束真的挡住我了吗？还是我只是没看？**
