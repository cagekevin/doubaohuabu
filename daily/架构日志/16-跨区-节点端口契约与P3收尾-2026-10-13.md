## 二、★ 根因：`NodeShell` 的契约与实现**相反**（且静默）

`NodeShell.tsx` 的 `handles` 契约写「对象 = 细分（**如下载节点 `{ source: false }` = 仅 target**）」，
而实现是：

```ts
const handleProps = typeof handles === 'object' ? handles : { target: handles, source: handles };
```

⇒ `{ source: false }` 让 `target` 变 `undefined` ⇒ **两侧都不渲染**（**无类型错、无运行时报错** —— 静默）。
**这正是 C2 一直"落不下去"的原因**：按文档写反而更糟。⇒ 修**实现**（对象形态补默认 `true`）。

## 七、教训

- **契约与实现相反时，照契约写会更糟**：`NodeShell.handles` 说「`{ source: false }` = 仅 target」，
  实现却是「缺的键 ⇒ `false`」⇒ 照文档写 ⇒ **两侧都不渲染且静默**。
  ⇒ **契约必须被实现兑现**，否则它是一条"照着做反而错"的假判据（**比没有契约更坏**）。
- **计划的「小件」定性要复核**：BP-34 记作「Tapnow 仅剩 `pP`」，回源后是**两站共用的取图原语**
  ＋一次架构取舍 ⇒ 规模与落点全变了（同 HANDOFF §四.2）。
- **`ui/**` 无单测 ⇒ UI 契约改动必须有端到端断言兜底**：本轮把端口数写进 `verify-canvas` ⑦，
  它**立刻抓到我自己断言里的键序 bug**（`JSON.stringify` 整对象比对）—— 断言也要按"逐键、与顺序无关"写。
