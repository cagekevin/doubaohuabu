## 一、源语义（逐行回源）

- `sm(state)`（`:25787-25812`）→ 返回 `{ isDuplicate }`：**精确哈希命中** ⇒ 重复；
  否则算**感知哈希**（注入的 `_cmp_Bc`），与已存 phash 的**汉明距离 ≤ `kk`(=8)** ⇒ 重复；

## 二、落点（单文件收口）

`adapters/site/shared/materializeScan.ts` 的 `materializeScannedImages`：

```ts
const dedupe = createDedupe(emptyDedupeState(), { phash: perceptualHash });   // 感知哈希由适配器注入
const isDup = async (src) => { const d = await dedupe.isDuplicate(src); if (d) skipped += 1; return d; };
```

三处判定，**全部在 `saveInline` 之前**（否则重复图照样写一次盘）：
1. `img://` 直接采用（画布 DOM 那半已落过盘）；
2. 内联 base64；
3. 远端取图（在 **junk 过滤之后** —— junk 是同步且更便宜）。

## 三、两个如实的范围说明（写清楚，别让人误以为它管了全部）

1. **状态范围 = 本次调用**。源 `h` 建在 `wp` **整轮**内；本仓「一轮」≈「一档」——
   失败档**早退且不落盘**，`summarizeScanAttempts` 只取**首个 `ok`** ⇒ 只有一档产出条目。
2. **与「已有」条目的重复不由它管**（源 `h0` 的 `exact` 种子那半）：本仓由
   `excludeSeenImages`（URL 级）＋ 落库方 `addLovartImages`（`dataUrl` 级）承担。
   ⇒ 它补的是**同一轮内的重复 ＋ 近重复**。

## 四、配套（本债原文要求，同批做掉）

`lib/phash.ts` 的三条失败路径（**无 DOM / 无 2d ctx / 解码失败**）原先**同返 `null`**、
调用方无从区分 ⇒ 「为什么没去重」永远查不出（`TD-02-10` 记的正是这个**静默**）。
现**各自 `log.warn` 留痕**；返回类型仍是 `string | null`（`DedupeDeps.phash` 只关心"有没有哈希"），
**区分度落在日志上**、消费方零改动。
