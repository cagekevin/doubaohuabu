### ① `core/rules/refs.ts` 的防御分支 —— ✅ **真错位，已归位**

原写：
```ts
const order: number[] = [];              // ← 只承载**编号**
for (…) if (byN.has(n) && !seen.has(n)) order.push(n);
…
order.forEach((oldN) => {
  const hit = byN.get(oldN);
  // 防御性分支：`order` 已用 `byN.has(n)` 过滤 ⇒ 不可达（保留以防将来改动漏掉过滤）
  if (!hit) return;
```
**病因**：上游的过滤**产物被丢掉**（只留下编号）⇒ 下游只能**重新查一次表**，并用「注释 + 防御分支」传递「查得到」这个前提。

**归位**：让前提**随数据一起传递** —— `order` 改为承载 `ParsedRef`（过滤的产物随手带走）：
```ts
const order: ParsedRef[] = [];
for (…) { const hit = byN.get(n); if (hit && !seen.has(n)) order.push(hit); }
…
order.forEach((hit, i) => { … });   // 无防御分支、无第二次查表
```
⇒ 防御分支与重查**结构上一起消失**（将来上游漏过滤 ⇒ **当场暴露**，不再被静默 `return` 吞掉）。
